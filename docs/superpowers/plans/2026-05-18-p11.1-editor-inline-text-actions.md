# P11.1 — Editor Inline-Text Action Family Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate 7 inline-text action handlers (`insertText`, `deleteBackward`, `deleteForward`, `deleteWord`, `deleteLine`, `toggleStyle`, `paste`) from legacy Layer 3 ops (StateNode-shape) to new Layer 3 ops (Y.Doc-backed State) per Decision D's parallel-window contract. After each handler runs the new op on `state`, `downgradeToStateNode` syncs `stateLegacy` so the legacy renderer keeps rendering correctly.

**Architecture (per Decision D points 6, 9, 10):**

Each migrated handler does this sequence:
1. Read `editor.state` (new State) and `editor.selection` (legacy Selection, still legacy until P11.3).
2. Convert legacy selection → new via `legacySelectionToNew(state, selection)`.
3. Run a NEW Layer 3 op on `state`, producing new `state'` (`OperationResult.state`) and new `NewSpan'` (handler-computed).
4. Compute new `stateLegacy' = downgradeToStateNode(state')`.
5. Re-project new selection back to legacy via `newSelectionToLegacy(stateLegacy', newSpan')`.
6. Push history via the `History` wrapper (which in P11.0 still routes to `historyLegacy` by constructing a `Change` from pre/post `stateLegacy` snapshots).
7. Return new EditorState with all fields updated.

**The repetitive parts (selection-conversion, downgrade-and-reproject, history-push) are centralized in a new `editor/actions/migrated-action.ts` wrapper** so each handler is small. Each handler ships a paired equivalence test (Decision D point 10): same logical action via legacy + via migrated path against equivalent starting state; assert resulting `stateLegacy` trees are structurally equal AND selections agree.

**Tech Stack:** TypeScript, Vitest, existing new Layer 3 ops (`state/insert-text.ts`, `state/delete-range.ts`, `state/replace-range.ts`, `state/apply-attrs.ts`, `state/clone-pasted-subtree.ts`), existing bridge helpers from P11.0 (`legacy-position-bridge.ts`, `rebuild-state-from-legacy.ts`).

## Resolved spec questions

- **Open Q 1 (helpers location):** resolved by Decision D point 6. All four conversion helpers live in `editor/legacy-position-bridge.ts` (P11.0 T6). Used as-is.
- **Open Q 2 (paste complexity):** the existing `state/clone-pasted-subtree.ts` (post-P6) returns a `ClonedSubtree` — a structured payload of cloned blocks. The paste handler composes `clonePastedSubtree` + per-block `insertBlock`. If a "spliceBlocks" helper is needed and missing, the implementer STOPs and escalates — don't add unauthorized helpers.
- **Open Q 3 (cursor advancement convention):** centralized in `migrated-action.ts` for the typing case (insertText returns new state + caller advances cursor). For non-typing actions (delete*, toggleStyle, paste), each handler computes its own post-action selection inline.
- **`deleteLine` line-navigation dependency on P10:** P10 shipped `cursor/line-navigation.ts` with `moveToLine` + `moveToLineBoundary` on new Position. P11.1 uses these for `deleteLine`. The shipped helpers take `(state, position, layoutTree, shaper, ...)` — the handler has access to all of these via EditorState + EditorConfig.

### Contract

```typescript
import type { EditorState, EditorConfig } from "../editor-state";
import { pushEditorChange } from "../editor-state";
import type { State } from "../../state/state";
import type { Span as NewSpan } from "../../state/block-position";
import type { Selection as LegacySelection } from "../../cursor/selection";
import { createSelection } from "../../cursor/selection";
import {
  legacySelectionToNew,
  newSelectionToLegacy,
} from "../legacy-position-bridge";
import {
  rebuildStateFromLegacy,
  downgradeToStateNode,
} from "../rebuild-state-from-legacy";
import { rebuildTrees } from "./helpers";

export interface MigratedActionResult {
  /** The new State after the action (output of the Layer 3 op). */
  readonly state: State;
  /** The new Selection (Span<NewPosition>) after the action. */
  readonly selection: NewSpan;
  /**
   * Optional merge tag for history grouping (e.g. "insert" so rapid
   * keystrokes collapse into one undo entry). Empty/undefined = no merge.
   */
  readonly mergeTag?: string;
}

/**
 * Wraps a migrated handler's core work in the Decision-D parallel-window
 * boilerplate: legacy → new selection conversion, downgrade + reproject
 * on the return trip, history push via the `History` wrapper (currently
 * delegating to historyLegacy), and rebuildTrees for the render/layout
 * cache.
 *
 * Handlers call this with a callback that produces the new state +
 * new-span result; the wrapper handles the bookkeeping. Deletes at P11.4
 * cutover when stateLegacy + historyLegacy go away.
 */
export function migratedAction(
  editor: EditorState,
  config: EditorConfig,
  fn: (state: State, selection: NewSpan) => MigratedActionResult,
): EditorState {
  const newSelection = legacySelectionToNew(editor.state, editor.selection);
  const result = fn(editor.state, newSelection);

  // Downgrade post-action state and reproject selection to legacy types.
  const newStateLegacy = downgradeToStateNode(result.state);
  // newSelectionToLegacy already returns a Selection (anchor + focus pair);
  // calling once and using its result directly avoids two redundant path-walks
  // through stateLegacy.
  const newLegacySelection = newSelectionToLegacy(newStateLegacy, result.selection);

  // History push: per Decision D point 9, wrapper constructs a Change
  // from pre/post stateLegacy snapshots and pushes via historyLegacy.
  // (P11.4 cutover replaces this with Y.UndoManager via History wrapper.)
  // The pushEditorChange helper already takes pre/post StateNode shape.
  const change = {
    oldState: editor.stateLegacy,
    newState: newStateLegacy,
    timestamp: Date.now(),
  };
  const newHistoryLegacy = pushEditorChange(
    editor.historyLegacy,
    {
      change,
      selectionBefore: editor.selection,
      selectionAfter: newLegacySelection,
    },
    result.mergeTag ?? "",
  );

  return rebuildTrees(
    {
      ...editor,
      state: result.state,
      stateLegacy: newStateLegacy,
      selection: newLegacySelection,
      historyLegacy: newHistoryLegacy,
    },
    editor,
    config,
  );
}
```

```typescript
import type { StateNode } from "@taleweaver/core";

/**
 * Structural equality for legacy StateNode trees. Used by P11.1+ paired
 * equivalence tests: same logical action via the legacy handler vs the
 * migrated handler should produce structurally-equal stateLegacy trees.
 *
 * Compares: type, properties (deep), style (deep), children (recursively
 * with this same function). Deliberately IGNORES `id` fields, because
 * legacy handlers and `downgradeToStateNode` may produce different id
 * strings for structurally-equivalent nodes (legacy: allocator-counted;
 * new: derived from new-state BlockIds + item indices). The semantic
 * shape — types, content, styling, structure — is what matters.
 *
 * Returns true iff the two trees are structurally equal.
 */
export function structurallyEqualStateNode(a: StateNode, b: StateNode): boolean {
  if (a.type !== b.type) return false;
  if (!deepEqual(a.properties, b.properties)) return false;
  if (!deepEqual(a.style, b.style)) return false;
  if (a.children.length !== b.children.length) return false;
  for (let i = 0; i < a.children.length; i++) {
    if (!structurallyEqualStateNode(a.children[i], b.children[i])) return false;
  }
  return true;
}

function deepEqual(x: unknown, y: unknown): boolean {
  if (x === y) return true;
  if (typeof x !== typeof y) return false;
  if (x === null || y === null) return x === y;
  if (typeof x !== "object") return false;
  const xObj = x as Record<string, unknown>;
  const yObj = y as Record<string, unknown>;
  const xKeys = Object.keys(xObj);
  const yKeys = Object.keys(yObj);
  if (xKeys.length !== yKeys.length) return false;
  for (const k of xKeys) {
    if (!Object.prototype.hasOwnProperty.call(yObj, k)) return false;
    if (!deepEqual(xObj[k], yObj[k])) return false;
  }
  return true;
}
```

### New shape

```typescript
import type { EditorState, EditorConfig } from "../editor-state";
import { migratedAction } from "./migrated-action";
import { insertText as newInsertText } from "../../state/insert-text";
import { replaceRange as newReplaceRange } from "../../state/replace-range";
import { createPosition } from "../../state/block-position";
import { createSpan } from "../../state/block-position";

export function handleInsertText(
  editor: EditorState,
  text: string,
  config: EditorConfig,
): EditorState {
  return migratedAction(editor, config, (state, selection) => {
    const anchorEquals = selection.anchor.blockId === selection.focus.blockId
      && selection.anchor.offset === selection.focus.offset;

    if (!anchorEquals) {
      // Replace selected range with the typed text. CRITICAL: for cursor
      // placement we need the doc-order EARLIER endpoint of the span
      // (which may be `focus` if the user dragged right-to-left).
      // Read replace-range.ts to confirm whether it normalizes internally;
      // if not, normalize here via spanStart from state/block-compare
      // (shipped in P10 T4) so the cursor lands at the visually-earlier end.
      const start = spanStart(state, selection); // import from "../../state/block-compare"
      const result = newReplaceRange(state, selection, text, /* attrs */ {});
      // Cursor: at the start's blockId, offset = start.offset + text.length.
      // Assumes the start block survives replaceRange (true for same-parent
      // cross-block per delete-range's contract; cross-parent would throw
      // before we reach this line).
      const newPos = createPosition(start.blockId, start.offset + text.length);
      return { state: result.state, selection: createSpan(newPos, newPos), mergeTag: "insert" };
    }

    // Collapsed selection: insertText at the cursor.
    const result = newInsertText(state, selection.focus, text, /* attrs */ {});
    const newPos = createPosition(selection.focus.blockId, selection.focus.offset + text.length);
    return { state: result.state, selection: createSpan(newPos, newPos), mergeTag: "insert" };
  });
}
```

NOTE on `attrs` (the new `insertText` signature requires a `ReadonlyAttrs` argument):
- Legacy `insertText` inherited attrs from surrounding text implicitly.
- New `insertText` takes explicit attrs. For typed text, `{}` is reasonable (inherit "no override"); the inline-content layer's merge logic will inherit from adjacent text items of the same run.
- The implementer should read the `state/insert-text.ts` JSDoc on attrs semantics to confirm `{}` is the right default. If a "current selection attrs" lookup is needed, build a helper.

NOTE on `replaceRange`: confirm the new `state/replace-range.ts` signature — does it take `attrs` like insertText? Adapt the call.

Per-handler notes:

### T3: `delete-backward.ts`

- Layer 3 op: `deleteRange(state, span)` from `state/delete-range.ts`.
- Collapsed selection at offset 0 of a paragraph: cross-block backspace (merges paragraphs).
- **CRITICAL — `deleteRange` throws on cross-parent spans** (per its source: "cross-parent spans are not supported in this phase — Action handlers should decompose into per-parent operations"). The naive pattern "use `moveByCharacter(state, position, 'backward')` to compute prev position, then `deleteRange` over the resulting span" works for SAME-PARENT cross-block backspace (two adjacent paragraphs under the same document or section). It FAILS at the cross-section / cross-table-cell boundary. The handler must:
  1. Compute prev position via `moveByCharacter`.
  2. Compare `prev.blockId` with `current.blockId`: if same block, in-block backspace (deleteRange on the same-block span — never throws).
  3. If different blocks: look up both blocks via `getBlock(state, id)`, compare `block.parentId`. If parents match, deleteRange handles the same-parent cross-block case. If parents differ — for P11.1, check whether `state/merge-blocks.ts` is exported and supports cross-parent merge; if not, STOP and escalate (cross-parent backspace is an open Layer 3 question). Read the existing legacy handler to understand whether it actually supported cross-parent backspace; if legacy didn't either, the new handler can mirror the same restriction.
- mergeTag: "delete".

### T4: `delete-forward.ts`

- Symmetric to T3. Forward direction.
- Layer 3 op: `deleteRange(state, span)`.
- Use `moveByCharacter(state, position, "forward")` for the "delete one grapheme forward" target.

### T5: `delete-word.ts`

- Layer 3 op: `deleteRange(state, span)`.
- Use `moveByWord(state, position, direction)` to find the word boundary, then delete to it.

### T6: `toggle-style.ts`

- Layer 3 op: `applyAttrsToRange(state, span, attrs)` from `state/apply-attrs.ts`.
- Helper needed: `selectionAllHaveAttr(state, span, key)` — walks the span's text items, returns true iff every text item has the attr set. If yes, apply `{ key: false }` to toggle off; otherwise `{ key: true }`.
- Add the helper to `actions/helpers.ts` (or co-located in `toggle-style.ts` if not shared).
- mergeTag: probably empty (formatting shouldn't merge with typing).

### T7: `delete-line.ts`

- Depends on P10 `cursor/line-navigation.ts` `moveToLineBoundary`.
- Layer 3 op: `deleteRange(state, span)`.
- Find line-start and line-end via `moveToLineBoundary(state, position, layoutTree, shaper, "start"|"end")`. Arguments come from: `state` = `editor.state` (new field, available in the wrapper callback), `layoutTree` = `editor.layoutTree` (already on `EditorState`), `shaper` = `config.measurer`. Confirm against `cursor/line-navigation.ts` and `editor-state.ts` for exact arg order.
- Cross-parent guard same as T3: if the line spans across parents (deeply nested layout), `deleteRange` will throw. Most line deletions are intra-paragraph and don't cross parents; defensive check still warranted.
