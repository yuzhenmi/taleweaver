# P11-cutover — Editor Migration in a Single Phase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the editor from the legacy state model (StateNode + legacy renderer + legacy cursor) to the new pipeline (Y.Doc-backed State + new render + new cursor + new components + new attr registry) in a single focused phase. Replaces P11.1–P11.4's per-family staged migration. No parallel-window scaffolding, no paired equivalence tests, no `*-Legacy` exports — every legacy artifact is deleted by the end of this phase.

**Rationale:** the project has zero external users; foundation modules (P7-P10) are fully tested with ~1442 tests on the new types. The parallel-window scaffolding shipped in P11.0 (`legacy-position-bridge.ts`, `rebuild-state-from-legacy.ts`, `migrated-action.ts`, `equivalence-test-utils.ts`, `path-to-block-id.ts`, `EditorState.stateLegacy`, `EditorState.historyLegacy`, `EditorHistory` machinery) is ~700 lines of throwaway code. The staged approach was a defensive default; hard cutover wins on total effort for an internal-only rewrite.

**Architecture after this phase:**
- `EditorState = { state: State; selection: Span; history: History; renderTree: RenderNode; layoutTree: LayoutBox; containerWidth: number; targetX: number | null; }` — no `stateLegacy`, no `historyLegacy`, no `nextId` (BlockIds are allocator-generated).
- `Selection` type unified with `Span` from `state/block-position.ts` (anchor + focus, each `{ blockId, offset }`).
- `createInitialEditorState(config)` calls `render(state, componentRegistry, attrRegistry)` → cascade is no longer a separate pass (the new render integrates cascade per Decisions B/G).
- All 26 action handlers operate on `editor.state` via new Layer 3 ops + new cursor ops + new geometry helpers.
- `History` wrapper backs undo/redo via Y.UndoManager (was passive in P11.0; flipped here to active).
- Legacy modules (state/*-legacy, cursor/cursor-ops-legacy, render/render-legacy, components/*-legacy, editor/*-legacy, cursor/selection.ts, EditorHistory) all deleted.

**Tech Stack:** TypeScript, Vitest. Foundation modules already shipped: P4e Y.Doc state, P5 tsconfig, P6 embedContents, P7 render module, P8 components, P9 cursor-ops + grapheme-utils, P10 hit-test + selection-geometry + cursor-position + line-navigation. All P11-cutover work plugs these together inside the editor.

## Build invariant

**Each task commit ends in a green build + green test suite.** Within a task, intermediate edits may have transient errors; the commit is atomic on green. Tasks are sized so that "commit when green" is achievable per task — typically by completing a self-contained rewrite within the task's scope.

## Sub-phase ordering

5 tasks. Each lands a green build + green test suite at commit.

1. **T0:** Plan-housekeeping. Decide on `Selection` type name (alias for `Span`, or just use `Span` directly). Verify scope (run a grep audit of legacy imports to size the work).
2. **T1:** Cutover commit — rewrite the editor module. Single atomic commit covering: `EditorState` interface trimmed; `createInitialEditorState` uses new render pipeline; all 26 action handlers rewritten on new types; `Selection` flipped to `Span<NewPosition>`. Delete P11.0 scaffolding + legacy modules + downstream consumers updated, all in one commit. Build green at end.
3. **T2:** Update DOM controller, React wrapper, and example apps.
4. **T3:** Rewrite integration tests + trim the public-API barrel + final clean.
5. **T4:** Browser smoke + final verification.

T1 is large but atomic. Subagent dispatch is comprehensive: rewrite all handlers, delete all scaffolding, delete all legacy modules. The plan provides per-family handler guidance below to scope the subagent's work.

**Why one big T1 commit instead of family-by-family:** every handler reads `editor.selection`. Flipping `Selection` type means every handler must update simultaneously. No middle state compiles. Trying to do this in pieces re-introduces parallel-window scaffolding. The atomic commit is honest about the actual coupling.

#### B. Rewrite `createInitialEditorState`

```typescript
import { createEmptyDocument } from "../state/initial-state";
import { render } from "../render/render";
import { layoutTree } from "../layout/dispatch";
import { createPosition, createSpan } from "../state/block-position";
import { createHistory } from "../state/history";
import { getBlock } from "../state/state";

export function createInitialEditorState(config: EditorConfig): EditorState {
  const state = createEmptyDocument();
  // Cursor at offset 0 of the first (only) paragraph in the empty doc.
  const docBlock = getBlock(state, state.rootId);
  if (docBlock === null) throw new Error("createInitialEditorState: root not found");
  const firstParagraphId = docBlock.firstChildId;
  if (firstParagraphId === null) {
    throw new Error("createInitialEditorState: empty document has no paragraph child");
  }
  const cursor = createPosition(firstParagraphId, 0);
  const selection = createSpan(cursor, cursor);

  // New render pipeline: render produces RenderNode tree; cascade is folded
  // into render per Decisions B/G. layoutTree consumes the result.
  const rendered = render(state, config.componentRegistry, config.attrRegistry);
  const layout = layoutTree(rendered.root, config.containerWidth, config.measurer, config.pageConfig);

  return {
    state,
    selection,
    history: createHistory(state),
    renderTree: rendered.root,
    layoutTree: layout,
    containerWidth: config.containerWidth,
    targetX: null,
  };
}
```

Notes:
- `render` returns `{ root, embedContents }`. For non-paginated layout, just use `root`. For paginated, `embedContents` feeds in via `pageConfig` (or a follow-up param; verify against `dispatch.ts`'s `layoutTree` signature).
- `cascadePass` is no longer a separate step — the new render integrates cascade. If the layout pipeline needs a separate cascaded tree, run `cascadePass(rendered.root)` once; check whether layout expects pre-cascaded or post-cascaded input.

#### C. Rewrite the 26 action handlers

All handlers in `packages/core/src/editor/actions/*.ts` (except `index.ts`, `helpers.ts`). Group by family for the subagent:

**Inline-text family** (state-mutating, 7 handlers):
- `insert-text.ts`: `insertText(state, position, text, attrs)` from `state/insert-text.ts`.
- `delete-backward.ts`: `deleteRange(state, span)` from `state/delete-range.ts`; for collapsed selection at offset 0 of a block, use `moveByCharacter` to get the prev position, then build a span and `deleteRange`. - `delete-forward.ts`: symmetric to backward.
- `delete-word.ts`: `moveByWord` to get the word boundary, then `deleteRange`.
- `delete-line.ts`: `moveToLineBoundary` (from `cursor/line-navigation.ts`) for line bounds, then `deleteRange`.
- `toggle-style.ts`: `applyAttrsToRange(state, span, attrs)` from `state/apply-attrs.ts`. Toggle on/off based on `selectionAllHaveAttr` (new helper in `actions/helpers.ts`).
- `paste.ts`: `clonePastedSubtree` from `state/clone-pasted-subtree.ts` (post-P6) + per-block `insertBlock`.

**Block-structure family** (state-mutating, 4 handlers):
- `split-node.ts`: `splitBlock(state, position)` from `state/split-block.ts`.
- `insert-node.ts`: `insertBlock(state, parentId, position, blockSpec)` from `state/insert-block.ts`.
- `set-block-type.ts`: `setBlockType(state, blockId, type)` from `state/set-block-type.ts`.
- `toggle-list.ts`: composes `setBlockType` (to/from list-item) + `insertBlock` (for new list wrapper) + `removeBlock`.

**Cursor / selection family** (no state mutation, ~10 handlers):
- `move-cursor.ts`: `moveByCharacter(state, position, direction)` from `cursor/cursor-ops.ts`.
- `move-word.ts`: `moveByWord(state, position, direction)`.
- `move-line.ts`: `moveToLine(state, position, layoutTree, measurer, direction, targetX)`.
- `move-line-boundary.ts`: `moveToLineBoundary(state, position, layoutTree, measurer, boundary)`.

**Layout family** (1 handler):
- `set-container-width.ts`: re-runs layout with new width. Should call `rebuildTrees(...)` from helpers.

**History family** (2 handlers):
- `undo.ts`: `editor.history.undo()` → returns new State + selection. Wrapper handles Y.UndoManager.
- `redo.ts`: `editor.history.redo()`.

#### D. Rewrite `actions/helpers.ts`

`rebuildTrees(newEditor, oldEditor, config)` — re-runs render + layout for the new editor state. Use new `render` + `layoutTree`. The function signature stays the same; the body switches to new pipeline.

Also: any helpers like `findFirstTextDescendant` / `findLastTextDescendant` (called from move-document-boundary) need rewriting on new types — or replaced with new helpers like "first content-bearing block" using `nextBlockInDocOrder`.

#### E. Update `History` wrapper integration

State-mutating handlers must call the History wrapper with the correct API per `state/history.ts`:

```typescript
// After producing newState + newSelection in a handler:
editor.history.setState(newState);            // syncs the wrapper's internal currentState ref
editor.history.push({ selection: newSelection });  // commits the entry
```

Two calls. `History.push` takes `PushHistoryArgs = { selection: unknown | null }` only — there is no `state` parameter. The `setState` call is the documented sync handshake (history.ts:74-77 explains why). For undo/redo handlers, call `editor.history.undo()` / `editor.history.redo()` which return `{ state, selection }`; assign both back to the EditorState.
