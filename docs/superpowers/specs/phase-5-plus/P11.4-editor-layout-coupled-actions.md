# P11.4 — Editor: layout-coupled action family

**Subject:** Migrate the remaining action handlers that interact with layout — `set-container-width`, line-bound movement helpers, paint-layer integration, scroll-to-selection. After this phase, no editor action references legacy `StateNode` or legacy `Position`-by-path.

**Reference:** Master spec migration step 10b (action family per Decision 4).

## Goal

The final action-family migration. Layout-coupled handlers consume the layout tree (RenderNode tree post-layout) and may emit changes that trigger re-layout (e.g., container width changes affecting line breaks). After P11.4, ALL editor actions are migrated.

## Dependencies

P11.3 (selection migrated; cursor module fully on new types).

## Current state

Action files in this family (per directory survey 2026-05-08):
- `set-container-width.ts` — change the document's content-area width (triggers re-layout).
- `move-line.ts`, `move-line-boundary.ts` — line-relative cursor movement (depend on layout-tree info).
- `move-document-boundary.ts` — Cmd+Up / Cmd+Down — full-document boundary movement.

(Selection-geometry consumption isn't an "action" but a paint-time operation; P11.3 should have already wired it.)

## Files involved

**Modified:**
- `actions/set-container-width.ts` — re-layout trigger on width change. State doesn't change (width is a layout parameter, not state).
- `actions/move-line.ts` — call `cursor/line-navigation-v2.ts` (P10 helper).
- `actions/move-line-boundary.ts` — same.
- `actions/move-document-boundary.ts` — likely uses `firstLeafBlock`/`lastLeafBlock` from Layer 2.
- Any helpers in `editor/layout-utils.ts` that reference legacy types.

## Parallel-window contract (Decision D) — and the cutover task

Same migrated-handler contract as P11.1/P11.2 (see those phases) applies through P11.4. After P11.3, the `legacyPositionToNew` step on handler entry is gone (selection is native new); the wrapper still maintains `stateLegacy` and the legacy renderer still reads it (per P11.3 path (b)).

**Cutover is the closing task of P11.4** (per `decisions.md` Decision D Affected phases). Once the last layout-coupled handler is migrated, the same commit:

1. Flips the renderer to consume `state` directly (replaces `render-legacy` import with `render`).
2. Flips the `History` wrapper to delegate to `Y.UndoManager` (deletes the `historyLegacy` branch from the wrapper).
3. Deletes `historyLegacy: EditorHistory` and `stateLegacy: StateNode` fields from `EditorState`.
4. Deletes bridge functions `rebuildStateFromLegacy`, `downgradeToStateNode`, `newPositionToLegacy` (the `legacyPositionToNew` direction was already removed in P11.3).
5. Deletes all paired equivalence tests (legacy handlers are about to go away in P15).
6. Build + browser smoke + full test pass; ship.

P11.4's success criteria gate on the cutover commit. P15 then removes the `*-legacy.ts` files (renderer, components, etc.) per Decision E — pure deletion, no logic changes.

## Key technical considerations

1. **`set-container-width` doesn't mutate `State`.** It mutates a layout parameter (probably stored in editor or layout module). After P11.4, state is untouched on width-change; layout re-runs with the new width.

2. **Line navigation = cursor navigation that depends on layout.** P10 introduced `line-navigation-v2.ts` that takes (state, position, layoutTree) → new position. P11.4 wires the editor handlers to this.

3. **Document-boundary navigation.** Cmd+Up = move cursor to start-of-document (block 0, offset 0). Cmd+Down = end-of-document (last leaf block, offset = its content length). Layer 2 utilities `firstLeafBlock(state, rootId)` and `lastLeafBlock(state, rootId)` provide this.

4. **Paint-layer integration.** Selection highlights, caret painting — these are mostly the renderer/paint module's job. Editor exposes the necessary state (selection, focus). P11.4 verifies the wiring still works after all type migrations.

## Risks and patterns to apply

- **Browser smoke for Cmd+Arrow movements** — easy to break.
- **Line navigation after Enter / paste** — common interaction. Verify cursor doesn't end up "between" lines or at a stale offset.
- **DRY:** if multiple handlers share a "find current line in layout tree" helper, extract.

## Open questions
