# P11.2 — Editor: block-structure action family

**Subject:** Migrate block-structure action handlers (Enter/split-paragraph, Backspace-at-block-start/merge, list indent/outdent, set-block-type, insert-node) to use new `State` and Layer 3 operations.

**Reference:** Master spec migration step 10b (action family per Decision 4).

## Goal

Block-structure handlers manipulate the document tree shape — splitting blocks, merging, changing block types, indenting list items. They build on Layer 3 ops `splitBlockAtPosition`, `mergeAdjacentBlocks`, `setBlockType`, `setBlockAttrs`, `insertBlock`, `removeBlock`.

After P11.2, Enter (split paragraph), Backspace-at-start-of-block (merge with previous), set-block-type (change paragraph to heading), insert-node (new block), and toggle-list (wrap in/out of list) all work via new Layer 3 ops.

## Dependencies

P11.1 (inline-text actions migrated; helpers in place; legacy-position-bridge available).

## Current state

`packages/core/src/editor/actions/`:
- `split-node.ts` — Enter key. Splits the current block at the cursor.
- `set-block-type.ts` — change paragraph → heading, etc.
- `toggle-list.ts` — wrap/unwrap in list.
- `insert-node.ts` — programmatic insertion of a new block.

(delete-backward.ts in P11.1 handles the inline-character-delete case. The cross-block-merge case — Backspace at offset 0 of a block — likely lives in delete-backward.ts too. P11.1 plan would have decided whether to migrate ONLY the inline case or the full handler. P11.2 may need to revisit if cross-block-merge wasn't fully handled in P11.1.)

## Files involved

**Modified:**

- Possibly revisit `delete-backward.ts` from P11.1 for the cross-block-merge case (call `mergeAdjacentBlocks`).

## Key technical considerations

1. **`splitBlockAtPosition` allocator.** This Layer 3 op needs an `IdAllocator`. Editor must inject `productionAllocator` (from `block-id.ts`) consistently. Same for `insertBlock`. Helper: `withAllocator(...)` wrapping editor handlers, OR direct passing.

2. **Cursor placement after split.** After Enter, cursor lands at offset 0 of the newly-created block. Easy to compute given `splitBlockAtPosition`'s deterministic id allocation.

3. **Cross-block merge after Backspace-at-block-start.** When user is at offset 0 of paragraph 2 and presses Backspace, `mergeAdjacentBlocks(state, p1.id, p2.id)` merges p2 into p1. Cursor moves to "end of p1's original content" which equals "the seam in p1's merged content."

4. **Toggle-list semantics.** Most complex P11.2 handler. Behaviors to preserve:
   - Selection is in a paragraph: wrap in a list-item inside a list container.
   - Selection is in a list-item: unwrap to paragraph.
   - Selection spans multiple paragraphs: wrap them all in one list with items.
   - These compose Layer 3 ops: `insertBlock` for the list container, `setBlockType` for items, etc.

5. **Set-block-type interaction with cascade.** Changing a paragraph to a heading changes the block's `type` AND the cascade interprets the new type for default styles. Verify the cascade pipeline handles the type change correctly (likely yes — cascade is type-driven, not snapshot-frozen).

## Risks and patterns to apply

- **DRY across structural handlers.** Wrapping/unwrapping in containers may share logic across `toggle-list` and other handlers. Extract common helpers.
- **Browser smoke critical.** Pressing Enter and seeing a new paragraph is a basic smoke test. List wrapping is more visible; verify carefully.
- **Implementer escalation:** complex toggle-list logic may require Layer 3 ops we don't have yet (e.g., "wrap blocks in a new container"). Note: `insertBlock` + per-block `setBlockAttrs` should be sufficient. If not, escalate.
