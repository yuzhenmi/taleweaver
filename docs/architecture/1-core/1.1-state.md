# 1.1 — `state/`

The state module is the document model. It is the single source of
truth for everything semantic about the document — what blocks exist,
their attributes, the rich-text content inside leaf blocks, and the
relationships between them. It owns no geometry, no resolved styles, and
no visual concerns.

The current design is the block-tree-of-styled-runs model committed to in
2026-05-02 (see `docs/superpowers/specs/2026-05-02-state-model-block-tree-of-ropes-design.md`
for the design spec, decisions log, and migration history).

## What state is

A document is a **block tree** keyed by stable `BlockId`s. Each block is
a flat record with a parent pointer and a doubly-linked-list of children
(`firstChildId` / `lastChildId` / `prevSiblingId` / `nextSiblingId`).
Container blocks (sections, lists, tables) hold child blocks; leaf
blocks (paragraphs, headings, list-items, table-cells) carry their rich
text as `inlineContent` — a flat array of styled inline items (text runs
and embed items).

Storage is backed by a Yjs `Y.Doc`. The Yjs container — two `Y.Map`s
keyed by `BlockId`, one for the main document tree and one for
embed-content subtrees (footnote bodies, etc.) — is owned by the state
module and exposed only through opaque snapshot accessors (`getBlock`,
`getEmbedContent`). Yjs is an implementation choice that gives the
engine cheap structural sharing across versions and a forward path to
collaborative editing without a state-module rewrite.

Positions are **id-and-offset**: `Position = { blockId, offset }`. The
offset counts UTF-16 code units across the block's inline content; each
embed item contributes one offset unit (a single cursor stop). Cursor
movement at the user-visible level enforces grapheme-cluster boundaries
via `Intl.Segmenter` (logic lives in `cursor/`, not here). Positions are
stable across edits to other blocks — only edits that touch the named
block can shift the named offset.

A `Span` is a directed pair `{ anchor, focus }`. Collapsed spans are
cursors. A span lives within a single **selection context** (the main
document tree, or one specific embed body); cross-context spans are not
supported.

Inline styles are **attributes on text runs and embeds**, not wrapper
nodes in state. The render module reconstructs `span` element boxes from
same-attribute neighbouring runs. State stores semantics; render
produces structure.

## Yjs encapsulation

The state module's public surface hides `Y.Doc` and its maps. Consumers
(cursor, render, cascade, layout, editor, components) import only:

- Layer 1 types (`State`, `Block`, `InlineContent`, etc.) — Yjs-free.
- Layer 1 snapshot accessors (`getBlock`, `getEmbedContent`) returning
  frozen `Block` snapshots.
- Narrow Y.Doc-free accessors for specialized needs (e.g.
  `getEmbedContentIds(state)` — used by render to iterate embed
  subtrees without naming the underlying Y.Map).
- Layer 2 utilities and Layer 3 operations (defined below).

`State`'s only public field is `rootId`. The underlying `Y.Doc` and the
per-State `SnapshotCache` live behind a non-exported `STATE_INTERNAL`
symbol (defined in `state-internal.ts`). Modules outside `state/`
cannot import the symbol — only state-module-internal code can spell
`state[STATE_INTERNAL].doc`. Attempting `state.doc` from any module
outside `state/` is a TypeScript compile error (asserted by
`state/encapsulation.test.ts`).

`STATE_INTERNAL` MUST NOT be re-exported from `packages/core/src/index.ts`
or any other barrel. Its containment is the whole encapsulation.

Yjs may surface in a few well-defined seams (e.g. a future collab
transport will subscribe to update events on the doc), but those seams
will be additive, narrow, and documented here.

## Submodules

Submodules are organized by the three-layer API surface (types and
access; pure utilities; state-mutating operations) plus the
infrastructure pieces.

**Layer 1 — types and access primitives**:

- **`state`** — the `State` container type, `createState`, the
  `OperationResult` shape, `applyOperation` (the transaction-runner
  every Layer 3 op composes), `freshState` (rebuilds the per-state
  snapshot cache after external Y.Doc mutations like undo). Also
  exports the narrow `getEmbedContentIds(state)` accessor that iterates
  embed-content BlockIds without exposing the underlying Y.Map (used by
  render).
- **`state-internal`** — the non-exported `STATE_INTERNAL` symbol that
  gates access to State's underlying Y.Doc + snapshot cache. Must not
  be re-exported from any barrel.
- **`build-state-from-blocks`** — state-module-internal builder that
  materializes Block fixtures directly into a fresh Y.Doc-backed State.
  Bypasses Layer 3 ops; intended for test-utils / boot helpers that
  need to construct an arbitrary state shape. The public test-utils
  `buildState` delegates here.
- **`block`** — the `Block` snapshot type.
- **`block-id`** — branded `BlockId` type, `IdAllocator` interface,
  `productionAllocator` (UUID v4 via `crypto.randomUUID()`),
  `createTestAllocator` (deterministic sequence for tests).
- **`block-init`** — the partial-block shape used by ops that create
  new blocks before assigning an id.
- **`block-position`** — `Position`, `Span`, `Selection` types and pure
  builders (`createPosition`, `createSpan`).
- **`inline-content`** — `InlineContent`, `InlineItem`, `TextItem`,
  `EmbedItem` types, plus pure normalization helpers
  (`mergeAdjacentTextItems`).
- **`attrs`** — `ReadonlyAttrs` type, `attrsEqual` (deep-value compare),
  `mergeAttrs`.
- **`block-schema`** — declared shape of a Y.Map-stored block, with a
  compile-time coverage check (`satisfies + DeclaredKeys`) so the
  read-path and write-path never drift.
- **`block-kinds`** — classification of block types into kinds
  (`inline-bearing-leaf`, `atomic-leaf`, `container`); consulted by
  `setBlockType` to refuse cross-shape transitions.

**Layer 2 — pure utilities**:

- **`block-traversal`** — `nextBlockInDocOrder`, `prevBlockInDocOrder`,
  `ancestorChain`, `firstLeafBlock`, `lastLeafBlock`. Step-bounded by
  the main-tree size to guard against corruption.
- **`block-compare`** — `compareBlocksInDocOrder` via LCA walk;
  `selectionContextOf`.
- **`span-iteration`** — `iterateSpan` (yields per-leaf-block ranges
  in document order) and `iterateBlocksInSpan` (yields each block,
  including containers, overlapped by the span).
- **`extract-text`** — flattens a span to a plain string for clipboard,
  find/replace, accessibility. Walks block boundaries via `iterateSpan`
  (no hardcoded block-type list); embeds serialize via a hook so plugins
  control their textual representation.

**Layer 3 — state-mutating operations**:

- **`operations`** — barrel re-exports of the operations below.
- **`insert-text`** — `insertText(state, position, text, attrs, allocator) → OperationResult`.
- **`delete-range`** — `deleteRange(state, span, allocator) → OperationResult`.
  Refuses cross-parent spans (action handlers decompose).
- **`replace-range`** — `replaceRange(state, span, text, attrs, allocator) → OperationResult`.
  Composes delete + insert atomically in one Y.Doc transaction.
- **`split-block`** — `splitBlockAtPosition`.
- **`merge-blocks`** — `mergeAdjacentBlocks` (same-parent neighbours).
- **`apply-attrs`** — `applyAttrsToRange` (inline) and the in-place run
  normalizer that merges adjacent same-attr items post-edit.
- **`set-block-attrs`** / **`merge-block-attrs`** — block-level attribute
  replace vs. merge semantics.
- **`set-block-type`** — type change, refusing cross-kind transitions.
- **`insert-block`** / **`remove-block`** — structural ops on the block
  tree; `remove-block` cascades to embed-referenced content blocks.
- **`clone-pasted-subtree`** — paste-helper that walks a source subtree,
  allocates fresh ids, builds an `oldId → newId` map, and rewrites all
  parent/sibling/child/`contentBlockId` references.
- **`embed-content-cascade`** — cascade-delete of embed-referenced
  blocks (called by removal paths).

**History**:

- **`history`** — `History` class wrapping `Y.UndoManager` plus the
  per-entry selection-stack alignment invariant. `commit(opResult, selections)`,
  `undo()`, `redo()`, `canUndo`, `canRedo`. Selection stacks are aligned 1:1
  with the underlying `undoStack` / `redoStack`; alignment is asserted in
  dev mode at every commit.

**Infrastructure (non-public)**:

- **`yjs-doc`** — `createYDoc`, `getBlocksMap`, `getEmbedContentsMap`,
  `getMetaMap`, `runTransaction`. State-module-internal.
- **`y-block`** / **`y-utils`** — read/write helpers between `Block`
  snapshots and the underlying `Y.Map` entries.
- **`snapshot`** — per-`State` snapshot cache. Reads via `getBlock` /
  `getEmbedContent` are O(1) cache lookups; `applyOperation` mints a new
  `State` whose cache inherits all non-dirty entries (structural sharing
  across versions without cloning the Y.Doc).
- **`id-collision-check`** — defense for the very rare case that
  `crypto.randomUUID()` returns a collision. Consumes `isDevMode()`
  from `dev-mode`.
- **`dev-mode`** — `isDevMode()` helper used by state-module code that
  needs to gate invariant assertions on `NODE_ENV !== "production"`.
  (`history.ts` currently inlines its own copy of the same logic rather
  than importing this module; that is a small consolidation opportunity,
  not a behavioural divergence.)

**Boot**:

- **`initial-state`** — `createEmptyDocument(allocator)` returns a fresh
  `State` with a single empty paragraph.

## How submodules connect

Layer 3 ops compose Layer 2 utilities (for traversal and span iteration)
and call `applyOperation` to wrap their write-side work in a Y.Doc
transaction. Layer 3 is the **audited surface** — all state-mutating
logic lives here, nothing outside can corrupt state.

Editor action handlers (`packages/core/src/editor/actions/*`) are the
sole external callers of Layer 3 ops. Each handler typically composes
one or more Layer 3 ops, then calls `history.commit(opResult, selections)`
to record a single undo entry. Handlers MUST short-circuit before
calling `commit` on a no-op operation
(`opResult.state === input.state`, equivalently `opResult.dirtyIds.size === 0`).
The render pipeline consumes `dirtyIds` to decide which subtrees to
rebuild (see `1.2-render.md`).

Layer 2 is read-only and consumed both by Layer 3 internally and by
external read paths (cursor, render, editor geometry queries).

## Reference

### `State` and `OperationResult`

```ts
interface State {
  readonly rootId: BlockId;
  // The underlying Y.Doc and SnapshotCache live behind a non-exported
  // STATE_INTERNAL symbol — reachable only from state-module-internal
  // code, not from any consumer. `state.doc` / `state.snapshotCache`
  // are TypeScript compile errors outside `state/`.
  readonly [STATE_INTERNAL]: {
    readonly doc: Y.Doc;
    readonly snapshotCache: SnapshotCache;
  };
}

interface OperationResult {
  readonly state: State;
  readonly dirtyIds: ReadonlySet<BlockId>;
}
```

`createState({ rootId, doc? })` constructs an opaque container with a
fresh snapshot cache. `applyOperation(state, fn)` runs `fn` inside one
Y.Doc transaction and returns `{ state, dirtyIds }`.

**No-op identity contract.** When the transaction produces no Y.Doc
mutations (`dirtyIds.size === 0`), `applyOperation` returns the literal
input `state` reference unchanged. Callers use
`result.state === input.state` as an O(1) "did anything change?" guard.

**Carry-forward.** On the non-no-op branch, the new `State`'s
snapshot cache inherits every non-dirty entry from the input cache.
Snapshots of unchanged blocks remain reference-equal across edits;
memoized renderers can `prev === next` to skip unchanged subtrees.

### `Block`

```ts
interface Block {
  readonly id: BlockId;
  readonly type: string;            // open string, registered as a component type
  readonly attrs: ReadonlyAttrs;    // open-schema (closed schema lives in ComputedStyle)
  readonly parentId: BlockId | null;
  readonly prevSiblingId: BlockId | null;
  readonly nextSiblingId: BlockId | null;
  readonly firstChildId: BlockId | null;
  readonly lastChildId: BlockId | null;
  readonly inlineContent: InlineContent | null;  // non-null iff leaf
}
```

`Block` is a frozen snapshot view returned by `getBlock(state, id)` /
`getEmbedContent(state, id)`. Mutations go through Layer 3 ops; reading
through the snapshot accessor is O(1).

### `Position`, `Span`, `Selection`

```ts
interface Position {
  readonly blockId: BlockId;
  readonly offset: number;          // UTF-16 code units across the block's inlineContent.items
}

interface Span {
  readonly anchor: Position;
  readonly focus: Position;
}

type Selection = Span;              // alias used by cursor / editor modules
```

Each text item contributes `text.length` (UTF-16 code units) to the
offset; each embed item contributes 1 (a single cursor stop, like one
character). `normalizeSpan(state, span)` returns the span in document
order via `compareBlocksInDocOrder` (LCA walk) plus an offset compare
when anchor and focus share a block.

### `InlineContent` and `InlineItem`

```ts
interface InlineContent {
  readonly items: ReadonlyArray<InlineItem>;
}

type InlineItem = TextItem | EmbedItem;

interface TextItem {
  readonly kind: "text";
  readonly text: string;
  readonly attrs: ReadonlyAttrs;
}

interface EmbedItem {
  readonly kind: "embed";
  readonly embedType: string;
  readonly attrs: ReadonlyAttrs;
  readonly properties: Readonly<Record<string, unknown>>;
}
```

`items` is kept normalized post-edit: adjacent text items with equal
attrs are merged, empty text items dropped. Equality respects the
attribute interpreter registry (see `1.3-cascade.md`).

Primitive embeds (images, mentions, equations, hard-breaks) carry their
data in `properties` inline. Substantial-content embeds (footnote
anchors) carry `properties.contentBlockId: BlockId` referencing a block
in the embed-contents subtree, whose own block-tree holds the body.

### `BlockId` and `IdAllocator`

```ts
type BlockId = string & { readonly __brand: "BlockId" };

interface IdAllocator {
  allocate(): BlockId;
}
```

`productionAllocator` uses `crypto.randomUUID()`. `createTestAllocator(prefix?)`
returns a deterministic counter for reproducible tests. Every Layer 3
op that creates blocks accepts an `IdAllocator` argument.

**Lifecycle:**

1. **Creation** — always allocate fresh.
2. **Deletion** — remove from the main map; cascade-delete any blocks
   referenced by `EmbedItem.properties.contentBlockId` from the deleted
   subtree (`embed-content-cascade`).
3. **Copy/paste** — `clonePastedSubtree` walks the source subtree,
   allocates fresh ids, rewrites references.
4. **Undo/redo** — no allocation. Yjs restores prior ids.

### History

```ts
interface SelectionEntry {
  readonly before: Selection | null;
  readonly after: Selection | null;
}

interface UndoRedoResult {
  readonly state: State;
  readonly selection: Selection | null;
}

class History {
  constructor(state: State);
  commit(opResult: OperationResult, selections: SelectionEntry): void;
  undo(): UndoRedoResult | null;
  redo(): UndoRedoResult | null;
  canUndo(): boolean;
  canRedo(): boolean;
}

function createHistory(state: State): History;
```

`History` wraps a `Y.UndoManager` configured with
`captureTimeout: Number.MAX_SAFE_INTEGER` — wall-clock auto-closure is
disabled; groups are closed explicitly via `commit` (which fires
`stopCapturing`). A single action handler may compose multiple
`applyOperation` calls; they merge into one undo entry at the action
boundary.

**Selection-stack alignment invariant.** `undoSelectionStack.length ===
undoManager.undoStack.length` (and the redo equivalent) holds after
every `commit`. Each pair stores both pre-action and post-action
selection so `undo` returns `before` and `redo` returns `after`. The
invariant is asserted in dev mode at every commit, undo, and redo.

**Meta-map non-undoability.** Writes to the doc's meta `Y.Map` (which
holds `rootId`) are intentionally not undoable — `rootId` is
session-immutable. Future meta-map writers MUST explicitly consider
undoability.

**Error recovery.** `undo` / `redo` order their work as
`undoManager.{undo,redo}` → `freshState` → selection-stack mutation, all
wrapped in try/catch. A throw from the first two leaves the selection
stacks untouched, preserving alignment for a retry. The caller sees a
wrapped error identifying the failure as history-internal.

### Dirty-set contract (rendering bridge)

Every Layer 3 operation returns an `OperationResult` carrying
`dirtyIds: ReadonlySet<BlockId>` produced at write-time by the
underlying Y.Doc transaction's change set — never by post-hoc tree
comparison.

The renderer contract: `dirtyIds` contains both updated and deleted ids.
Consumers distinguish them with `getBlock(state, id) === null` (deleted)
vs. non-null (updated, re-render). Deletions in `embedContents` use the
same contract via `getEmbedContent`.

This is the engine's incremental-rebuild driver; see `1.2-render.md` for
how the render module consumes `dirtyIds`.

### Inline-attribute interpretation and run merging

State stores attributes openly (any key, any value). Equality for the
purpose of merging adjacent same-attr text items defaults to deep value
equality and consults a per-key `equals` from the **attribute
interpreter registry** (defined in `1.3-cascade.md`).

The cascade module translates `attrs` into declarable `Style` via the
same registry, producing `ComputedStyle` through the existing
resolution pipeline (em/rem flattening, inheritance, defaults). State
holds the open schema; cascade closes it.

### Initial state and creation

- `createEmptyDocument({ allocator? })` returns a `State` whose root is
  a `document` container block holding one empty `paragraph` child. The
  document block is `state.rootId`; the paragraph sits beneath it.

### Performance contracts

- `getBlock` / `getEmbedContent` — O(1) cache lookup.
- All Layer 3 ops — O(N_block) on the touched block(s) plus O(1) per
  affected sibling pointer; structural sharing on the snapshot cache
  preserves reference equality of unchanged block snapshots.
- `compareBlocksInDocOrder` — O(depth + LCA-fanout); bounded by ~100
  sibling-pointer hops at the target document scale.
- `applyOperation` no-op path — O(1) identity return.

The target document scale is smooth editing at ≤ 10,000 blocks per
document; graceful degradation to ≤ 100,000. See the spec doc for the
rationale (recalibrated from the prior "1M blocks" framing).
