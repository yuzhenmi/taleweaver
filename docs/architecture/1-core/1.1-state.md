# 1.1 — `state/`

The state module is the document model. It is the single source of
truth for everything semantic about the document — what blocks exist,
their attributes, the rich-text content inside leaf blocks, and the
relationships between them. It owns no geometry, no resolved styles, and
no visual concerns.

The current design is the block-tree-of-styled-runs model committed to in
2026-05-02 (see `docs/superpowers/specs/2026-05-02-state-model-block-tree-of-ropes-design.md`
for the design spec, decisions log, and migration history).

## What state is

A document is a **block tree** keyed by stable `BlockId`s. Each block is
a flat record with a parent pointer and a doubly-linked-list of children
(`firstChildId` / `lastChildId` / `prevSiblingId` / `nextSiblingId`).
Container blocks (sections, lists, tables) hold child blocks; leaf
blocks (paragraphs, headings, list-items, table-cells) carry their rich
text as `inlineContent` — a flat array of styled inline items (text runs
and embed items).

Storage is backed by a Yjs `Y.Doc`. The Yjs container — three `Y.Map`s
keyed by `BlockId`: the main document tree, the embed-content subtrees
(footnote bodies, etc.), and the template-content subtrees (header/footer
bodies) — is owned by the state module and exposed only through opaque
snapshot accessors (`getBlock`, `getEmbedContent`, `getTemplateContent`,
and the provenance-aware `resolveBlock`). BlockIds are globally unique
across all three maps. Yjs is an implementation choice that gives the
engine cheap structural sharing across versions and a forward path to
collaborative editing without a state-module rewrite.

Positions are **id-and-offset**: `Position = { blockId, offset }`. The
offset counts UTF-16 code units across the block's inline content; each
embed item contributes one offset unit (a single cursor stop). Cursor
movement at the user-visible level enforces grapheme-cluster boundaries
via `Intl.Segmenter` (logic lives in `cursor/`, not here). Positions are
stable across edits to other blocks — only edits that touch the named
block can shift the named offset.

A `Span` is a directed pair `{ anchor, focus }`. Collapsed spans are
cursors. A span lives within a single **selection context** (the main
document tree, or one specific embed body); cross-context spans are not
supported.

Inline styles are **attributes on text runs and embeds**, not wrapper
nodes in state. The render module reconstructs `span` element boxes from
same-attribute neighbouring runs. State stores semantics; render
produces structure.

## Yjs encapsulation

The state module's public surface hides `Y.Doc` and its maps. Consumers
(cursor, render, cascade, layout, editor, components) import only:

- Layer 1 types (`State`, `Block`, `InlineContent`, etc.) — Yjs-free.
- Layer 1 snapshot accessors (`getBlock`, `getEmbedContent`,
  `getTemplateContent`, `resolveBlock`) returning
  frozen `Block` snapshots.
- Narrow Y.Doc-free accessors for specialized needs (e.g.
  `getEmbedContentIds(state)` / `getTemplateContentIds(state)` — used by
  render to iterate the embed/template subtree ROOTS without naming the
  underlying Y.Map).
- Layer 2 utilities and Layer 3 operations (defined below).

**Two import surfaces (intra-core vs cross-package).** Sibling core
modules import the state module through `state/index.ts` — the **barrel**
that is the intra-core API contract, grouped by layer (types/access,
utilities, ops + history, boot). It re-exports the Layer 1/2/3 surface
with named exports only and deliberately excludes the infrastructure
files (it cannot leak `STATE_INTERNAL` or any Yjs type). Separately, the
package-level `packages/core/src/index.ts` is the **cross-package**
surface consumed by `packages/dom`, `packages/react`, and examples. The
two surfaces are distinct on purpose; the barrel is the canonical
intra-core contract.

`State`'s only public field is `rootId`. The underlying `Y.Doc` and the
per-State `SnapshotCache` live behind a non-exported `STATE_INTERNAL`
symbol (defined in `state-internal.ts`). Modules outside `state/`
cannot import the symbol — only state-module-internal code can spell
`state[STATE_INTERNAL].doc`. Attempting `state.doc` from any module
outside `state/` is a TypeScript compile error (asserted by
`state/encapsulation.test.ts`).

`STATE_INTERNAL` MUST NOT be re-exported from `packages/core/src/index.ts`
or any other barrel. Its containment is the whole encapsulation.

Yjs may surface in a few well-defined seams (e.g. a future collab
transport will subscribe to update events on the doc), but those seams
will be additive, narrow, and documented here.

## Submodules

Submodules are organized by the three-layer API surface (types and
access; pure utilities; state-mutating operations) plus the
infrastructure pieces.

**Layer 1 — types and access primitives**:

- **`state`** — the `State` container type, `createState`, the
  `OperationResult` shape, `applyOperation` (the transaction-runner
  every Layer 3 op composes), `freshState` (rebuilds the per-state
  snapshot cache after external Y.Doc mutations like undo). Snapshot
  accessors: `getBlock` (main tree), `getEmbedContent`,
  `getTemplateContent`, and `resolveBlock(state, id) → { block, kind }`
  which resolves across all three trees (precedence main →
  embedContents → templateContents) and reports the `ResolvedBlockKind`
  provenance so a caller can route a follow-up write to the right map.
  Callers that only need the value use
  `resolveBlock(state, id)?.block ?? null`. Also exports the narrow
  `getEmbedContentIds(state)` / `getTemplateContentIds(state)` accessors
  that iterate the embed/template subtree ROOT BlockIds (blocks with
  `parentId === null`; body children are reached via the root's child
  chain, not enumerated) without exposing the underlying Y.Map (used by
  render).
- **`index`** — the `state/index.ts` barrel: the intra-core API contract,
  grouped by layer. Named re-exports only; infra is excluded.
- **`state-internal`** — the non-exported `STATE_INTERNAL` symbol that
  gates access to State's underlying Y.Doc + snapshot cache. Must not
  be re-exported from any barrel.
- **`build-state-from-blocks`** — state-module-internal builder that
  materializes Block fixtures directly into a fresh Y.Doc-backed State.
  Bypasses Layer 3 ops; intended for test-utils / boot helpers that
  need to construct an arbitrary state shape. The public test-utils
  `buildState` delegates here.
- **`block`** — the `Block` snapshot type.
- **`block-id`** — branded `BlockId` type, `IdAllocator` interface,
  `productionAllocator` (UUID v4 via `crypto.randomUUID()`),
  `createTestAllocator` (deterministic sequence for tests).
- **`block-init`** — the partial-block shape used by ops that create
  new blocks before assigning an id.
- **`block-position`** — `Position`, `Span`, `Selection` types and pure
  builders (`createPosition`, `createSpan`).
- **`inline-content`** — `InlineContent`, `InlineItem`, `TextItem`,
  `EmbedItem` types, plus pure normalization helpers
  (`mergeAdjacentTextItems`).
- **`attrs`** — `ReadonlyAttrs` type, `attrsEqual` (deep-value compare),
  `mergeAttrs`.
- **`block-schema`** — declared shape of a Y.Map-stored block, with a
  compile-time coverage check (`satisfies + DeclaredKeys`) so the
  read-path and write-path never drift.
- **`block-kinds`** — defines the `BlockKind` taxonomy
  (`inline-bearing-leaf` / `atomic-leaf` / `container`) and a narrow
  `BlockKindResolver` interface (`getBlockKind(type) → BlockKind | null`).
  The component registry implements the resolver; state ops that need to
  judge shape (e.g., `setBlockType` for cross-kind refusal, `INSERT_NODE`'s
  shape validation) accept a resolver parameter. State no longer
  hardcodes type-string sets — taxonomy is owned by component
  definitions (`kind: "container"` for containers; leaf components
  declare `leafShape: "inline-bearing" | "atomic"`).

**Layer 2 — pure utilities**:

- **`block-traversal`** — `nextBlockInDocOrder`, `prevBlockInDocOrder`,
  `ancestorChain`, `firstLeafBlock`, `lastLeafBlock`. Step-bounded by
  the main-tree size to guard against corruption.
- **`block-compare`** — `compareBlocksInDocOrder` via LCA walk;
  `selectionContextOf`.
- **`span-iteration`** — `iterateSpan` (yields per-leaf-block ranges
  in document order) and `iterateBlocksInSpan` (yields each block,
  including containers, overlapped by the span).
- **`extract-text`** — flattens a span to a plain string for clipboard,
  find/replace, accessibility. Walks block boundaries via `iterateSpan`
  (no hardcoded block-type list); embeds serialize via a hook so plugins
  control their textual representation.

**Layer 3 — state-mutating operations** (one file per op in the `ops/`
subdirectory, re-exported from the `state/index.ts` barrel — there is no
separate `operations.ts`). The barrel's prose groupings (inline / structural
/ attrs / section / template) are the category taxonomy; `ops/` itself is
flat. File names below are relative to `ops/`:

**The `plan*` / `*InTx` split (atomic composition).** Each op file also holds
that op's `plan*` / `*InTx` primitives, so several ops can compose into ONE
Y.Doc transaction (one undo entry / one collab event) instead of each opening
its own. The split is uniform: a pure-data `*Plan` produced by a `plan*`
function that does ALL validation + snapshot reads BEFORE the transaction
(returning `null` for a no-op); a `*InTx(doc, …)` primitive guarded by
`requireInTransaction(doc, opName)` that performs the writes; and a thin
public op = `applyOperation(state, () => *InTx(…))`. Ops exposing the split:
`deleteRange` (`planDeleteRange` / `deleteRangeInTx` / `DeleteRangePlan`),
`insertBlock`, `splitBlockAtPosition`, `insertText`, `reparentChildren`
(`computeReparentWrites` / `reparentChildrenInTx`), `applyAttrsToRange`
(`planApplyAttrsToRange` / `applyAttrsToRangeInTx` / `ApplyAttrsToRangePlan`),
and `insertBlocksAfter` (`planInsertBlocksAfter` / `insertBlocksAfterInTx` /
`InsertBlocksAfterPlan`).

Most `*InTx` primitives are **read-free structural appliers**: the `plan*`
function snapshots everything needed and the primitive only writes (e.g.
`reparentChildrenInTx` reads nothing). `applyAttrsToRangeInTx` is the
exception — it reads live Y items by necessity, because the attr update is an
in-place, Y.Text-identity-preserving rewrite that walks the live `Y.Array` to
locate item boundaries and split partially-covered text (so a fully-covered
item keeps its per-character CRDT identity). Consequence: a read-free
primitive composes correctly after any prior in-tx op, but
`applyAttrsToRangeInTx` is correct only when prior in-tx ops do NOT shift this
span's offsets. Composing it atomically AFTER an offset-changing op
(delete/insert) needs mid-transaction span re-resolution against live Y state;
that is not yet implemented and lands with the consuming feature.

- **`insert-text`** — `insertText(state, position, text, attrs, allocator) → OperationResult`.
- **`delete-range`** — `deleteRange(state, span, allocator) → OperationResult`.
  Refuses cross-parent spans (action handlers decompose).
- **`replace-range`** — `replaceRange(state, span, text, attrs, allocator) → OperationResult`.
  Composes delete + insert atomically in one Y.Doc transaction.
- **`split-block`** — `splitBlockAtPosition`.
- **`merge-blocks`** — `mergeAdjacentBlocks` (same-parent neighbours).
- **`apply-attrs`** — `applyAttrsToRange` (inline) and the in-place run
  normalizer that merges adjacent same-attr items post-edit. Exposes the
  `plan*` / `*InTx` split (`planApplyAttrsToRange` / `applyAttrsToRangeInTx`)
  with the read-live-items caveat noted above.
- **`set-block-attrs`** / **`merge-block-attrs`** — block-level attribute
  replace vs. merge semantics.
- **`set-block-type`** — type change, refusing cross-kind transitions.
- **`insert-block`** / **`remove-block`** — structural ops on the block
  tree; `remove-block` cascades to embed-referenced content blocks.
- **`insert-blocks-after`** — `insertBlocksAfter(state, afterId, inits,
  allocator)`: atomic bulk-insert of a run of sibling blocks after a given
  block, in one transaction (the paste-migration / cloned-subtree primitive).
  Exposes the `plan*` / `*InTx` split (`planInsertBlocksAfter` /
  `insertBlocksAfterInTx`): `planInsertBlocksAfter` allocates ids + resolves
  the boundary relink pre-tx into an `InsertBlocksAfterPlan`, and
  `insertBlocksAfterInTx` is a read-free structural applier.
- **`reparent-children`** — `reparentChildren(state, blockIds, newParentId,
  beforeSiblingId?) → OperationResult`: bulk-move a CONTIGUOUS run of sibling
  blocks between parents in one transaction. The relink is a pure function
  (`computeReparentWrites`) that builds a fully-resolved write-list from the
  pre-mutation snapshot; `reparentChildrenInTx` applies it (reads nothing).
  Empty list / identity self-move → no-op (same `State` ref). Shared core for
  outline moves and `section-break`.
- **`section-break`** — `applySectionBreak(state, cursor, allocator) →
  SectionBreakResult` (extends `OperationResult` with `newCursorBlockId`):
  splits the document into FLAT (never-nested) `section` blocks at the cursor's
  boundary block, in ONE transaction (create section(s) via `buildYBlock` +
  reparent bodies via `reparentChildrenInTx`). Breaking at a container's first
  child is a no-op (no empty leading section).
- **`merge-section`** — `mergeSectionWithPrevious(state, sectionId)`: the
  inverse of `applySectionBreak` — reparents a `section`'s bodies back into
  the previous section (or the document root) and removes the now-empty
  section, in one transaction. Drives section-break removal on delete-backward
  / delete-forward at a section boundary.

**History**:

- **`history`** — `History` class wrapping `Y.UndoManager`.
  `beginEntry(key, now)`, `breakCoalescing()`, `commit(opResult, selections)`,
  `undo()`, `redo()`, `canUndo`, `canRedo`. Each undo unit's before/after
  `SelectionEntry` is stored ON its `Y.UndoManager` `StackItem.meta` (written
  at `commit`; read at undo/redo from the popped item), so selection travels
  with the item and cannot index-desync from the Yjs stacks — there is no
  parallel selection array. `beginEntry` / `breakCoalescing` own every
  undo-group boundary (typing coalescing; see the History reference below).

**Infrastructure (non-public)**:

- **`yjs-doc`** — `createYDoc`, `getBlocksMap`, `getEmbedContentsMap`,
  `getTemplateContentsMap`, `getMetaMap`, `runTransaction`, `captureDirtyIds`.
  State-module-internal.
- **`y-block`** / **`y-utils`** — read/write helpers between `Block`
  snapshots and the underlying `Y.Map` entries.
- **`snapshot`** — per-`State` snapshot cache. Reads via `getBlock` /
  `getEmbedContent` are O(1) cache lookups; `applyOperation` mints a new
  `State` whose cache inherits all non-dirty entries (structural sharing
  across versions without cloning the Y.Doc).
- **`root-id-cache`** — per-`Y.Doc` cache of the embed/template subtree
  ROOT ids (`parentId === null`), backing `getEmbedContentIds` /
  `getTemplateContentIds`. Invalidated by a flat `Y.Map.observe` key-set
  listener on the embed/template maps (fires for cascade-deletes and
  undo/redo Yjs surgery alike); recomputed lazily only after a root is
  added/removed, so the common render path does not rescan. Rides the
  shared `Y.Doc` (not `State`).
- **`id-collision-check`** — defense for the very rare case that
  `crypto.randomUUID()` returns a collision. Consumes `isDevMode()`
  from `dev-mode`.
- **`dev-mode`** — `isDevMode()` helper used by state-module code that
  needs to gate invariant assertions on `NODE_ENV !== "production"`.
  `history.ts`, `id-collision-check.ts`, and the structural ops import it
  rather than re-deriving the check.
- **`clone-pasted-subtree`** — paste helper that walks a source subtree,
  allocates fresh ids, builds an `oldId → newId` map, and rewrites all
  parent/sibling/child/`contentBlockId` references. Consumed by the paste
  path; not a barrel-exposed op, so it stays at `state/` top level (the
  `ops/` files import it as `../clone-pasted-subtree`).
- **`embed-content-cascade`** — cascade-delete of embed-referenced bodies
  (called by `remove-block` / `delete-range` removal paths) plus the dev-only
  `assertNoOrphanedEmbedContent` / `assertNoSharedEmbedContent` invariants run
  from `applyOperation`. Cross-cutting (used by ops AND `applyOperation`), so
  it stays at `state/` top level, not in `ops/`.

**Boot**:

- **`initial-state`** — `createEmptyDocument(allocator)` returns a fresh
  `State` with a single empty paragraph.

## How submodules connect

Layer 3 ops compose Layer 2 utilities (for traversal and span iteration)
and call `applyOperation` to wrap their write-side work in a Y.Doc
transaction. Layer 3 is the **audited surface** — all state-mutating
logic lives here, nothing outside can corrupt state.

Editor action handlers (`packages/core/src/editor/actions/*`) are the
sole external callers of Layer 3 ops. Each handler typically composes
one or more Layer 3 ops, then calls `history.commit(opResult, selections)`
to record the unit's selection meta; the reducer has already decided whether
that unit opens a fresh undo group or coalesces into the open one (via
`beginEntry` / `breakCoalescing`, see the History reference). Handlers MUST
short-circuit before calling `commit` on a no-op operation
(`opResult.state === input.state`, equivalently `opResult.dirtyIds.size === 0`).
The render pipeline consumes `dirtyIds` to decide which subtrees to
rebuild (see `1.2-render.md`).

Layer 2 is read-only and consumed both by Layer 3 internally and by
external read paths (cursor, render, editor geometry queries).

## Reference

### `State` and `OperationResult`

```ts
interface State {
  readonly rootId: BlockId;
  // The underlying Y.Doc and SnapshotCache live behind a non-exported
  // STATE_INTERNAL symbol — reachable only from state-module-internal
  // code, not from any consumer. `state.doc` / `state.snapshotCache`
  // are TypeScript compile errors outside `state/`.
  readonly [STATE_INTERNAL]: {
    readonly doc: Y.Doc;
    readonly snapshotCache: SnapshotCache;
  };
}

interface OperationResult {
  readonly state: State;
  readonly dirtyIds: ReadonlySet<BlockId>;
}
```

`createState({ rootId, doc? })` constructs an opaque container with a
fresh snapshot cache. `applyOperation(state, fn)` runs `fn` inside one
Y.Doc transaction and returns `{ state, dirtyIds }`.

**No-op identity contract.** When the transaction produces no Y.Doc
mutations (`dirtyIds.size === 0`), `applyOperation` returns the literal
input `state` reference unchanged. Callers use
`result.state === input.state` as an O(1) "did anything change?" guard.

**Carry-forward.** On the non-no-op branch, the new `State`'s
snapshot cache inherits every non-dirty entry from the input cache.
Snapshots of unchanged blocks remain reference-equal across edits;
memoized renderers can `prev === next` to skip unchanged subtrees.

### `Block`

```ts
interface Block {
  readonly id: BlockId;
  readonly type: string;            // open string, registered as a component type
  readonly attrs: ReadonlyAttrs;    // open-schema (closed schema lives in ComputedStyle)
  readonly parentId: BlockId | null;
  readonly prevSiblingId: BlockId | null;
  readonly nextSiblingId: BlockId | null;
  readonly firstChildId: BlockId | null;
  readonly lastChildId: BlockId | null;
  readonly inlineContent: InlineContent | null;  // non-null iff leaf
}
```

`Block` is a frozen snapshot view returned by `getBlock(state, id)` /
`getEmbedContent(state, id)`. Mutations go through Layer 3 ops; reading
through the snapshot accessor is O(1).

### `Position`, `Span`, `Selection`

```ts
interface Position {
  readonly blockId: BlockId;
  readonly offset: number;          // UTF-16 code units across the block's inlineContent.items
}

interface Span {
  readonly anchor: Position;
  readonly focus: Position;
}

type Selection = Span;              // alias used by cursor / editor modules
```

Each text item contributes `text.length` (UTF-16 code units) to the
offset; each embed item contributes 1 (a single cursor stop, like one
character). `normalizeSpan(state, span)` returns the span in document
order via `compareBlocksInDocOrder` (LCA walk) plus an offset compare
when anchor and focus share a block.

### `InlineContent` and `InlineItem`

```ts
interface InlineContent {
  readonly items: ReadonlyArray<InlineItem>;
}

type InlineItem = TextItem | EmbedItem;

interface TextItem {
  readonly kind: "text";
  readonly text: string;
  readonly attrs: ReadonlyAttrs;
}

interface EmbedItem {
  readonly kind: "embed";
  readonly embedType: string;
  readonly attrs: ReadonlyAttrs;
  readonly properties: Readonly<Record<string, unknown>>;
}
```

`items` is kept normalized post-edit: adjacent text items with equal
attrs are merged, empty text items dropped. Equality respects the
attribute interpreter registry (see `1.3-cascade.md`).

Primitive embeds (images, mentions, equations, hard-breaks) carry their
data in `properties` inline. Substantial-content embeds (footnote
anchors) carry `properties.contentBlockId: BlockId` referencing a block
in the embed-contents subtree, whose own block-tree holds the body.

Each `EmbedItem.contentBlockId` references a **unique** embedContent root:
every body has exactly one owning anchor. Sharing one body across two
anchors is unsupported by design — Word and Google Docs both follow the
"each anchor owns its own body" model, and the unconditional
cascade-delete on anchor removal relies on it. Copy-paste preserves the
1:1 mapping by remapping every `contentBlockId` to a freshly-cloned body
via `clonePastedSubtree`. In dev builds the two halves of this mapping are
enforced after every op: `assertNoOrphanedEmbedContent` catches a
reference with zero owners, and `assertNoSharedEmbedContent` catches a
body with two-plus owners. See
`docs/superpowers/specs/2026-05-30-367-shared-embedcontent-decision.md`.

### `BlockId` and `IdAllocator`

```ts
type BlockId = string & { readonly __brand: "BlockId" };

interface IdAllocator {
  allocate(): BlockId;
}
```

`productionAllocator` uses `crypto.randomUUID()`. `createTestAllocator(prefix?)`
returns a deterministic counter for reproducible tests. Every Layer 3
op that creates blocks accepts an `IdAllocator` argument.

**Lifecycle:**

1. **Creation** — always allocate fresh.
2. **Deletion** — remove from the main map; cascade-delete any blocks
   referenced by `EmbedItem.properties.contentBlockId` from the deleted
   subtree (`embed-content-cascade`).
3. **Copy/paste** — `clonePastedSubtree` walks the source subtree,
   allocates fresh ids, rewrites references.
4. **Undo/redo** — no allocation. Yjs restores prior ids.

### History

```ts
interface SelectionEntry {
  readonly before: Selection | null;
  readonly after: Selection | null;
}

interface UndoRedoResult {
  readonly state: State;
  readonly selection: Selection | null;
  // BlockIds whose subtrees were mutated by the undo/redo's reversal,
  // captured via the same `afterTransaction` channel `runTransaction`
  // uses (Y.UndoManager.undo / .redo each wrap their Y.Doc surgery in
  // an internal transaction). Lets the editor's incremental render
  // pipeline rebuild only the affected RenderNodes.
  readonly dirtyIds: ReadonlySet<BlockId>;
}

type BeginKey = "insert" | "delete" | "command";

class History {
  constructor(state: State);
  beginEntry(key: BeginKey, now: number): void;
  breakCoalescing(): void;
  commit(opResult: OperationResult, selections: SelectionEntry): void;
  undo(): UndoRedoResult | null;
  redo(): UndoRedoResult | null;
  canUndo(): boolean;
  canRedo(): boolean;
}

function createHistory(state: State): History;
```

`History` wraps a `Y.UndoManager` configured with
`captureTimeout: Number.MAX_SAFE_INTEGER` — Yjs never auto-merges or
auto-closes groups by its own wall-clock; `History` owns **every** undo-group
boundary explicitly. A single action handler may compose multiple
`applyOperation` calls; they merge into one undo entry at the action
boundary. The boundary between consecutive actions is decided by
`beginEntry` / `breakCoalescing` (see **Undo coalescing** below), not by
`commit`.

**Selection lives on `StackItem.meta`.** Each undo unit's `SelectionEntry`
(pre- and post-unit selection) is stored on its `Y.UndoManager`
`StackItem.meta` rather than in a parallel array. `commit` writes the
entry onto the unit's StackItem (the item Yjs has already pushed/merged in
`afterTransaction`); `undo` / `redo` read it from the item Yjs pops. Because
Yjs mints a fresh (empty-`meta`) item on the opposite stack for each
undo/redo, `undo` / `redo` re-weld the entry onto that new top so it survives
the round-trip. `undo` returns `before`, `redo` returns `after`. Welding the
selection to the live stack item means it cannot index-desync from the Yjs
stacks — there is no second structure to keep aligned. A dev-mode check
confirms a popped item carries an entry.

**Undo coalescing.** A run of typing collapses into a single undo unit,
matching Google Docs. Two edit kinds are **coalescible**: `insert`
(`INSERT_TEXT`) and `delete` (`DELETE_BACKWARD` / `DELETE_FORWARD` /
`DELETE_WORD` / `DELETE_LINE`). Consecutive **same-kind** coalescible edits
whose gap is `< UNDO_COALESCE_PAUSE_MS` merge into one unit; the merged unit
keeps the run's **original** `before` selection and the **latest** `after`
selection. Coalescing is purely time-based (no word-boundary logic) — a
continuous burst collapses regardless of spaces. A group is **broken** (the
next edit starts a fresh unit) by any of: a **pause** (gap `≥` the window), a
**kind switch** (`insert ↔ delete`), any **discrete command** (split, paste,
formatting, block-type, list, section, header/footer/footnote — each is its
own unit and never coalesces, not even with an identical neighbour), or a
**selection jump** (caret move / selection change / click). `UNDO` / `REDO`
also break the open group; a window resize (`SET_CONTAINER_WIDTH`) is inert —
it neither edits nor breaks coalescing.

The boundary is decided **before** an edit's Y.Doc transaction (under
`captureTimeout: MAX` a transaction merges into the open `StackItem` unless
`stopCapturing` was already called, and a merge cannot be undone). So the
decision is a pre-operation hook, not part of `commit`:

- `beginEntry(key, now)` — called before each committing action. Coalesces
  with the open group iff the key is coalescible, matches the open group's
  key, and the gap is within `UNDO_COALESCE_PAUSE_MS`; otherwise it
  `stopCapturing`s to start a fresh unit. Commands set the open key to null
  (so the next edit also breaks). `BeginKey` is the `insert`/`delete`/`command`
  subset; selection/inert never reach it.
- `breakCoalescing()` — called on selection jumps and on undo/redo. Closes the
  open group so the next edit is fresh. Idempotent and cheap.
- `commit` — no longer closes the group; it only records selection meta. On a
  coalesced merge it preserves the group's original `before` and advances only
  `after`.

The editor reducer is the single chokepoint: it classifies each action with
the pure, exhaustive `coalesceKeyOf` (`editor/coalesce-key.ts`, a `switch`
with a `never` default so a new action forces a classification at compile
time) into `ActionClass = insert | delete | command | selection-break | inert`,
then routes `insert`/`delete`/`command` → `beginEntry`, `selection-break` →
`breakCoalescing`, and ignores `inert`. The clock is injected via
`EditorConfig.now` (defaults to `Date.now`) so the pause window is
deterministically testable. `UNDO_COALESCE_PAUSE_MS` is a `history`-module
constant. See `1.7-editor.md` for the reducer wiring. (Accepted edge: the
boundary advances before the per-action no-op short-circuit, so a no-op
committing action can still close an open typing group — the policy lives in
one place by design.)

**Meta-map non-undoability.** Writes to the doc's meta `Y.Map` (which
holds `rootId`) are intentionally not undoable — `rootId` is
session-immutable. Future meta-map writers MUST explicitly consider
undoability.

**Error recovery.** `undo` / `redo` order their work as
`undoManager.{undo,redo}` → `freshState` → advance `currentState` (and
re-weld the entry onto the opposite stack's new top), all wrapped in
try/catch. `currentState` is advanced last, only after the Yjs reversal
and `freshState` succeed, so a throw from the first two leaves the wrapper
retriable. The caller sees a wrapped error identifying the failure as
history-internal.

**Undo-depth cap.** `commit` trims the oldest entries past `maxDepth`
(default 1000) via `undoManager.undoStack.splice` — the trimmed items
carry their `.meta` away with them, so no separate selection-stack trim is
needed.

### Dirty-set contract (rendering bridge)

Every Layer 3 operation returns an `OperationResult` carrying
`dirtyIds: ReadonlySet<BlockId>` produced at write-time by the
underlying Y.Doc transaction's change set — never by post-hoc tree
comparison.

**Raw vs closure-expanded.** The `dirtyIds` returned by `applyOperation`
(and `History.undo` / `History.redo`) is the **raw mutated set** —
exactly the blocks whose own Y.Doc data changed under the transaction.
The render module's `dirtyIds` input (in `RenderOptions`) is the
**closure-expanded set**: `mutated ∪ ancestors(mutated) ∪
descendants(mutated)`. State emits the raw set; render owns the
closure expansion. The same name across module boundaries refers to
DIFFERENT sets — state's raw set is a strict subset of render's
closure-expanded set. See `1.2-render.md` for the expansion rule.

The renderer contract: `dirtyIds` contains both updated and deleted ids.
Consumers distinguish them with `getBlock(state, id) === null` (deleted)
vs. non-null (updated, re-render). Deletions in `embedContents` use the
same contract via `getEmbedContent`.

This is the engine's incremental-rebuild driver; see `1.2-render.md` for
how the render module consumes `dirtyIds`.

### Inline-attribute interpretation and run merging

State stores attributes openly (any key, any value). Equality for the
purpose of merging adjacent same-attr text items defaults to deep value
equality and consults a per-key `equals` from the **attribute
interpreter registry** (defined in `1.3-cascade.md`).

The cascade module translates `attrs` into declarable `Style` via the
same registry, producing `ComputedStyle` through the existing
resolution pipeline (em/rem flattening, inheritance, defaults). State
holds the open schema; cascade closes it.

### Initial state and creation

- `createEmptyDocument({ allocator? })` returns a `State` whose root is
  a `document` container block holding one empty `paragraph` child. The
  document block is `state.rootId`; the paragraph sits beneath it.

### Performance contracts

- `getBlock` / `getEmbedContent` / `getTemplateContent` — O(1) cache lookup.
- `getEmbedContentIds` / `getTemplateContentIds` — O(roots) to yield from
  the cached root-id set; no per-call scan of the map. The set is
  recomputed (O(N_map_keys)) only after a root is added/removed, which is
  rare relative to keystrokes — so these accessors do not tie per-keystroke
  render cost to embed/template body size.
- All Layer 3 ops — O(N_block) on the touched block(s) plus O(1) per
  affected sibling pointer; structural sharing on the snapshot cache
  preserves reference equality of unchanged block snapshots.
- `compareBlocksInDocOrder` — O(depth + LCA-fanout); bounded by ~100
  sibling-pointer hops at the target document scale.
- `applyOperation` no-op path — O(1) identity return.

The target document scale is smooth editing at ≤ 10,000 blocks per
document; graceful degradation to ≤ 100,000. See the spec doc for the
rationale (recalibrated from the prior "1M blocks" framing).
