# 1.1 — `state/`

The state module is the document model. It is the single source of
truth for everything semantic about the document — what nodes exist,
what their properties and styles are, where the cursor is. It owns no
geometry, no styles-as-resolved-values, and no visual concerns.

## What state is

A document is an immutable tree of `StateNode`s. Each node has an
opaque type (`paragraph`, `text`, `list-item`, etc.), a frozen property
bag, declared inline styles, and an ordered children array. Node identity
is preserved via `id`; the tree is structurally shared across edits, so
any node not on the path of an edit retains its prior reference.

Positions are paths plus offsets: a `Position` names a path of child
indices from the root plus a character offset within the destination
text node. A `Span` is a directed pair of positions (`anchor`, `focus`);
collapsed spans are cursors.

## Submodules

- **`state-node`** — the `StateNode` type definition.

- **`create-node`** — frozen factories that produce `StateNode`s with
  shared empty-styles references when nothing is declared.

- **`operations`** — path-based tree manipulation. `getNodeByPath`,
  `updateAtPath`, `insertChild`, `removeChild`, `updateProperties`. All
  operations preserve sibling references on the unchanged side of the
  path; only the path from root to the touched node is rebuilt.

- **`transformations`** — high-level edits that compose operations.
  `insertText`, `deleteRange`, `replaceRange`, `splitNode`. Each takes a
  state plus a position or span and returns a `Change` (old state + new
  state + timestamp).

- **`formatting`** — inline-style application across spans.
  `applyInlineStyle`, `getStyleInRange`, `remapPosition`.

- **`normalize`** — structural-paragraph maintenance. Ensures, for
  example, that opaque blocks (tables, images) sit between paragraphs
  rather than mid-paragraph; injects empty paragraphs where needed.

- **`position`** — the position/span types and pure manipulations
  (`comparePositions`, `normalizeSpan`, `createPosition`, `createSpan`).

- **`history`** — bounded undo/redo. `createHistory`, `pushChange`,
  `undo`, `redo`. The editor reducer uses this to manage user-visible
  undo grouping.

- **`change`** — the `Change` type returned by transformations:
  `{ oldState, newState, timestamp }`.

- **`dirty`** — `findDirtyPaths(oldState, newState)` walks both trees by
  reference equality and returns the paths where they diverge. Used by
  the editor reducer to decide which subtrees the rendering pipeline
  must rebuild.

- **`extract-text`** — `extractText(state, span)` flattens a span into
  a plain string. Used by clipboard, find/replace, accessibility.

- **`find-path`** — `findPathById` walks the tree to locate a node by
  `id`. Used by external integrations that hold a node reference and
  need to translate to a path.

- **`text-utils`** — `getTextContent`, `getTextContentLength`,
  `clampOffset`. Helpers for working with text-node `content` properties.

- **`new-node`** — the partial-shape type used for `INSERT_NODE`-style
  actions that haven't been assigned an `id` yet.

- **`initial-state`** — `createEmptyDocument()` builds a fresh state
  with a single empty paragraph.

## How submodules connect

`state-node` and `position` are foundational types — every other
submodule imports them.

`operations` and `transformations` are the write API. Editor action
handlers call `transformations` to produce a `Change`; the reducer
records the change in `history` and propagates the new state through the
pipeline.

`dirty` is the bridge to the rendering pipeline: after the state changes,
the reducer compares old and new states via `findDirtyPaths` to drive
incremental rebuild downstream.

`formatting` and `normalize` are higher-level edits that compose
`transformations` and `operations`.

`extract-text`, `find-path`, `text-utils`, `change`, `new-node`,
`initial-state` are utilities consumed by the reducer or by external
integrations.

## Reference

### `StateNode`

```ts
interface StateNode {
  readonly id: string;
  readonly type: string;                                  // open string, registered as a component type
  readonly properties: Readonly<Record<string, unknown>>; // schema-less per-type bag
  readonly style: Readonly<Style>;                        // declared inline styles (closed schema; see 1.3-cascade)
  readonly children: readonly StateNode[];
}
```

`properties` is the per-type extension point. Conventions per built-in type:
- `text` — `{ content: string }`.
- `image` — `{ src: string; width?: number; height?: number }`.
- `list` — `{ listType: "ordered" | "unordered" }`.
- `horizontal-line` — `{}`.
- Other components define their own keys; the property bag is per-type by convention, not enforced by a schema.

All factories (`createNode`, `createTextNode` in `create-node`) freeze their output, including a deep freeze on `properties`, `style`, and `children`. Empty styles share a single `EMPTY_STYLES` reference so equality checks on style identity stay cheap.

### `Position`, `Span`, `Selection`

```ts
interface Position {
  readonly path: readonly number[]; // child indices from root; last index addresses a text node
  readonly offset: number;          // character offset within that text node's `properties.content`
}

interface Span {
  readonly anchor: Position;        // where the span started
  readonly focus: Position;         // current end (cursor moves the focus)
}

type Selection = Span;              // alias defined in cursor/selection
```

Invariants: `path` is non-empty and addresses an existing text node; `offset` is in `[0, getTextContentLength(targetNode)]`. `comparePositions(a, b)` returns negative/zero/positive in document order; when `a.path` is a prefix of `b.path`, the shorter path comes first. `normalizeSpan(span)` returns a span with `anchor` ≤ `focus` in document order.

### Operations (`operations.ts`)

```ts
function getNodeByPath(root: StateNode, path: readonly number[]): StateNode | null;
function updateAtPath(root: StateNode, path: readonly number[], newNode: StateNode): StateNode;
function insertChild(node: StateNode, child: StateNode, index: number): StateNode;
function removeChild(node: StateNode, index: number): StateNode;
function updateProperties(node: StateNode, properties: Record<string, unknown>): StateNode;
```

Reference-equality preservation: `updateAtPath` rebuilds only the chain from root to the target; siblings on each level keep their references. This is the foundation for downstream incremental rebuild.

### Transformations (`transformations.ts`)

```ts
function insertText(state: StateNode, position: Position, text: string): Change;
function deleteRange(state: StateNode, range: Span): Change;
function replaceRange(state: StateNode, range: Span, replacement: string): Change;
function splitNode(state: StateNode, position: Position): Change;
```

Each returns a `Change` (not a state). The reducer wraps with a selection-aware history entry before pushing.

### `Change` and `History`

```ts
interface Change {
  readonly oldState: StateNode;
  readonly newState: StateNode;
  readonly timestamp: number;       // milliseconds since epoch
}

interface History {
  readonly undoStack: readonly Change[]; // most recent last
  readonly redoStack: readonly Change[];
  readonly maxDepth: number;             // default 500
}

function pushChange(history: History, change: Change, collapseThresholdMs: number = 500): History;
function undo(history: History): { history: History; state: StateNode } | null;
function redo(history: History): { history: History; state: StateNode } | null;
```

**History grouping rule.** When `change.timestamp - last.timestamp <= collapseThreshold`, the new change merges with the previous undoStack entry: the merged entry keeps `oldState = last.oldState`, `newState = change.newState`, and `timestamp = last.timestamp` (the *original* timestamp, not the latest — so a long stream of fast keystrokes still groups but doesn't slide the window forward indefinitely). The redo stack is cleared on every push.

The editor reducer wraps `Change` in `EditorHistoryEntry` to also carry `selectionBefore` / `selectionAfter`; selection state restores along with state on undo/redo.

### Dirty tracking (`dirty.ts`)

```ts
function findDirtyPaths(oldRoot: StateNode, newRoot: StateNode): number[][];
function isDirty(oldRoot: StateNode, newRoot: StateNode, path: readonly number[]): boolean;
```

`findDirtyPaths` walks both trees in lock-step, recursing only where references differ. Complexity: O(D) where D = total dirty subtree size — the unchanged subtrees skip via `oldNode === newNode`. Returns an array of paths where the trees diverge, including added / removed / replaced children.

### Formatting (`formatting.ts`)

```ts
function getStyleInRange(state: StateNode, range: Span): Partial<Style>;
function applyInlineStyle(state: StateNode, range: Span, style: Partial<Style>): { newState: StateNode; newRange: Span };
function remapPosition(oldState: StateNode, newState: StateNode, position: Position): Position;
```

`applyInlineStyle` adjusts the state tree to apply the given style across the range, splitting and merging text nodes as needed; `newRange` covers the same content in `newState`. `remapPosition` projects a position from an old state to its corresponding position in a new state after a structural transformation.

### Inline-style data-model strategy

Two strategies were possible: (a) wrap styled runs in `span` nodes whose `style` carries the inline style, or (b) attach the inline style directly to the `text` node's `style` field. The engine chooses **(b) — style attaches to text nodes**. The state tree therefore has the shape `paragraph > [text(style A), text(style B), text(style A), ...]` rather than `paragraph > [text, span(style B) > text, text]`.

Reasoning:
- Inline styles in this engine are a closed set (`fontWeight`, `fontStyle`, `textDecoration`, etc.) carried directly on `StateNode.style`. There is no inline style that requires a wrapping element to express.
- Splitting a text node when style boundaries don't align with the existing tree is simpler than reasoning about span insertion/merging.
- Toolbar "is bold here" indicators read `text.style[prop]` directly at the cursor's text node — fewer edge cases than walking up an ancestor chain looking for a span.

Implementation contract for `applyInlineStyle(state, range, style)`:

1. Normalize `range` so `anchor ≤ focus`.
2. Walk text nodes intersected by `range`. For each:
   - If the text node lies entirely within `range`: produce a single text node with merged `{ ...text.style, ...style }`.
   - If `range` cuts through the text node: split it into up to three text nodes (prefix outside, middle inside, suffix outside) using the existing `splitNode` machinery, then apply the merged style to the middle.
3. Adjacent text nodes whose `style` references are equal (by deep value) MAY be merged back into one text node as a post-pass — this is an optimization, not a correctness requirement.
4. Return `newState` plus `newRange` covering the same content in `newState` (positions remap because intermediate text nodes were split).

The toolbar's "is bold" indicator reads from the current cursor's text node: `editorState.state.children[paragraphIdx].children[textIdx].style.fontWeight === "bold"`. No span lookup needed.

The render layer re-introduces `span` ElementBoxes when adjacent text nodes have different inline styles — the IFC's tokenizer carries the `inlineAncestors` for each token from the render tree's structure. The `span` component's render function may emit either an `ElementBox` (when present in the state tree) or be skipped (when not present) — the rendering of styled inline text doesn't depend on a span existing in the state tree.

### Initial state and helpers

- `createEmptyDocument(): StateNode` — a single empty paragraph wrapping an empty text node.
- `getTextContent(node): string` — reads `properties.content`; returns `""` for non-text nodes.
- `getTextContentLength(node): number` — code-point count, not UTF-16 length.
- `clampOffset(offset, contentLength): number` — clamps to `[0, contentLength]`.
- `findPathById(state, id): number[] | null` — walks the tree to locate by id.
- `extractText(state, span): string` — flattens a span to plain text in document order.

### Performance contracts

- All operations preserve reference equality on subtrees outside the change path.
- `updateAtPath`, `insertText`, `deleteRange`: O(D) where D is the depth of the change path.
- `findDirtyPaths`: O(D′) where D′ is the size of the actually-dirty subtrees.
- `pushChange`: O(1) amortized; the array slice for `maxDepth` enforcement is O(N) only when overflowing (rare).
