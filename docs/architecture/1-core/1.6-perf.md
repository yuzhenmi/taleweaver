# 1.6 — `perf/`

The perf module is a flag-gated tracing API that other modules call
into to measure per-pass latency. It is the only place in core that
carries cross-cutting state — a single shared accumulator of recorded
samples, organized by label.

## API surface

Three primitives:

- **`markStart(label)` / `markEnd(label, token)`** — bracket a region
  of code. `markStart` records a timestamp and returns a token;
  `markEnd` records the elapsed time under `label`. Calls must be
  paired; a `try/finally` around the region keeps the pairing intact
  if the region throws.

- **`recordSample(label, ms)`** — record a pre-measured duration.
  Used when the duration comes from an external source (e.g., React's
  Profiler callback gives `actualDuration` directly).

- **`report()`** — return a snapshot of the accumulated samples (per
  label: count, total ms, average ms).

Plus three lifecycle controls:

- **`setPerfTraceEnabled(value)`** — turn tracing on or off. When off,
  `markStart`/`markEnd`/`recordSample` early-return without recording
  anything; the cost is one boolean check per call.

- **`isPerfTraceEnabled()`** — read the current state.

- **`resetPerfTrace()`** — clear the accumulator. Used between scenarios
  when measuring multiple workloads in one session.

## Where the markers live

The markers are spread across packages but share the same tracing API (imported from `@taleweaver/core`):

**`@taleweaver/core`** markers:
- `cascadePass` and `cascadePassIncremental` — under labels `cascadePass`
  and `cascadePassIncremental`.
- Operation COUNTERS (`recordSample(label, 0)` — the count is the signal, deterministic
  regardless of machine load; used as the typing-latency gates): `render.blockBody` (a
  block rendered), `decorations.mapped` (a decoration carried through an edit),
  `anchors.remapped` (an anchor carried through an edit), `anchors.reindexed` (an
  anchor's covered-block index rebuilt — only on structural edits inside its span),
  `crossReferences.blockRead` (a block the cross-reference index read or walked — one
  per keystroke inside a bookmark target or field host, independent of document size).

**`@taleweaver/print`** markers (layout, cursor geometry, and paint):
- `layoutTree` and `layoutTreeIncremental` — under labels `layoutTree`
  and `layoutTreeIncremental`.
- `bfc.layoutBlock` — `bfc.layoutBlock`.
- `ifc.layoutInlineContent` — `ifc.layout`.
- IFC's wrap loop — `ifc.wrap`.
- IFC cache hit / miss — `ifc.cache.hit` / `ifc.cache.miss`.
- `table-fc.layoutTable` — `table.layout`.
- The geometry-query functions — `cursor.cursor-position`,
  `cursor.hit-test`, `cursor.selection-geometry`.
- Paint — `paint.total`, `paint.walk`, `paint.draw`.
- Editor controller — `ctrl.update`, `ctrl.resolveCursor`,
  `ctrl.selectionRects`, `ctrl.syncDom`, `ctrl.startBlink`,
  `ctrl.paint`, `ctrl.scrollIntoView`, `ctrl.syncPageCanvases`.
- Line-navigation sub-labels — `cursor.line-navigation.moveToLine`,
  `cursor.line-navigation.moveToLineBoundary`.
- Operation counters — `decorations.segmentGeometry` (an inline decoration's geometry
  computed, i.e. a cache miss), `ctrl.widgetResolve` (a widget placed).

**`@taleweaver/digital`** counter — `digital.renderBlock` (a block's DOM rendered).

**`@taleweaver/react`** markers:
- `react.render.EditorView` — React Profiler `actualDuration` routed
  through `recordSample`.
- `react.subscribe.notify` — controller `update(state)` propagation.

## Why a separate module

Tracing must be:

- **Cheap when off.** Most production users never enable it. The early-
  return on a boolean flag costs effectively nothing.
- **Safe under exceptions.** Failing to call `markEnd` on an exception
  path would leak entries; the `try/finally` pattern at every call
  site keeps the accumulator consistent.
- **Centrally queryable.** A single `report()` snapshots everything;
  hosts expose it through dev hooks (e.g., `window.__perfReport()` in
  the React example) for browser-console inspection.

Putting the API in its own module — with no dependencies on other core
modules — lets every module call into it without import cycles.

## Use pattern

The perf module produces measurement, not action. Consumers (the host
or a debugger) read `report()` and decide what to do — log to the
console, write to a file, plot a chart. The engine itself doesn't
react to its own measurements.

## Reference

### API signatures

```ts
function setPerfTraceEnabled(enabled: boolean): void;
function isPerfTraceEnabled(): boolean;

function markStart(label: string): number;          // returns opaque token
function markEnd(label: string, startToken: number): void;
function recordSample(label: string, ms: number): void;

interface PerfReport {
  readonly entries: ReadonlyArray<{
    readonly label: string;
    readonly count: number;
    readonly totalMs: number;
    readonly avgMs: number;
  }>;
}

function report(): PerfReport;
function resetPerfTrace(): void;
```

`markStart` returns a timestamp (or 0 when disabled). `markEnd` recovers the duration via `performance.now() - startToken` and accumulates into the named bucket. The pair is intended for use with `try/finally`:

```ts
const t = markStart("cascadePass");
try {
  // ... work
} finally {
  markEnd("cascadePass", t);
}
```

`recordSample(label, ms)` is the no-pair variant for callbacks that supply a pre-measured duration (e.g., `React.Profiler`'s `actualDuration`).

`report()` returns entries sorted by descending `totalMs`. Calling it does not reset the accumulator.

### Performance contracts

- `markStart` / `markEnd` / `recordSample` when disabled: O(1) with a single boolean check; no allocation.
- When enabled: O(1) per call; one `Map.get` + `Map.set` for the accumulator.
- `report`: O(L log L) where L = unique labels (sort).

### Structural-storage costs

The document is a registry plus flows of pieces with end-mark items (1.1 "Structural
storage"). Each cost below is independent of document size; `state/structural.bench.ts`
(`vitest bench`, production mode) checks them flat from 1e2 to 1e4 paragraphs, and checks
keystroke / Enter / Backspace-merge / remote keystroke in the final and a middle section
of a 2e4-paragraph document split into four sections at the unsectioned cost.

| Operation | Cost | Mechanism |
|---|---|---|
| Block → mark | O(1) | `MarkIndex` lookup (per doc, in memory) |
| Block → holder | O(depth ≤ 4) | piece → flow array → sub-flow / registry entry parents |
| Offset → `(piece, index)` | O(extents + piece) warm; O(paragraph + E) once on a locator miss | the block's cached locator (`state/locator.ts`): an extent scan, then one in-piece walk to the run's boundary item. E = empty / tombstone-only pieces the region crosses |
| Keystroke | O(extents + piece) + Yjs index op O(piece) + the dirty block's read O(paragraph) | the locator's extent length is updated in place; `piece ≤ PIECE_SOFT_MAX` (1024 structs). The dirty set is exactly {owner}: a run terminated by a ¶ changes no link, so no neighbour is a candidate; the position mapping is content-only; local or remote, no previous-version record is derived or compared (no entity appeared or vanished) |
| Enter / Backspace-merge | O(piece) + O(1) registry `set` / delete + O(split / joined paragraphs) dirty / mapping, in any section | one ¶ insert / delete; a full piece gains a sibling piece in O(1); the locators around the ¶ are dropped and rebuilt on their next read. The paragraph's registry entry moves no parent, so no section is walked (see "Any transaction → dirty blocks") |
| Any transaction → dirty blocks | O(changed × piece + touched paragraphs) | two tiers from the transaction's new / deleted structs (`state/flow-dirty.ts`); a content struct in a cached run resolves its owner in O(piece). Structural candidates (neighbourhoods, the mapping's previous-version ids and the rename closure) are dirty only when their record differs between the two versions (exact compare), so an untouched neighbour keeps its snapshot. A definite-dirty id skips the compare and the rename closure: its siblings, edge parent and children are already candidates (a change point's neighbourhood — the holder start's implicit run when no boundary precedes it — the mapping's relinks, the region and grid rules), and a non-edge parent's record cannot change; the previous version is built only for the remaining candidates (none for a keystroke). A candidate's parent is compared only when its position item moved or the transaction changed a section-end or a section / table / row / cell / container entry (a paragraph's or atomic object's entry moves no parent); with no section-end change the previous version reads through the current version's section memos, so a section record re-read (first / last child changed) is O(1) amortized. A transaction that adds / removes a section-end: + O(the sections around it) |
| Locator reconcile | O(changed × piece) | content change → its run's length recomputed; structural change → exactly the touched locators dropped |
| Exact position mapping | O(touched runs × piece) content-only; O(changed + affected paragraphs) structural | `state/tx-mapping.ts`, once per transaction |
| `MarkIndex` maintenance | O(changed) | `afterTransaction` reconcile from `beforeState → afterState` + the delete set |
| Bind a doc (`createState`) | O(doc) once | one scan of every flow (same order as decoding the update) |
| Section derivations | O(1) amortized; O(section) on the first read after a section-end change | `MarkIndex.sections`: a root-flow item's section (the first section-end at or after it, else the final section), memoized per item; a section's neighbouring boundaries (its first child / siblings), memoized per section-end item (the final section: per document). Cleared when a section-end or a section entry changes |
| Table grid | O(table) per grid change | memoized per doc; recomputed after a transaction |

**Piece-size rule.** No write inserts into a piece at or over `PIECE_SOFT_MAX` structs
(tombstones and formats included): it goes to a fresh piece after / before it, or into a
sub-flow mid-piece (depth cap 4 — the documented residue grows with the edit history
at one spot, never with document size).

**Locators.** A text block's locator (`state/locator.ts`) caches its resolved region
(chain marks, boundary, anchor), its derived sibling ids and its EXTENTS: one per run
of content, a run being the content between a boundary item (a live mark or sub-flow
item, or the piece start) and the next boundary in that piece, keyed `(piece, after)`.
Marks and sub-flow items are length-1 embeds Yjs never splits or merges, so the key
survives every edit inside the run. Built on a miss by one walk of the region
(O(paragraph + E)); a local write updates its extent's length in place; each
transaction reconciles from its changed structs (a content change recomputes its run's
length; a structural change drops exactly the locators whose region or links it
touches — the run's owner, the locators holding the item as a chain mark / anchor /
boundary / previous mark and their linked neighbours, the mark id's family; grid /
container changes drop all). Ops apply the same rules eagerly inside their transaction,
so composed steps see their own writes. A hit is validated: every role item must still
be a live effective mark. So a block whose region crosses a large deleted range pays
the crossing once; later keystrokes never walk it.

**Dead pieces.** A piece whose every item is deleted is skipped by the cold flow-order
walks in O(1) once known (`y-flow.ts` `pieceIsDead`; an insert into the piece forgets
it); a past-version walk (`View.keep`) never skips a piece the transaction emptied.

### Per-keystroke inline-storage cost

A block's inline content is its region of a flow (1.1). Yjs disables a `Y.Text`'s
search markers permanently once it holds any formatting item, so every insert /
delete / format walks the edited piece's item list from its start, and the inline
primitives read the block's delta (snapping, marker splits, canonical attrs). The bound
is **O(items in the edited block) per keystroke, independent of document size** — the
same order as the per-dirty-block snapshot rebuild and the History's RelativePosition
encoding. `state/inline-keystroke.bench.ts` (`vitest bench`, production mode) documents
both curves: a keystroke stays flat as the document grows 1e2 → 1e4 blocks with the
edited block fixed, and grows with the edited block's run count.
