# 1.3 — `cascade/`

The cascade module resolves declared styles into computed styles. It is
the second of two style-resolution passes in the CSS pipeline:

1. **Cascade** (this module) — resolve inheritance, initial values, and
   length values that depend only on the cascade chain (`em`, `rem`).
   Output: each render node carries a `ComputedStyle`.
2. **Layout** (next pass; see [`1.4-layout/`](1.4-layout/overview.md))
   — resolve values that depend on geometry (`%` against containing
   block, `auto` against formatting context, intrinsic keywords against
   content). Output: each layout box carries a `UsedStyle` alongside its
   `ComputedStyle`.

Splitting them lets the engine keep `%`, `auto`, and intrinsic-keyword
values *symbolic* through cascade, deferring their resolution to layout
where the necessary geometry is known.

## What computed style is

`ComputedStyle` is the fully-populated, fully-typed version of a
declared `Style` after inheritance and initial values have been applied.
Inheritable properties (font-family, color, line-height) flow down from
ancestors; non-inheritable properties (margin, padding, background) take
their initial value when not declared. `em` and `rem` lengths flatten
into `px` numbers using the resolved font-size at the cascade level
where they appear. Logical-axis properties pass through; the layout
pass owns the mapping from logical to physical at the layout-box
boundary.

`ComputedStyle` is closed over a fixed set of keys (defined in
`styles/computed-style.ts`). Every key has a known type; there's no
schema-less escape hatch.

## Submodules

- **`compose`** — `composeComputed(specified, parentComputed)`. Walks
  the property table (`PROPERTY_META`) and decides per-property whether
  to inherit from `parentComputed`, take `specified`, or fall back to
  the initial value. Returns a fresh `ComputedStyle`.

- **`resolve-length`** — `resolveLength(value, fontSize)`. Resolves a
  declared `Length` at cascade time: numbers and `px` pass through, `em`
  multiplies by `fontSize`, `%` and `auto` and intrinsic keywords pass
  through unchanged for layout to resolve.

- **`cascade-pass`** — the orchestrator. Two entry points:
  - `cascadePass(root)` — full-tree cascade. Walks top-down, calling
    `composeComputed` and then a length-flattening helper at each node.
  - `cascadePassIncremental(newRoot, oldRoot, oldCascadedRoot)` — adds
    a subtree short-circuit: when `newNode === oldNode` *and* the
    parent's `ComputedStyle` reference is unchanged, the corresponding
    `oldCascaded` subtree returns directly. The recompute path also has
    a structural-equality fallback: if the freshly composed
    `ComputedStyle` value-equals the prior one, the old reference is
    reused so child short-circuits can fire on `===`.

  Also exports `computedStylesEqual(a, b)` — a typed property-by-property
  comparison driven by an explicit key list. Used by the layout pass's
  reuse predicate.

## How submodules connect

`compose` and `resolve-length` are pure functions. `cascade-pass`
composes them into the walker.

The cascade is invoked by the editor reducer immediately after the
render pass:

    reducer
      ├─► renderTreeIncremental(newState, oldState, oldRender, registry)
      ├─► cascadePassIncremental(newRender, oldRender, oldCascadedRoot)
      └─► layoutTreeIncremental(newCascaded, oldCascaded, oldLayout, ...)

The output — a render tree where every node has `computedStyle`
populated — is the input to layout.

## Reference equality discipline

The layout pass and the paint pass both use reference equality on
`ComputedStyle` to short-circuit work for unchanged subtrees. The
cascade is therefore the load-bearing layer for incremental performance:
when an unchanged paragraph flows through cascade, its computed style
must come out as the same reference as last time, or every downstream
cache misses.

The structural-equality fallback in `cascadePassIncremental` (described
above) preserves this invariant even when the render tree's parent
re-rendered: if the parent's children-array changed but a particular
child's computed style is value-equal to its prior, the prior reference
is returned. The layout pass's reuse predicate then sees
`newNode.computedStyle === oldNode.computedStyle` and short-circuits.
