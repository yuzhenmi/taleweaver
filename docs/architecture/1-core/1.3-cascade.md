# 1.3 — `cascade/`

The cascade module resolves declared styles into computed styles. It is
the second of two style-resolution passes in the CSS pipeline:

1. **Cascade** (this module) — resolve inheritance, initial values, and
   length values that depend only on the cascade chain (`em`).
   Output: each render node carries a `ComputedStyle`.
2. **Layout** (next pass; see [`2.2-layout/`](../2-print/2.2-layout/overview.md))
   — resolve values that depend on geometry (`%` against containing
   block, `auto` against formatting context, intrinsic keywords against
   content). Output: each layout box carries a `UsedStyle` alongside its
   `ComputedStyle`.

Splitting them lets the engine keep `%`, `auto`, and intrinsic-keyword
values *symbolic* through cascade, deferring their resolution to layout
where the necessary geometry is known.

## What computed style is

`ComputedStyle` is the fully-populated, fully-typed version of a
declared `Style` after inheritance and initial values have been applied.
Inheritable properties (font-family, color, line-height) flow down from
ancestors; non-inheritable properties (margin, padding, background) take
their initial value when not declared. `em` lengths flatten into `px` numbers using the resolved font-size at the cascade
level where they appear (`rem` is not a supported `Length` unit). Logical-axis properties pass through; the layout
pass owns the mapping from logical to physical at the layout-box
boundary.

`ComputedStyle` is closed over a fixed set of keys (defined in
`styles/computed-style.ts`, matching `PROPERTY_META`). Every key has a
known type; there's no schema-less escape hatch.

## Submodules

- **`compose`** — `composeComputed(specified, parentComputed)`. Walks
  the property table (`PROPERTY_META`) and decides per-property whether
  to inherit from `parentComputed`, take `specified`, or fall back to
  the initial value. Returns a fresh `ComputedStyle`.

- **`resolve-length`** — `resolveLength(value, fontSize)`. Resolves a
  declared `Length` at cascade time: numbers and `px` pass through, `em`
  multiplies by `fontSize`, `%` and `auto` and intrinsic keywords pass
  through unchanged for layout to resolve.

- **`flatten-lengths`** — `flattenLengths(cs)`. Resolves `em` lengths to
  px using `cs.fontSize`, propagating the resolved fontSize back into
  the returned `ComputedStyle`. Shared by `cascade-pass` (legacy
  renderer pipeline) and the new renderer's per-block style composition.

- **`cascade-pass`** — the orchestrator. Two entry points:
  - `cascadePass(root)` — full-tree cascade. Walks top-down, calling
    `composeComputed` and then `flattenLengths` at each node.
  - `cascadePassIncremental(newRoot, oldRoot, oldCascadedRoot)` — adds
    a subtree short-circuit: when `newNode === oldNode` *and* the
    parent's `ComputedStyle` reference is unchanged, the corresponding
    `oldCascaded` subtree returns directly. The recompute path also has
    a structural-equality fallback: if the freshly composed
    `ComputedStyle` value-equals the prior one, the old reference is
    reused so child short-circuits can fire on `===`.

  Also exports `computedStylesEqual(a, b)` — a typed property-by-property
  comparison driven by an explicit key list. Used by the layout pass's
  reuse predicate.

- **`attr-registry`** + **`builtin-attrs`** — translation from
  open-schema state attrs to typed `Partial<Style>` contributions.
  `AttrRegistry` maps an `attrKey` (e.g. `"bold"`, `"fontSize"`) to an
  `AttrInterpreter` whose `toStyle(value, ctx?)` validates the raw
  attr value and returns the corresponding `Partial<Style>`. The
  state-to-render pipeline calls `applyAll(attrs)` to merge every
  registered interpreter's contribution, producing the declared
  `Style` that feeds `composeComputed`.

  Note: not every `Style` property has an interpreter. Some are set
  directly by a component's `render` from a component-specific attr
  key — the "component-set" convention. Examples:
  - `components/list-item.ts` derives its marker gutter
    (`paddingInlineStart`) from `view.attrs.listLevel` and bakes
    `markerText` from the render-time numbering service
    (`ctx.counterValue`) — see [`1.2-render.md`](./1.2-render.md)
    "Numbering (list markers)". (There is NO `components/list.ts` and no
    `listType` attr — the flat list model carries the
    ordered/unordered choice in the `listDefs` config, not on the block;
    numbering is a render-service concern, NOT a cascade `counter()` walk.)
  - `components/heading.ts` reads `view.attrs.level` (1-6) and emits
    the matching `fontSize`/`fontWeight`/margins on the ElementBox.

  These attrs intentionally have no interpreter — the component owns
  the translation. Audits of "missing" interpreters should check this
  convention first.

## How submodules connect

`compose`, `resolve-length`, and `flatten-lengths` are pure functions.
`cascade-pass` composes them into the walker.

The cascade is invoked by the editor reducer immediately after the
render pass:

    reducer
      ├─► renderTreeIncremental(newState, oldState, oldRender, registry)
      ├─► cascadePassIncremental(newRender, oldRender, oldCascadedRoot)
      └─► layoutTreeIncremental(newCascaded, oldCascaded, oldLayout, ...)

The output — a render tree where every node has `computedStyle`
populated — is the input to layout.

## Reference equality discipline

The layout pass and the paint pass both use reference equality on
`ComputedStyle` to short-circuit work for unchanged subtrees. The
cascade is therefore the load-bearing layer for incremental performance:
when an unchanged paragraph flows through cascade, its computed style
must come out as the same reference as last time, or every downstream
cache misses.

The structural-equality fallback in `cascadePassIncremental` (described
above) preserves this invariant even when the render tree's parent
re-rendered: if the parent's children-array changed but a particular
child's computed style is value-equal to its prior, the prior reference
is returned. The layout pass's reuse predicate then sees
`newNode.computedStyle === oldNode.computedStyle` and short-circuits.

## Reference

### `Length` / `ComputedLength` / `UsedLength`

Three forms of one concept; each cascade or layout step narrows further.

```ts
type Length =
  | number                                            // shorthand for px
  | { readonly unit: "px"; readonly value: number }
  | { readonly unit: "percent"; readonly value: number }
  | { readonly unit: "em"; readonly value: number };

type LengthOrAuto = Length | "auto";

type ComputedLength =
  | number                                            // px
  | { readonly unit: "percent"; readonly value: number };

type ComputedLengthOrAuto = ComputedLength | "auto";

type UsedLength = number;
type UsedLengthOrAuto = UsedLength | "auto";

type IntrinsicSizingKeyword = "min-content" | "max-content" | "fit-content";
```

Cascade flattens `em` into px (using the resolved `fontSize` at the cascade level where the `em` appears; `rem` is not a supported `Length` unit). `percent` and `auto` and intrinsic keywords pass through unchanged for layout. Layout flattens `percent` against the containing block and `auto` per the FC algorithm; the result is a plain `number`.

### `Style` (declared, all-optional)

  readonly direction?:   Direction;     // "ltr" | "rtl"

  readonly minBlockSize?:  Length | IntrinsicSizingKeyword;

  readonly maxBlockSize?:  Length | "none" | IntrinsicSizingKeyword;

  readonly paddingBlockStart?, paddingBlockEnd?, paddingInlineStart?, paddingInlineEnd?: Length;

### `PROPERTY_META` — inheritance flags

Closed table; one entry per `Style` key. `inherits: true` means the property flows from parent to child when the child doesn't declare it; `inherits: false` means the child takes the initial value when not declared.

| Key (or family) | Inherits |
|---|---|
| `display`, sizing, box-sizing | `false` |
| `writingMode`, `direction` | `true` |
| margin/padding/border (all four sides each) | `false` |
| `backgroundColor` | `false` |
| `fontFamily`, `fontSize`, `fontWeight`, `fontStyle`, `lineHeight`, `color` | `true` |
| `underline`, `lineThrough` | `false` (CSS Text Decoration L3 — ancestor paints across descendants visually; cascade does not inherit) |
| `whiteSpace` | `true` |
| `verticalAlign` | `false` |
| `textAlign`, `textIndent`, `textWrap`, `hyphens`, `letterSpacing`, `wordSpacing`, `textTransform`, `fontFeatureSettings` | `true` |
| `tabStops` | `false` |
| `defaultTabStop` | `true` |
| `language`, `hyphenateLimitChars`, `overflowWrap` | `true` |
| `markerText` | `false` |
| `position`, `insetBlockStart`, `insetBlockEnd`, `insetInlineStart`, `insetInlineEnd`, `zIndex`, `transform`, `transformOrigin`, `opacity` | `false` |
| `float`, `clear` | `false` |
| `breakBefore`, `breakAfter`, `breakInside` | `false` |
| `widows`, `orphans` | `true` |
| `listStyleType`, `listStylePosition` | `true` |

`INITIAL_COMPUTED_STYLE` is the `ComputedStyle` value used when no parent and no declaration applies. Its values follow CSS defaults: `fontSize: 16`, `lineHeight: 1.2`, `display: "inline"`, all margins/paddings/borders `0`, `color: "black"`, `backgroundColor: "transparent"`, `widows: 2`, `orphans: 2`, etc. (Full table in [1.0-styles.md](./1.0-styles.md).)

### `ComputedStyle` (post-cascade)

Same key set as `Style`, but every key is required and `em` is resolved.

```ts
interface ComputedStyle {
  display: Display;
  writingMode: WritingMode;
  direction:   Direction;

  // Sizing — `percent` / `auto` / intrinsic keywords kept symbolic
  inlineSize:    ComputedLengthOrAuto | IntrinsicSizingKeyword;
  blockSize:     ComputedLengthOrAuto | IntrinsicSizingKeyword;
  minInlineSize: ComputedLength | IntrinsicSizingKeyword;
  minBlockSize:  ComputedLength | IntrinsicSizingKeyword;
  maxInlineSize: ComputedLength | "none" | IntrinsicSizingKeyword;
  maxBlockSize:  ComputedLength | "none" | IntrinsicSizingKeyword;
  boxSizing:     "content-box" | "border-box";

  // margin/padding/border — same structure as Style with ComputedLength values
  // ...

  fontSize: number;                    // em already resolved
  lineHeight: number | ComputedLength;
  // ... all other Style fields, in their computed form
}
```

### `cascadePass` and `cascadePassIncremental`

```ts
function cascadePass(root: RenderNode): RenderNode;

function cascadePassIncremental(
  newRoot: RenderNode,
  oldRoot: RenderNode | null,
  oldCascadedRoot: RenderNode | null,
): RenderNode;

function computedStylesEqual(a: ComputedStyle, b: ComputedStyle): boolean;
```

Both return a render tree where every node carries `computedStyle`.

### Algorithm — `cascadePassIncremental`

```
function cascadeNodeIncremental(newNode, oldNode, oldCascaded, parentComputed, oldParentComputed):
  // Subtree short-circuit
  if oldNode != null && oldCascaded != null
       && newNode === oldNode
       && parentComputed === oldParentComputed:
    return oldCascaded

  // Recompute
  base = composeComputed(newNode.style, parentComputed)
  computed = flattenLengths(base)              // resolve em with own fontSize

  // Structural-equality reuse: produces reference equality on unchanged values
  if oldCascaded != null
       && computedStylesEqual(computed, oldCascaded.computedStyle):
    computed = oldCascaded.computedStyle       // reuse the prior reference

  if newNode.type == "text":
    return frozen { ...newNode, computedStyle: computed }

  // Element: recurse into children, matching by key
  oldByKey = map of { oldChild.key → { node: oldChild, cascaded: oldCascadedChild } }
  newChildren = newNode.children.map(child →
    prev = oldByKey.get(child.key)
    return cascadeNodeIncremental(child, prev?.node, prev?.cascaded, computed, oldCascaded?.computedStyle)
  )

  return frozen { ...newNode, computedStyle: computed, children: newChildren }
```

`composeComputed(specified, parentComputed)` walks `PROPERTY_META`. For each key:
- If `specified[key]` is defined → use it.
- Else if `inherits` is `true` and `parentComputed != null` → use `parentComputed[key]`.
- Else → use `INITIAL_COMPUTED_STYLE[key]`.

`flattenLengths(cs)` resolves `em` against `cs.fontSize`. `cs.fontSize` itself is resolved first (via `resolveFontSize`) from the `ComputedStyle`'s own already-composed `fontSize` field (falling back to `INITIAL_COMPUTED_STYLE.fontSize` for the root case — no second chain walk); once it's a number, every other length-typed field that's `em` flattens with it.

### `computedStylesEqual` algorithm

Driven by `COMPUTED_STYLE_KEYS`, which is derived at module load as `Object.keys(PROPERTY_META)` — so new properties added to `PROPERTY_META` are automatically picked up without a manual update to a separate key list. For each key:
- If both values are reference-equal → continue.
- If both are `Length`-shaped objects → compare `unit` and `value`.
- If both are arrays (e.g., `fontFeatureSettings`) → compare lengths and elementwise.
- Otherwise → `===` comparison.

Returns `false` on first inequality, `true` if all keys pass.

### Performance contracts

- `cascadePass`: O(N) where N is the render-tree size.
- `cascadePassIncremental`: O(D) where D is the size of the dirty subtrees plus the path from root to each dirty subtree. Unchanged subtrees short-circuit via `newNode === oldNode`.
- `computedStylesEqual`: O(K) where K = number of keys in `COMPUTED_STYLE_KEYS` (constant).
