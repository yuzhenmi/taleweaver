# 1.4.1 — Block Formatting Context (BFC)

The BFC lays out an element whose `display` is `block`-like (`block`,
`flow-root`, the document root, `inline-block`'s inner content). It
arranges children vertically along the block axis and emits a `BlockBox`.

## Responsibilities

- **Stack children vertically.** Walk children top-down; place each at
  the next available block offset.

- **Margin collapsing.** Adjacent block siblings collapse their
  block-axis margins (top of one with bottom of the prior). Empty blocks
  collapse with both surroundings. Parent/first-child collapsing applies
  when the parent has no top boundary (no padding, no border).

- **Floats.** When a child's `float` is `inline-start` or `inline-end`,
  ask the BFC's `FloatEnvironment` to place it. The float doesn't
  advance the block offset; it shapes the available width at subsequent
  block offsets where lines and other content flow around it. When a
  child has `clear` set, query the float environment for clearance and
  shift the block offset down accordingly.

- **List markers.** Children with `display: list-item` get an associated
  `MarkerBox` emitted at the block-start of the item's first line. The
  marker text is resolved via `list-counter` (decimal, lower-alpha,
  bullet, etc.) using a per-list-counter that increments per item.

- **Anonymous block-runs for mixed content.** When a block element
  contains a mix of block and inline children (paragraphs and runs of
  bare text adjacent to them), the BFC groups inline children into
  anonymous runs and dispatches each through the IFC, splicing the
  resulting lines back in among the block siblings.

- **Subtree reuse.** Before laying out a block, consult the
  `LayoutBoxCache` from the prior layout pass: if the render node is
  equivalent to the cached entry's, the prior `BlockBox` returns by
  reference and no further work happens for this subtree.

- **Fragmentation entry.** When pagination is enabled, the BFC reports
  per-block break-eligibility (`break-before`, `break-after`,
  `break-inside`, widows, orphans) to the fragmenter, which decides
  where pages split.

## Inputs and outputs

The BFC's entry function takes:

- The element's render node (with `ComputedStyle` and children).
- The block offset where layout starts (relative to the parent).
- The inline offset where layout starts.
- A `LayoutContext` carrying writing-mode, direction, containing-inline-size,
  the float environment, the previous-pass cache, and the shaper.

It returns a `BlockBox` containing positioned children
(`BlockBox`, `LineBox`, `TableBox`, `MarkerBox`).

## Float environment lifetime

A box that establishes a new BFC (root, `flow-root`, `inline-block`,
floats themselves, table cells, `overflow: hidden|auto`) gets a fresh
`FloatEnvironment` from `makeChildContext`. A box that does *not*
establish a new BFC inherits its parent's float environment, so its
floats rise to the nearest BFC ancestor and shape that ancestor's flow.
The flag `LayoutContext.isBFCRoot` distinguishes the two cases.

## Margin-collapsing + clearance interaction

When a block has a non-zero margin AND a `clear` property AND the
previous siblings produced floats that would clear, CSS 8.3.1 specifies
a particular interaction: the larger of the collapsed margin and the
clearance distance applies, but the margin doesn't shift through the
clearance. The BFC tracks `clearanceApplied` per child to honor this.

## Incremental considerations

The BFC is the load-bearing site for layout reuse. Two reuse gates fire:

- **Strict identity** (`renderNode === entry.renderNode`): the input
  render node is the exact same reference as the one that produced the
  cached box. Most subtree reuses go through this path.

- **Layout-equivalent identity** (`renderNodesLayoutEquivalent`): the
  parent was rebuilt with a fresh children-array, but its children are
  reference-equal to the cached entry's. Used for the document root
  after a single-paragraph edit, where most paragraphs flow through
  unchanged. Without this gate the BFC would iterate every child;
  with it, the entire document subtree returns by reference.

Both gates additionally check `isLayoutBoxReusable` to confirm
container size, writing-mode, and float-env dirty offset haven't shifted.
