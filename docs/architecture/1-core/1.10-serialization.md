# 1.10 — Document serialization

This module turns a document `State` into bytes (or text) and back. It is the
engine's **encode → wire** and **wire → decode** boundary; the host owns where
those bytes live (a database row, a file, a network frame). The engine does not
read or write storage — it only (de)serializes.

Serialization is pluggable: one `DocumentSerializer` per wire format, looked up
in a `SerializerRegistry` by a stable format id. The v1 built-in is a **lossless
binary** serializer backed by Yjs's native update format.

## Why it lives inside `state/`

The serializer consumes and produces `State`, and the binary serializer needs the
raw underlying `Y.Doc`, which lives behind the module-private `STATE_INTERNAL`
symbol (see [`1.1-state.md`](1.1-state.md) and `state/state-internal.ts`). That
symbol is deliberately NOT re-exported from the `state/` barrel — the whole Yjs
encapsulation depends on it. Every legitimate consumer
(`build-state-from-blocks.ts`, `list-defs.ts`, `initial-state.ts`) reaches the
`Y.Doc` by a relative sibling import of `state-internal`. The serialize module
does the same: it lives at `state/serialize/` and imports
`STATE_INTERNAL` by sibling path. A `serialize/` directory OUTSIDE `state/` could
not legally reach the doc. The serialize barrel's public surface is re-exported
through `state/index.ts` (and onward through the core barrel); `getMetaRootId`
(the meta-map read the binary decoder uses) stays state-private.

## The `DocumentSerializer` contract

```ts
type SerializedDocument = Uint8Array | string;

interface DocumentSerializer<TWire extends SerializedDocument = SerializedDocument> {
  readonly format: string;                 // stable format id; the registry key
  encode(state: State): TWire;
  decode(source: TWire): State;
}
```

`encode` / `decode` are INVERSES for round-trippable formats — the binary
serializer is exactly lossless. `SerializedDocument` is `Uint8Array | string`:
binary for the Yjs-native format, text for a future human-friendly format.

Dependencies a serializer needs (e.g. an `IdAllocator` for a future structured
text decoder) are injected at CONSTRUCTION — a factory closing over them — NOT
passed per call. That keeps the interface a clean two-method contract and keeps
per-call sites (the engine dispatch below) dependency-free.

## The registry

`SerializerRegistry` mirrors the component and attribute registries: a small
interface over a `Map`, keyed by `serializer.format`, with two factories.

```ts
interface SerializerRegistry {
  register(serializer: DocumentSerializer): void;
  get(format: string): DocumentSerializer | undefined;
  has(format: string): boolean;
}

createSerializerRegistry(): SerializerRegistry          // empty — tests isolate behavior
createDefaultSerializerRegistry(): SerializerRegistry   // pre-registers the binary serializer
```

`register` stores by the serializer's own `format`. A
`DocumentSerializer<Uint8Array>` is assignable to the registry's
default-generic `DocumentSerializer`, so the binary serializer registers without
ceremony.

## Engine-level dispatch

Two pure functions look up the serializer for a `format` and delegate. They are
the engine entry points the host calls.

```ts
serializeDocument(state: State, format: string, registry: SerializerRegistry): SerializedDocument
deserializeDocument(source: SerializedDocument, format: string, registry: SerializerRegistry): State
```

When `format` is not registered, both throw `UnknownSerializerFormatError`
(carrying the offending `format`). A serializer's `decode` may additionally throw
`MalformedDocumentError` for structurally-invalid wire data.

## The v1 Yjs-binary serializer

`createBinaryDocumentSerializer()` returns the `DocumentSerializer<Uint8Array>`
registered under `BINARY_FORMAT` (`"taleweaver-binary"`).

State is Yjs-native, so the round-trip is a thin shell over Yjs's update codec:

- **encode**: `Y.encodeStateAsUpdate(doc)` captures the ENTIRE `Y.Doc` — all
  three block trees (`blocks` / `embedContents` / `templateContents`), the
  `listDefs` config side-table, and the `meta` map (which carries the immutable
  `rootId`) — into one `Uint8Array`.
- **decode**: `Y.applyUpdate(freshDoc, update)` rebuilds that doc exactly, then
  the decoder reads `rootId` via `getMetaRootId(doc)` and calls
  `createState({ rootId, doc })`. `createState` is idempotent on already-seeded
  meta, and the freshly-decoded `State` correctly starts with an EMPTY snapshot
  cache — the cache is a derived read-side structure over the `Y.Doc`, not part
  of the serialized document.

`getMetaRootId` returns `undefined` when the decoded doc carries no (valid)
`rootId` — e.g. a bare `Y.Doc` that never seeded one. The decoder turns that into
a `MalformedDocumentError`, the one structural-validity check it owns. (Raw
garbage bytes are a different failure: `Y.applyUpdate` may throw a Yjs-internal
error before the rootId check is even reached.)

The **v1** update codec (`encodeStateAsUpdate` / `applyUpdate`) is used, not v2 —
v1 is the interchange unit Yjs's own ecosystem (the `y-*` bindings) treats as
stable.

### Round-trip guarantee + format stability

`decode(encode(state))` reconstructs a `State` structurally equal to the input
across every block in all three trees (each block's `type`, `attrs`,
parent/sibling/child links, and `inlineContent` — text items with attrs, embed
items with `embedType` + `properties`), the `listDefs`, and `rootId`. The
per-State snapshot cache is intentionally NOT preserved (it is derived).

`BINARY_FORMAT` is a STABLE id. A future format change ships a NEW id; old bytes
are never reinterpreted under a different meaning. This is what lets a stored
document name its format and decode unambiguously years later.

## Host-owns-persistence boundary

The engine's responsibility ends at `Uint8Array` / `string`. Saving, loading,
chunking, compression, and transport are the host's. This keeps the engine
runtime-agnostic (no filesystem, no network) and lets different hosts (a desktop
shell, a server, a browser app) make their own storage choices over the same
wire format.

## Named follow-ups (future, not degraded splits)

- An **editor-level export/import wrapper** that pairs the serialized document
  with editor-session state (selection, scroll) for a complete save/restore.
- A **human-friendly text serializer** (a second `DocumentSerializer` under its
  own format id) for diff-friendly / inspectable output.
- **v2 / migration**: when the document model changes shape, a new format id plus
  a decode path that upgrades old bytes — never an in-place reinterpretation of
  the v1 id.

## Relationship to collaborative editing

The binary serializer uses the SAME Yjs update primitives a future collab sync
transport will use (per [CLAUDE.md](../../../CLAUDE.md), the state model is built
on Yjs primitives from the start). Serialization (whole-doc snapshot) and collab
(incremental update exchange) are distinct concerns, but both ride
`encodeStateAsUpdate` / `applyUpdate`, so the binary format and collab transport
share a foundation rather than diverging.
