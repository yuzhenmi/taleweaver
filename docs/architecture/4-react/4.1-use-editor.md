# 4.1 — `use-editor`

The `useEditor` hook is the React-side owner of an editor's state. It
wraps `core`'s reducer in `useReducer`, constructs an `EditorConfig`
once on mount, and hands back the values its companion component
(`EditorView`) needs to wire itself up.

## Return shape

`useEditor()` returns a record:

- `editorState` — the current `EditorState`, returned from
  `useReducer`.
- `dispatch` — the React-managed dispatcher. Calls `reduceEditor` under
  the hood (the config rides on `editorState.config`).
- `containerRef` — a `useRef` for the HTML container. The component
  attaches this to its outer `div`.
- `shaper` — the canvas-based `TextShaper` constructed at hook init
  time. Forwarded to `EditorView` as a prop.
- `focus` — a callback that focuses the editor's hidden textarea. The
  component exposes this so consumers can call `editor.focus()`
  programmatically.
- `halted` / `replaceDocument` — the HALTED state of the print controller (2.8; 1.5
  "Incompatible documents"). The hook is linked to the `<EditorView>` it drives
  AUTOMATICALLY — through its stable `dispatch` (an internal `WeakMap` from the hook's
  `dispatch` to its halt link) — so no prop wiring is needed, PROVIDED the view receives
  the hook's OWN `dispatch` unwrapped (a wrapper breaks the link: the hook is never told
  of a halt; in dev builds the view warns once when it gets a hook's `editorState` with
  another `dispatch`, detected through an internal `WeakMap` from each state the hook
  hands out to its `dispatch`):
  when a peer update carries legacy inline storage the controller halts, `halted`
  becomes true, the option `onIncompatibleDocument` is called once per halt, and `dispatch`
  ignores actions (the reducer would read the incompatible document). The hook owns the
  state, so it RESUMES BY ITSELF when the shared document is upgraded — by an upgraded
  peer, by this host itself, or while no view was mounted (a re-mounted view's halted
  controller inspects the document at once) — the controller's `onDocumentCompatible`: it replaces the document with a fresh Document over
  the same Y.Doc. `replaceDocument(document)` shows another document — a fresh
  `EditorState` (the old `History` destroyed, caret at the start); passing an
  `upgradeDocument`-ed document resumes a halted editor. The controller is the source of
  truth for halted and the hook mirrors it: legacy storage returning before a resume
  reaches the controller, or a replacement the controller refuses, halts the hook again
  (the option is called again). The live `History` is tracked
  in a ref updated synchronously by `replaceDocument`, so several replacements in one
  React batch each destroy the history they replace.

The host application calls `useEditor()` once per editor and forwards
the whole record to `<EditorView>`.

## Initialization

On mount the hook constructs an `EditorConfig`:

- The component registry is built from `defaultComponents` (the
  built-in document/paragraph/text/etc. components shipped by `core`).
  Hosts that need custom components (charts, equations) supply them
  via a registry override; the default hook uses the built-ins.

- The text measurer is a canvas-based shaper produced by
  `createCanvasShaper`. The hook owns its own internal canvas for
  measurement — separate from the visible canvas the editor paints
  to (which `EditorView` owns).

- `containerWidth` is initialized to a default; a `ResizeObserver` set
  up by the hook itself (in a `useEffect`, observing `containerRef`) later
  dispatches `SET_CONTAINER_WIDTH` actions to keep this in sync with the
  actual container.

The config is stored in a ref to keep its identity stable across
renders — every `EditorState` the hook builds (the initial one and each
`replaceDocument`) carries the same config, so the registries never churn.

## Initial state

`createInitialEditorState(config)` produces an empty document with a
single empty paragraph. The initial state carries NO geometry — there are
no `renderTree`/`layoutTree` fields on `EditorState`; `lastDirtyIds` is
`null` to signal an initial full build. The backend layout-driver builds
the render/layout tree from `state` on the first `update()`. The hook
returns this initial state from `useReducer`'s initializer.

## Why a hook

The hook isolates React-specific lifecycle (mount, render, unmount,
ref-equality) from the engine. The engine's reducer is a pure function;
the hook is the place where that function meets React's `useReducer`
machinery. Splitting them lets `core` stay framework-agnostic — a Solid
or Svelte adapter could re-implement the hook in its own framework
without changing anything in `core`.

## Reference

### Public API

```ts
interface UseEditorOptions {
  // The attr registry (built-ins + host marks from `registerMark`).
  // Default: createDefaultAttrRegistry().
  readonly attrRegistry?: AttrRegistry;
  // Host extensions: commands, keymap, input rules, triggers.
  readonly extensions?: EditorExtensions;
  // Page setup (size, margins, gap); undefined ⇒ unpaginated. Like every option it
  // lands on `editorState.config`, which the reducer and the print controller both read.
  readonly pageConfig?: PageConfig;
  // The controller HALTED on incompatible (legacy) document storage (called once per halt).
  readonly onIncompatibleDocument?: (report: IncompatibleDocumentReport) => void;
}

interface UseEditorReturn {
  readonly editorState: EditorState;
  readonly dispatch: React.Dispatch<EditorAction>;
  readonly containerRef: React.RefObject<HTMLDivElement | null>;
  readonly shaper: TextShaper;
  readonly focus: () => void;
  readonly halted: boolean;
  readonly replaceDocument: (state: State) => void;
}

function useEditor(options?: UseEditorOptions): UseEditorReturn;
```

### Initialization sequence

1. `configRef = useRef<EditorConfig | null>(null)` — holds `{ componentRegistry, attrRegistry, containerWidth }`, created once on first render (NOT the shaper).
2. If `configRef.current === null`:
   - `registry = createDefaultComponentRegistry()`.
   - `attrRegistry = options?.attrRegistry ?? createDefaultAttrRegistry()`.
   - `containerWidth = DEFAULT_WIDTH` (a constant; updated later via `SET_CONTAINER_WIDTH`).
   - Store `{ componentRegistry: registry, attrRegistry, containerWidth }` (plus `extensions` / `pageConfig` when given) in `configRef.current`.
3. `shaperRef = useRef<TextShaper | null>(null)` — holds the canvas-based `TextShaper`, separate from `configRef`.
4. If `shaperRef.current === null`:
   - Create a hidden `<canvas>` element via `document.createElement("canvas")`.
   - `shaperRef.current = createCanvasShaper(canvas)`.
5. `useReducer(reducer, configRef.current, init)` where:
   - `reducer = (document, message) => message is a document replacement ? its EditorState : reduceEditor(document, message)` (the config rides on the state).
   - `init = (config) => createInitialEditorState(config)`.
   The returned `dispatch` forwards actions only while not halted.
6. `containerRef = useRef<HTMLDivElement>(null)`.
7. `useEffect` installs a `ResizeObserver` on `containerRef.current` to dispatch `SET_CONTAINER_WIDTH` when the container resizes.
8. `focus = useCallback(() => containerRef.current?.querySelector("textarea")?.focus(), [])`.

### Performance contracts

- `useEditor` first render: O(N) where N is initial-document size (cold render + cascade + layout).
- Subsequent renders: O(D) where D is the dirty subtree size.
