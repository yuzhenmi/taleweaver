# 2.3 — `paint-cache`

The paint cache is the per-canvas memory that lets the renderer skip
work for boxes that haven't changed since the previous paint. It is the
companion to `core`'s layout-tree reuse: whereas the layout pass keeps
unchanged subtrees by reference, the paint cache keeps unchanged
*pixels* by tracking what was last painted.

## What's cached

Two pieces of state:

- **A per-`LayoutBox` paint-input hash.** A string-encoded summary of
  every input that determines what the box paints — geometry (parent-
  relative position and size), paint-relevant `ComputedStyle` fields
  (color, font properties, decoration, border colors and styles,
  background, direction), paint-relevant `UsedStyle` fields (paddings,
  border widths), and type-specific fields (text content, baseline,
  fragment-edge marker, marker text). Two boxes with the same hash
  produce identical paint output.

  The hash is stored in a `WeakMap` keyed by the box itself. When a box
  is no longer referenced (e.g., because its render node was deleted),
  the entry auto-collects.

- **The last-walked root reference.** A separate slot remembers which
  layout-tree root was passed to the most recent `walkAndDetectChanges`
  call. The walk's root short-circuit checks this before doing any work.

## API

`createPaintCache()` returns a `PaintCache` with:

- `get(box)` / `set(box, hash)` / `isUnchanged(box)` — per-box hash
  access.
- `getLastRoot()` / `setLastRoot(root)` — last-walked root tracking.
- `clear()` — reset both. Used when the host wants to force a full
  repaint (e.g., on theme change, font reload).

Plus a free function `hashPaintInputs(box) → PaintInputHash` that
computes the hash for one box. Both the renderer (for comparison
during walk) and consumers (for tests, dev tooling) call it.

## How the walk uses it

`walkAndDetectChanges(box, ..., cache, dirty, isRoot)` recurses the
layout tree:

1. **Root short-circuit.** If `isRoot` and `cache.getLastRoot() === box`,
   return immediately. The whole tree is reference-equal to last time;
   no box can have changed.

2. **Per-box hash compare.** Otherwise, compute the box's current hash
   and compare to `cache.get(box)`. If different, push the box's
   absolute rectangle onto the dirty list and update the cache. If
   same, the box is unchanged.

3. **Recurse.** Walk children regardless of whether the parent's hash
   changed (children may have changed even if the parent didn't —
   different inputs, different cache entries).

After the walk, the renderer calls `cache.setLastRoot(box)` so the next
walk's root short-circuit can fire.

## Two layers of reuse

The cache is at the *paint* layer, atop `core`'s reuse at the *layout*
layer. They compose:

- When the layout pass returns a reference-equal layout tree (no edits,
  cursor moves only, etc.), the paint walk's root short-circuit fires
  and skips all work. Canvas remains untouched.

- When the layout pass produces a tree where most paragraphs are
  reference-equal but one changed, the per-box hash compare fires on
  the changed paragraph and emits a dirty rect there. Other paragraphs
  short-circuit at their box's `cache.get` check (hash unchanged). Only
  the changed paragraph re-clears and repaints.

Without `core`'s reuse, the cache would hash every box on every paint
even when nothing changed. Without the cache, the renderer would clear
and repaint the whole canvas. Together, they collapse paint cost to
the actually-changed regions.

## Why a `WeakMap`

`LayoutBox` instances flow through the engine many times — created in
the layout pass, queried by the editor, painted by the renderer. The
cache references each box, but the box itself owns the lifetime: when a
new layout pass produces a fresh tree and the old tree's boxes are no
longer referenced anywhere, the `WeakMap` lets the entries collect.
A regular `Map` would retain every box ever painted.

## Reference

### Public API

```ts
type PaintInputHash = string;

interface PaintCache {
  get(box: LayoutBox): PaintInputHash | undefined;
  set(box: LayoutBox, hash: PaintInputHash): void;
  isUnchanged(box: LayoutBox): boolean;
  clear(): void;
  getLastRoot(): LayoutBox | null;
  setLastRoot(root: LayoutBox | null): void;
}

function createPaintCache(): PaintCache;
function hashPaintInputs(box: LayoutBox): PaintInputHash;
```

### `hashPaintInputs` exact construction

Concatenated string. Sections joined by `|`; values within a section joined by `:`.

```
{box.x}:{box.y}:{box.width}:{box.height}
| cs:{backgroundColor}:{color}:{fontFamily}:{fontSize}:{fontWeight}:{fontStyle}:{underline}:{lineThrough}
   :{borderBlockStartStyle}:{borderBlockEndStyle}:{borderInlineStartStyle}:{borderInlineEndStyle}
   :{borderBlockStartColor}:{borderBlockEndColor}:{borderInlineStartColor}:{borderInlineEndColor}
   :{direction}
| us:{paddingBlockStart}:{paddingBlockEnd}:{paddingInlineStart}:{paddingInlineEnd}
   :{borderBlockStartWidth}:{borderBlockEndWidth}:{borderInlineStartWidth}:{borderInlineEndWidth}
| (type-specific)
```

Type-specific suffix:
- `text-run` → `|text:{text}`
- `marker` → `|marker:{text}`
- `line` → `|baseline:{baseline}`
- `inline` → `|fragment:{fragmentEdge}`
- `table` → `|cols:{columnPxWidths.join(",")}`

Two boxes with the same hash produce identical paint output. Collision is theoretically possible but unlikely for normal documents — strings encode each numeric/string value distinctly.

### `walkAndDetectChanges` algorithm

```
function walkAndDetectChanges(box, parentX, parentY, cache, dirty, isRoot):
  // Root short-circuit
  if isRoot && cache.getLastRoot() === box:
    return

  absX = parentX + box.x; absY = parentY + box.y

  currentHash = hashPaintInputs(box)
  cachedHash = cache.get(box)

  if cachedHash !== currentHash:
    dirty.push({ x: absX, y: absY, w: box.width, h: box.height })
    cache.set(box, currentHash)

  if "children" in box:
    for child in box.children:
      walkAndDetectChanges(child, absX, absY, cache, dirty, false)
```

Callers (`paintCanvas`, `paintPage`) call this once per paint with `isRoot: true`, then `cache.setLastRoot(rootBox)` to enable the next call's short-circuit.

### Performance contracts

- Root short-circuit fires (layout tree reference unchanged): O(1).
- Per-box hash compare: O(N) where N is the number of layout boxes; per-box cost is the hash construction (constant per box but proportional to the type-specific suffix length).
- `WeakMap` lookups and inserts: O(1) amortized.
