# 2.5 — `html-serializer`

The HTML serializer is the human-friendly `DocumentSerializer<string>` that
ships with `dom`, registered under the format id `taleweaver-html`. Its job is
**readable authoring** of documents — letting a host seed long, hand-written
content (a public-domain chapter, a fixture) as an HTML string rather than
hand-building state. It is NOT a lossless interchange format; the
`taleweaver-binary` serializer in `core` owns lossless, id-preserving round-trips.

## Why it lives in `dom`, not `core`

`core` is platform-agnostic and must not depend on DOM APIs. DECODE needs an
HTML parser, and the engine's chosen parser is the browser-native `DOMParser`
(zero new runtime dependency; jsdom supplies it under the dom test env). So the
serializer lives in `packages/dom`, where `DOMParser` is available. ENCODE is
pure string-building with no DOM dependency, but encode and decode are a cohesive
pair and ship together in one module.

The construction primitive both halves rely on — `buildDocumentFromTree` — is
the format-agnostic foundation in `core` (see
[`1.10-serialization.md`](../1-core/1.10-serialization.md) and the state barrel).
DECODE lowers parsed HTML to a declarative `BlockNode` tree and hands it to
`buildDocumentFromTree`, which mints block ids and derives every structural link.

## Public surface

```ts
export const HTML_FORMAT = "taleweaver-html";
export function createHtmlDocumentSerializer(deps: {
  allocator: IdAllocator;
}): DocumentSerializer<string>;
```

The `IdAllocator` is injected at construction (decode mints fresh block ids).
The serializer exposes the standard `format` / `encode` / `decode` contract.

## Internal structure

- `html-serializer.ts` — the public factory; wires the encode/decode helpers
  into a `DocumentSerializer`.
- `html-encode.ts` — `encodeHtml(state): string`, pure (no DOM).
- `html-decode.ts` — `decodeHtml(html, allocator): State`, via `DOMParser`.
- `dev-mode.ts` — the dom-local `isDevMode()` gate (core's is barrel-excluded).

## Supported subset

The format expresses the LOGICAL document — element nesting, document order, and
semantic marks — the way Google Docs' human interchange does. v1 round-trips
this subset **semantically** (structure + types + supported attrs + text +
mark-sets), NOT by block-id identity (decode mints fresh ids — decoding the same
HTML twice yields distinct ids by design):

| Engine | HTML |
|---|---|
| `document` root | `<body>` |
| `heading` (`attrs.level` 1–6) | `<h1>`…`<h6>` |
| `paragraph` | `<p>` |
| `list-item` (`listId`, `listLevel`) | grouped under `<ul>`/`<ol>`, nested by level |
| ordered vs unordered | `<ol>` vs `<ul>` (via `classifyListDef`) |
| `horizontal-line` | `<hr>` |
| `table` (`columnWidths`) → `table-row` → `table-cell` (`rowSpan`/`colSpan`) | `<table>` (optional `<colgroup>` of `<col style="width:%">`) → `<tr>` → `<td>` (`rowspan`/`colspan` when > 1); cell content encoded recursively. **ENCODE only** — decode does not yet parse `<table>`. |
| `image` (`src`, `width`, `height`) | `<img src width height>` |
| mark `bold` | encode `<strong>` / decode `<strong>` + `<b>` |
| mark `italic` | encode `<em>` / decode `<em>` + `<i>` |
| mark `underline` | `<u>` |
| mark `strikethrough` | encode `<s>` / decode `<s>` + `<del>` |
| mark `link` (URL payload) | `<a href>` |
| `hard-break` embed | `<br>` |

**Lists** use the Google-Docs flat model: `list-item` blocks are siblings sharing
one `listId`, with `listLevel` for nesting depth (NOT nested `<li>` blocks).
ENCODE groups consecutive same-`listId` items into one `<ul>`/`<ol>`, opening and
closing nested lists by `listLevel` (arbitrary depth, via a nesting stack).
DECODE mints a fresh `listId` per TOP-LEVEL list and threads it through nested
lists (incrementing depth), emitting one flat `list-item` per `<li>`. Each
top-level list gets one default `listDefs` entry (`<ol>` → decimal, `<ul>` →
disc).

**Mark accumulation on decode is order-independent**: walking down an inline
subtree, each recognized mark element adds its attr to the active set, so
`<strong><em>x</em></strong>` and `<em><strong>x</strong></em>` both yield one
text run `x` with `{bold, italic}`. `<a href>` adds `link = href`. Unknown inline
wrappers (e.g. `<span>`) are recursed into so their text survives; unknown block
elements are ignored but recursed into so a wrapper's supported children surface.

## Lossiness boundary (binary is the lossless escape)

Out of v1 scope (dropped on encode, ignored on decode): footnotes,
cross-references, headers/footers, sections, `tab` embeds, and open
style attrs (color, fontSize, fontFamily, textTransform, textAlign, writingMode,
direction, margins, tabStops). **Tables** now ENCODE (`<table>`/`<tr>`/`<td>`,
above) — so they are no longer lost on export; DECODE of a pasted `<table>` back
into `table` blocks is a tracked follow-up. Two accepted semantic losses are documented and
test-locked:

- **Content-bearing embed drops warn.** When encode skips a `footnote-anchor` or
  `cross-reference` embed (author-written content lost on HTML export), it emits a
  dev-mode `console.warn` — at most once per distinct dropped embed type — naming
  the dropped type and pointing at `taleweaver-binary` as the lossless path. Style
  attrs are dropped silently (they degrade to default rendering; no content is
  lost). Production pays nothing (the warn is dev-gated).
- **Non-consecutive same-`listId` runs split.** Two list-item runs sharing one
  `listId` but separated by a non-list block (a valid flat-model state) encode as
  two separate `<ul>`/`<ol>` elements and decode to two distinct lists. Rare in
  prose; documented, not silently surprising.

## Error contract

The HTML decoder NEVER throws `MalformedDocumentError`. `DOMParser` is lenient
(it recovers any string into a tree), the empty/all-unsupported body falls back
to a single empty `paragraph` (a valid minimal editable doc), the typed `string`
contract rules out non-string input, and the discriminated-union `BlockNode`
makes the container-XOR-leaf invariant a compile-time guarantee. Strictness is
per-serializer: the binary serializer still throws on a missing rootId.

## Untrusted-input sanitization (decode is a trust boundary)

Decoded HTML can come from an untrusted source (paste / `loadDocument`), so decode
sanitizes URL-bearing attributes SYMMETRICALLY with encode (`isExportSafeLinkUrl`
in `url-safety.ts`, the allowlist `http`/`https`/`mailto`/`tel`/relative): an
`<a href>` or `<img src>` whose scheme is `javascript:`/`data:`/`vbscript:`/`file:`
is dropped (the `<a>`'s link text is kept; the `<img>`'s `src` becomes `""`), so a
decoded document never carries an executable-scheme URL into the click-nav path or
the canvas image loader. (`data:image` paste is a future rich-paste concern;
the boundary stays allowlist-only.) Decode also recovers a list nested DIRECTLY
inside a list with no intervening `<li>` (the `<ol><ol>` shape a list-LEVEL JUMP
encodes to, and a common Word/web paste shape) by recursing it one level deeper —
without which the deeper items were silently dropped.

## Registration

`core` cannot pre-wire this serializer into `createDefaultSerializerRegistry` (it
lives in `dom` and needs an `IdAllocator`). The host composes it manually:

```ts
const reg = createDefaultSerializerRegistry();
reg.register(createHtmlDocumentSerializer({ allocator: productionAllocator }));
// loadDocument(html, HTML_FORMAT, reg, config)
```
