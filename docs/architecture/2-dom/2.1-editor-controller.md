# 2.1 — `editor-controller`

The editor controller is the host orchestrator. The host application
constructs one per editor instance, hands it an HTML container, and
forwards its lifecycle (`update`, `focus`, `destroy`). Internally the
controller owns the canvases, the input listeners, the cursor blink
animation, and the paint flow. It is the point where `core`'s pure
engine connects to the browser's mutable DOM.

## Construction

`createEditorController(container, options) → EditorController` takes:

- The HTML container the editor will render into.
- A `measurer` — the host's `TextShaper` (or legacy `TextMeasurer`)
  implementation. The default in this package is `createCanvasShaper`.
- A `dispatch` callback — how the controller forwards `EditorAction`s
  to the host's reducer.
- Optional `pageHeight` and `pageGap` — pagination configuration.
  When set, the controller activates per-page canvases; when unset,
  it uses a single full-document canvas.

It returns three methods:

- `update(state)` — call after every state change to repaint and
  reposition.
- `focus()` — programmatically focus the editor's hidden textarea.
- `destroy()` — tear down listeners, animation timers, canvases.

## Internal modules

The controller is a single file (`editor-controller.ts`) that composes
the other dom modules:

- **Canvas management.** Owns either one canvas (non-paginated) or a
  pool of per-page canvases (paginated). Resizes them based on the
  document's layout output and the device-pixel-ratio.

- **Painting.** On each `update(state)`, selects the correct paint
  function (`paintCanvas` for single-canvas, `paintPage` per page) and
  passes the relevant `LayoutBox` plus the controller's `PaintCache`
  instance. The cache enables the renderer's incremental short-circuit;
  see [`2.2-canvas-renderer.md`](2.2-canvas-renderer.md) and
  [`2.3-paint-cache.md`](2.3-paint-cache.md).

- **Input listeners.** Installs DOM listeners on the container and a
  hidden textarea (the textarea captures keystrokes, IME composition,
  and clipboard events while the canvas captures mouse and scroll).
  Translates events through `key-handler` (for keyboard) and
  inline logic (for mouse/scroll) into `EditorAction`s, then forwards
  to the dispatch callback.

- **Cursor blink.** A `setInterval`-driven timer that toggles cursor
  visibility every 500ms while the editor is focused. The timer calls
  the paint function with the current state; the renderer's root
  short-circuit + `paint.draw` viewport culling keep the cost minimal.

- **Scroll syncing.** When pagination is active, scrolls between page
  canvases by adjusting their CSS positions. When non-paginated,
  delegates scroll to the surrounding container.

- **Image cache.** A separate `ImageCache` instance manages async-
  loaded image resources for image blocks; when an image finishes
  loading, the controller re-paints to render it.

## Paint cache lifetime

The controller creates one `PaintCache` per canvas at construction time
(or per page at first paint, in paginated mode). The cache lives for
the controller's lifetime. On `destroy()`, the cache is dropped along
with everything else.

Reuse fires across the controller's lifetime: the second call to
`update` benefits from the first call's hashes, the third from the
second's, etc. This is the load-bearing optimization for cursor blink
and cursor moves: when only the cursor's position changed, the layout
tree's root reference is unchanged, the cache short-circuits, and the
paint walk does no work beyond redrawing the cursor itself.

## Why the controller exists in `dom` rather than `core`

The controller is mutable: it owns DOM listeners, animation timers,
canvases. `core` is pure — it cannot hold mutable references or react
to time. Putting the controller in `dom` keeps the boundary clean: the
controller is the only mutable thing in the engine boundary, and
everything mutable lives behind its interface.

## Reference

### Public API

```ts
interface EditorControllerOptions {
  readonly measurer: TextShaper | TextMeasurer;
  readonly dispatch: (action: EditorAction) => void;
  readonly pageHeight?: number;
  readonly pageGap?: number;
}

interface EditorController {
  update(state: EditorState): void;
  focus(): void;
  destroy(): void;
}

function createEditorController(
  container: HTMLElement,
  options: EditorControllerOptions,
): EditorController;
```

### Internal state

The controller is a closure over private mutable state:

- `state: EditorState | null` — the most recent state passed via `update`.
- `singleCanvas: HTMLCanvasElement | null` — non-paginated mode only.
- `singleCtx: CanvasRenderingContext2D | null`.
- `activeCanvases: Map<number, HTMLCanvasElement>` — paginated mode; one per page index.
- `pages: LayoutBox[]` — the current `PageBox`es (paginated mode only).
- `canvasCache: PaintCache` — shared paint cache for non-paginated mode.
- `pageCaches: Map<number, PaintCache>` — per-page paint caches.
- `imageCache: ImageCache` — async image loader.
- `cursorPos: { x, y, height, lineY, lineHeight, pageIndex }` — last-resolved cursor.
- `selectionRects: SelectionRect[]` — last-resolved selection rectangles.
- `focused: boolean` — whether the textarea has focus.
- `cursorVisible: boolean` — flips on each blink-timer tick.
- `blinkIntervalId: number | null` — `setInterval` handle.
- `isDragging: boolean`, `dragAnchor: Position | null` — drag-selection state.
- `isComposing: boolean` — IME composition state.
- `destroyed: boolean` — set by `destroy()` to short-circuit pending callbacks.

### Lifecycle in detail

`createEditorController(container, options)`:

1. Style the container (`position: relative`, `outline: none`, `cursor: text`, `userSelect: none`).
2. Create a hidden `<textarea>` inside the container, focus it.
3. Install event listeners on the textarea (keydown, beforeinput, input, compositionstart/update/end, copy, cut, paste, blur, focus) and on the container (mousedown, mousemove, mouseup, scroll, wheel).
4. Create the `canvasCache: PaintCache`.
5. Start the cursor-blink interval (paused when not focused).
6. Return the `EditorController` instance.

`controller.update(state)`:

1. Store `state` in the closure.
2. Compute `cursorPos` via `resolvePixelPosition(state.layoutTree, state.selection.focus)`.
3. Compute `selectionRects` via `computeSelectionRects(state.layoutTree, state.selection)`.
4. Detect paginated vs non-paginated via `state.layoutTree.children` containing `PageBox`es.
5. In non-paginated mode: ensure the single canvas exists, sized to `state.layoutTree.width × state.layoutTree.height × dpr`. Call `paintCanvas(...)` with `canvasCache`.
6. In paginated mode: synchronize `activeCanvases` with `pages.length`, create/destroy canvases as needed. For each visible page, call `paintPage(...)` with `getOrCreatePageCache(pageIndex)`.

`controller.destroy()`:

1. Set `destroyed = true`.
2. Clear the blink interval.
3. Cancel pending RAFs.
4. Remove DOM listeners.
5. Remove the textarea, canvases, spacer divs.
6. Clear `canvasCache` and `pageCaches`.

### Event handlers

| Event | Handler |
|---|---|
| `textarea.keydown` | `mapKeyEvent(e)` → if non-null and not composing, `dispatch(action)`. |
| `textarea.beforeinput` | If `inputType === "insertText"`, dispatch `INSERT_TEXT` with `e.data`. Suppress for IME composition (handled separately). |
| `textarea.compositionstart` | Set `isComposing = true`; remember composition-start position. |
| `textarea.compositionupdate` | Re-render the composition region with distinct styling (target architecture; not yet implemented). |
| `textarea.compositionend` | Dispatch `INSERT_TEXT` with the committed text; set `isComposing = false`. |
| `container.mousedown` | Hit-test → `SET_SELECTION`. Set `dragAnchor` and `isDragging` based on shift/click count. |
| `container.mousemove` while dragging | Hit-test → `SET_SELECTION` extending from `dragAnchor`. |
| `container.mouseup` | Clear `isDragging`. |
| `container.scroll` | Update visible viewport bounds; trigger re-paint with new `visibleTop`/`visibleBottom`. |
| `textarea.focus` / `textarea.blur` | Update `focused`; start/stop blink. |

### Cursor-blink timer

```
const BLINK_INTERVAL_MS = 500;

function startBlink():
  stopBlink();
  cursorVisible = true;
  if (!focused) return;
  blinkIntervalId = setInterval(() => {
    cursorVisible = !cursorVisible;
    paint();
  }, BLINK_INTERVAL_MS);

function stopBlink():
  if (blinkIntervalId !== null) {
    clearInterval(blinkIntervalId);
    blinkIntervalId = null;
  }
```

When the engine state hasn't changed between blinks, the layout tree is reference-equal across `paint()` calls; the renderer's root short-circuit keeps the cost negligible.
