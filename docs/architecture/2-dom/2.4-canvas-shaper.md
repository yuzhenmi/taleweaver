# 2.4 — `canvas-shaper`

The canvas shaper is the default `TextShaper` implementation that ships
with `dom`. It produces shaped runs for the engine's IFC and painter by
delegating glyph rendering and metrics to the browser's canvas API,
supplemented with the engine's own Unicode-algorithm code for cluster
boundaries, bidi levels, and break opportunities.

> ## ⚠️ Status: shipped v1 is simpler than the target state below
> This file documents the **target** shaper. The **shipped v1**
> (`packages/dom/src/canvas-shaper.ts` — the authoritative current behavior)
> is intentionally simpler and does NOT yet implement the UAX algorithms or
> hyphenation described later. What v1 actually does today:
> - **Clusters:** one cluster per UTF-16 **code unit** (`segmentClusters`),
>   NOT UAX #29 graphemes via `Intl.Segmenter`. No ligature detection.
> - **Break opportunities:** a simple **whitespace + hard-break heuristic**
>   (soft break after each whitespace; hard break at `\n`/`\r`). NOT UAX #14;
>   there is no line-break property table.
> - **Bidi:** a single **uniform per-run level** (0 for LTR, 1 for RTL from
>   `baseDirection`). NOT UAX #9; mixed-direction text is not cluster-resolved.
> - **Options / hyphenation:** `createCanvasShaper(canvas)` takes **no options**.
>   There is no `CanvasShaperOptions`, no `hyphenator`, no dictionary loading.
>
> Everything below describing `Intl.Segmenter`, UAX #9/#14, the line-break
> table, and hyphenation is **[TARGET — not yet implemented]**. A HarfBuzz-WASM
> backend (`@taleweaver/shaper-harfbuzz`) is the planned path to the full target
> via the same `TextShaper` interface.

## Construction

`createCanvasShaper(canvas) → TextShaper`. The host instantiates one
shaper per editor and passes it as `EditorConfig.measurer`. The shaper
holds a reference to a canvas's 2D rendering context — used internally
to call `measureText` and to read font metrics.

A single shaper instance can serve many shape calls; it has no
per-string state.

## What it does

For each `shape(text, computedStyle, options)` call, the shaper:

1. **Resolves the font.** Builds the canvas font string from the
   computed-style font fields (`fontStyle fontWeight fontSize fontFamily`)
   and assigns it to the context.

2. **Measures glyph advances.** Calls `measureText(text)` on the
   context. The browser's underlying text shaper (HarfBuzz on Chrome
   / Firefox, CoreText on WebKit) does the heavy lifting — handling
   ligatures, kerning, contextual forms, and font-feature-settings
   honored by the OS.

3. **Computes cluster boundaries (UAX #29). [TARGET]** Walks the input
   string to identify grapheme clusters — base codepoints with combining
   marks, emoji ZWJ sequences, regional indicator pairs. Each cluster
   maps to one cursor stop and is treated as atomic for line-break
   decisions. *(Shipped v1: one cluster per UTF-16 code unit; no grapheme
   clustering.)*

4. **Computes bidi levels (UAX #9). [TARGET]** Determines the bidi level
   per cluster from the script and the surrounding context's base
   direction. Outputs uniform-direction runs as a single level; mixed-
   direction runs (Hebrew embedded in English, Arabic in Latin) get
   per-cluster levels for the IFC's reorder pass. *(Shipped v1: one
   uniform per-run level from `baseDirection`; no per-cluster bidi.)*

5. **Computes break opportunities (UAX #14). [PARTIAL]** Walks the text
   and identifies positions where line wrap may occur — after spaces,
   after hyphens, before/after CJK characters, etc. Hyphenation
   opportunities (within-word breaks) come from a per-language
   dictionary when the `hyphens` style + the document language
   request them. *(Shipped v1: whitespace + hard-break heuristic only;
   no UAX #14 walk, no hyphenation.)*

6. **Reads font metrics.** Ascent, descent, x-height, line-height —
   read from the `TextMetrics` object the canvas returns. Used by the
   IFC for baseline alignment.

The output is a `ShapedRun` containing positioned glyphs (with
advances), cluster boundaries, bidi levels, break opportunities, and
font metrics — the engine's IFC and painter both consume from this
single representation.

## What it doesn't do

The canvas shaper does not implement a HarfBuzz integration in
JavaScript. It relies on the browser's native shaper for the actual
glyph positioning. This means:

- **Latin and most European scripts** render correctly because the
  browser handles them well via canvas.
- **Arabic, Hebrew** render correctly because the browser shapes them
  for `fillText`; the shaper's bidi work makes them flow correctly in
  multi-script lines.
- **Indic, complex emoji ZWJ sequences** may render imperfectly at
  cluster boundaries that the canvas's shape grouping doesn't expose
  cleanly. A future plan can ship a `@taleweaver/shaper-harfbuzz`
  package that bundles HarfBuzz-WASM for cases where canvas falls
  short; the engine consumes either backend through the same
  `TextShaper` interface without modification.

## Hyphenation dictionaries [TARGET — not implemented in v1]

Hyphenation is language-dependent and dictionary-driven. The shaper
loads a dictionary (e.g., Knuth-Liang patterns) per declared document
language and generates within-word break opportunities for each word
when the `hyphens` style requests them. Loading is async; until the
dictionary lands the shaper falls back to no-hyphenation.

## Font fallback

When a glyph isn't available in the requested font, the browser's
canvas falls back to a configured font chain. The shaper sees the
final advance widths post-fallback and exposes them; the engine
doesn't need to know about the fallback chain itself.

## Why this is the default

A canvas shaper is the cheapest path to a working engine in a browser:
no WASM bundle, no font fetching, no integration work. It's good enough
for the dominant document use cases (Latin and CJK with Hebrew/Arabic
supported via the browser's bidi-capable shaper) and gives the engine
correct cluster, bidi, and break behavior even when the underlying
glyph shaper is opaque.

When richer shaping is needed, the same engine accepts a different
implementation — the contract is the `TextShaper` interface, not the
canvas-specific implementation.

### `shape()` algorithm

**[TARGET]** The pseudocode below is the target algorithm (`Intl.Segmenter`
grapheme clustering + hand-rolled UAX #9 bidi). The shipped v1
(`canvas-shaper.ts`) instead: segments one cluster per UTF-16 code unit
(`segmentClusters`), emits break opportunities from the whitespace/hard-break
heuristic, and returns a single uniform `bidiLevel` (`baseDirection === "rtl" ? 1
: 0`) with no per-cluster bidi pass. See the status banner and the Status column
above for the per-item divergence.

```
function shape(text, cs, baseDirection):
  applyFont(ctx, cs)

  // 1. Cluster boundaries
  segmenter = new Intl.Segmenter(cs.fontFamily.includes(...) ? lang : "default", { granularity: "grapheme" })
  clusters = []
  for segment in segmenter.segment(text):
    advance = ctx.measureText(segment.segment).width
    clusters.push({
      start: segment.index,
      end:   segment.index + segment.segment.length,
      inlineAdvance: advance,
      isLigature: false,                    // simplified; canvas doesn't expose ligature info
      glyphs: [],                           // canvas doesn't expose glyph IDs
    })

  // 2. Bidi levels
  bidiLevels = computeBidiLevels(text, baseDirection)  // hand-rolled UAX #9
  // Aggregate per cluster (max level over the cluster's codepoints)

  // 3. Break opportunities
  breakOpportunities = []
  for cluster in clusters:
    if isAfterSpace(cluster) || isAfterCJKBreakable(cluster) || isAfterHyphen(cluster):
      breakOpportunities.push({ clusterIndex: cluster.index, kind: "soft" })

  // (hyphen opportunities defer to a future plan)

  // 4. Font metrics
  metrics = ctx.measureText("M")
  ascent = metrics.fontBoundingBoxAscent ?? metrics.actualBoundingBoxAscent
  descent = metrics.fontBoundingBoxDescent ?? metrics.actualBoundingBoxDescent
  lineGap = cs.lineHeight is number ? cs.lineHeight * cs.fontSize - (ascent + descent) : 0

  // 5. Aggregates
  unbreakableRunInlineSize = sum(clusters.map(c => c.inlineAdvance))
  minClusterInlineSize = max(clusters.map(c => c.inlineAdvance))

  return {
    text, computedStyle: cs,
    clusters,
    ascent, descent, lineGap,
    minClusterInlineSize, unbreakableRunInlineSize,
    breakOpportunities,
    bidiLevel: paragraphBaseLevel(baseDirection),
  }
```

### Performance contracts

- `shape(text, cs)` cold: O(L) where L = `text.length`.
- `measureFontMetrics(cs)`: O(1) (a few `measureText` calls — `"Hg"`, `"x"`, `"H"`).
- The canvas's underlying `measureText` is fast (microseconds for typical run lengths). **[TARGET]** the hand-rolled UAX #9/14 work would dominate per call but is also linear; the shipped v1's whitespace-heuristic break detection is the linear pass today.
