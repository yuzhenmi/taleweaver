# 3.2 — `editor-view`

`<EditorView>` is the React component that mounts a `dom` controller
into the React tree and binds it to the `useEditor` hook's lifecycle.
It owns no engine state of its own; it owns the DOM container, the
controller's lifetime, and the React-side update propagation.

## Props

`EditorViewProps` matches the shape returned by `useEditor`:

- `editorState` — the current state.
- `dispatch` — the action dispatcher.
- `containerRef` — the ref for the editor's outer `div`.
- `measurer` — the text shaper.
- `focus` — focus callback (passed through; not used internally).
- Optional `pageHeight` and `pageGap` — pagination configuration.

## Lifecycle

The component runs two effects:

1. **Mount.** A `useEffect` with empty dependencies. Calls
   `createEditorController(container, options)` where `container` is
   the ref's current node and `options` carries `measurer`, `dispatch`,
   and pagination settings. Stores the resulting controller in a
   component-local ref. Its cleanup function (run on unmount) calls
   `controller.destroy()`, freeing listeners, animation timers, and
   canvases.

2. **State change.** A `useEffect` keyed on `editorState`. Calls
   `controller.update(editorState)` so the controller repaints and
   repositions for the new state. The update is wrapped with a
   `markStart` / `markEnd` pair under `react.subscribe.notify` so the
   perf module measures how long state propagation takes.

## Imperative handle

`EditorView` is a `forwardRef<EditorViewHandle, EditorViewProps>`. A
`useImperativeHandle(ref, () => ({...}), [])` exposes the controller's
find-session + replace methods so a parent-held find bar (Find & Replace
UI) can drive find/replace without reaching into the encapsulated
controller:

```ts
interface EditorViewHandle {
  findStart(query: string, options?: FindMatchesOptions): FindStatus;
  findNext(): FindStatus;
  findPrev(): FindStatus;
  findClose(): void;
  replaceActive(replacement: string): FindStatus;
  replaceAll(replacement: string): FindStatus;
  findStatus(): FindStatus;
}
```

Each handle method delegates to `controllerRef.current?.<method>(...)`,
reading the ref **lazily at call time** (so the `[]` deps are correct —
the controller is assigned in the mount effect, after the handle is
created). When the controller is still null (pre-mount), the
status-returning methods return the empty `{ total: 0, activeIndex: -1 }`
and `findClose` is a no-op. The handle type is re-exported from the
`react` package index. (The find bar reads `findStatus()` each render for
the authoritative "n of N" — the parent re-renders after every dispatch,
so the count auto-refreshes the render after a replace/edit.)

## Render output

The component renders a single `<div ref={containerRef}>`. The
controller appends its canvas, hidden textarea, and pagination DOM
inside this div on mount. The component itself produces no other React
children — the editor's UI is canvas-painted, not React-rendered.

The render is wrapped in a `React.Profiler` whose `onRender` callback
forwards `actualDuration` to the perf module under
`react.render.EditorView`. The Profiler has no functional effect; it
exists for measurement.

## Why two pieces (`useEditor` + `EditorView`)

Splitting the hook from the component lets consumers:

- **Mount the editor in different DOM positions.** Some applications
  put the editor in a portal, a modal, a tabbed panel — the consumer
  controls where `<EditorView>` mounts while the hook's state lives
  alongside the rest of the consumer's React tree.

- **Tap the editor's state for sidebars and toolbars.** A toolbar that
  shows "this paragraph is bold" reads from `editor.editorState`
  alongside the rest of the React component tree, dispatches
  `APPLY_INLINE_STYLE` actions, and lets `<EditorView>` repaint via
  the normal effect chain.

- **Compose multiple editors.** A consumer with several editors on a
  page calls `useEditor()` per editor and renders each into its own
  `<EditorView>`. Each editor has independent state, controller, and
  paint cache.

The hook + component pattern is conventional React; `dom`'s controller
is the imperative half hidden behind it.

## Reference

### Public API

```ts
interface EditorViewProps {
  readonly editorState: EditorState;
  readonly dispatch: React.Dispatch<EditorAction>;
  readonly containerRef: React.RefObject<HTMLDivElement | null>;
  readonly measurer: TextShaper | TextMeasurer;
  readonly pageHeight?: number;
  readonly pageGap?: number;
}

interface EditorViewHandle {
  findStart(query: string, options?: FindMatchesOptions): FindStatus;
  findNext(): FindStatus;
  findPrev(): FindStatus;
  findClose(): void;
  replaceActive(replacement: string): FindStatus;
  replaceAll(replacement: string): FindStatus;
  findStatus(): FindStatus;
}

const EditorView: React.ForwardRefExoticComponent<
  EditorViewProps & React.RefAttributes<EditorViewHandle>
>;
```

### Component flow

```tsx
const EditorView = forwardRef<EditorViewHandle, EditorViewProps>(function EditorView(
  { editorState, dispatch, containerRef, measurer, pageHeight, pageGap },
  ref,
) {
  const controllerRef = useRef<EditorController | null>(null);

  // Imperative handle: delegate the controller's find/replace methods.
  // Each closure reads controllerRef.current lazily, so [] deps are correct.
  useImperativeHandle(ref, () => ({
    findStart: (q, o) => controllerRef.current?.findStart(q, o) ?? EMPTY_FIND_STATUS,
    // ...findNext / findPrev / findClose / replaceActive / replaceAll / findStatus
  }), []);

  // Mount: create the controller
  useEffect(() => {
    const el = containerRef.current;
    if (!el) return;
    const ctrl = createEditorController(el, { measurer, dispatch, pageHeight, pageGap });
    controllerRef.current = ctrl;
    ctrl.update(editorState);
    return () => ctrl.destroy();
  }, []); // mount-only

  // State change: forward to the controller
  useEffect(() => {
    const t = markStart("react.subscribe.notify");
    try {
      controllerRef.current?.update(editorState);
    } finally {
      markEnd("react.subscribe.notify", t);
    }
  }, [editorState]);

  return (
    <Profiler id="EditorView" onRender={handleProfile}>
      <div ref={containerRef} />
    </Profiler>
  );
});

const handleProfile: ProfilerOnRenderCallback = (id, _phase, actualDuration) => {
  if (!isPerfTraceEnabled()) return;
  recordSample(`react.render.${id}`, actualDuration);
};
```

### Performance contracts

- React's reconciliation per render: O(1) (the component renders a single `<div>`; React does not see the canvas or its descendants).
- `controller.update(editorState)`: dominated by `paintCanvas`/`paintPage` cost; see [`2.2-canvas-renderer.md`](../2-dom/2.2-canvas-renderer.md) and [`2.3-paint-cache.md`](../2-dom/2.3-paint-cache.md).
- `React.Profiler` is a no-op in production builds and adds negligible overhead in development.
