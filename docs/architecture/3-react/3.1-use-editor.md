# 3.1 — `use-editor`

The `useEditor` hook is the React-side owner of an editor's state. It
wraps `core`'s reducer in `useReducer`, constructs an `EditorConfig`
once on mount, and hands back the values its companion component
(`EditorView`) needs to wire itself up.

## Return shape

`useEditor()` returns a record:

- `editorState` — the current `EditorState`, returned from
  `useReducer`.
- `dispatch` — the React-managed dispatcher. Calls `reduceEditor` under
  the hood with the cached config.
- `containerRef` — a `useRef` for the HTML container. The component
  attaches this to its outer `div`.
- `measurer` — the canvas-based `TextShaper` constructed at hook init
  time. Forwarded to `EditorView` as a prop.
- `focus` — a callback that focuses the editor's hidden textarea. The
  component exposes this so consumers can call `editor.focus()`
  programmatically.

The host application calls `useEditor()` once per editor and forwards
the whole record to `<EditorView>`.

## Initialization

On mount the hook constructs an `EditorConfig`:

- The component registry is built from `defaultComponents` (the
  built-in document/paragraph/text/etc. components shipped by `core`).
  Hosts that need custom components (charts, equations) supply them
  via a registry override; the default hook uses the built-ins.

- The text measurer is a canvas-based shaper produced by
  `createCanvasShaper`. The hook owns its own internal canvas for
  measurement — separate from the visible canvas the editor paints
  to (which `EditorView` owns).

- `containerWidth` is initialized to a default; a `ResizeObserver` set
  up by `EditorView` later dispatches `SET_CONTAINER_WIDTH` actions to
  keep this in sync with the actual container.

The config is stored in a ref to keep its identity stable across
renders — the reducer expects the same config across calls so that
component-registry lookups and the measurer don't churn.

## Initial state

`createInitialEditorState(config)` produces an empty document with a
single empty paragraph and runs the pipeline once to populate
`renderTree` and `layoutTree`. The hook returns this from `useReducer`'s
initializer.

## Why a hook

The hook isolates React-specific lifecycle (mount, render, unmount,
ref-equality) from the engine. The engine's reducer is a pure function;
the hook is the place where that function meets React's `useReducer`
machinery. Splitting them lets `core` stay framework-agnostic — a Solid
or Svelte adapter could re-implement the hook in its own framework
without changing anything in `core`.

## Reference

### Public API

```ts
interface UseEditorReturn {
  readonly editorState: EditorState;
  readonly dispatch: React.Dispatch<EditorAction>;
  readonly containerRef: React.RefObject<HTMLDivElement | null>;
  readonly measurer: TextShaper | TextMeasurer;
  readonly focus: () => void;
}

function useEditor(): UseEditorReturn;
```

### Initialization sequence

1. `configRef = useRef<EditorConfig | null>(null)` — created once on first render.
2. If `configRef.current === null`:
   - Create a hidden `<canvas>` element.
   - `measurer = createCanvasShaper(canvas)`.
   - `registry = createRegistry(defaultComponents)`.
   - `containerWidth = DEFAULT_WIDTH` (a constant; updated later via `SET_CONTAINER_WIDTH`).
   - Store `{ measurer, registry, containerWidth }` in `configRef.current`.
3. `useReducer(reducer, configRef.current, init)` where:
   - `reducer = (state, action) => reduceEditor(state, action, configRef.current!)`.
   - `init = (config) => createInitialEditorState(config)`.
4. `containerRef = useRef<HTMLDivElement>(null)`.
5. `useEffect` installs a `ResizeObserver` on `containerRef.current` to dispatch `SET_CONTAINER_WIDTH` when the container resizes.
6. `focus = useCallback(() => containerRef.current?.querySelector("textarea")?.focus(), [])`.

### Performance contracts

- `useEditor` first render: O(N) where N is initial-document size (cold render + cascade + layout).
- Subsequent renders: O(D) where D is the dirty subtree size.
