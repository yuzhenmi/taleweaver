# 2.10 — `dom-mirror`

`buildDomMirror` is the dom-side consumer of the core accessibility projection.
It is a **pure structural transform**: given an `AccessibilityNode` tree (from
core's `buildAccessibilityTree`, see
[`1-core/1.8-accessibility.md`](../1-core/1.8-accessibility.md)), it returns a
detached, visually-hidden, AT-visible semantic DOM subtree. No side effects, no
mounting, no controller coupling — it builds and returns one `HTMLElement` and
nothing else.

The canvas is the *visual* surface; assistive technology cannot read pixels. The
DOM mirror is the *semantic* surface a screen reader traverses, kept off-screen
but exposed to the accessibility tree.

## Public surface

```ts
export function buildDomMirror(
  node: AccessibilityNode,
  doc?: Document,
): HTMLElement;
```

`doc` defaults to the ambient `document` global and is injectable for testing /
non-default environments (jsdom supplies it under the dom test env).

## Why it lives in `print`, not `core`

`core` is platform-agnostic and must not depend on DOM APIs; `buildDomMirror`
calls `doc.createElement` / `createTextNode`. The projection it consumes
(`buildAccessibilityTree`) is the platform-agnostic, geometry-free half in
`core`; the DOM materialization is the dom half. The split mirrors the
serializer split (core builds the model, dom touches `DOMParser`).

## Role → element mapping

The transform walks the `AccessibilityNode` tree, mapping each node's `role` to
an element (and ARIA where the element alone is not enough), then appends the
node's text runs followed by its child subtrees, recursively.

| Role | Element / ARIA |
|---|---|
| `document` | `div[role=document]`, visually hidden (see below) |
| `paragraph` | `p` |
| `heading` (`level` 1–6) | `h1`…`h6` by level (defaults to `h1` when level is absent or out of range) |
| `list` (`listOrdered`) | `ol` when `listOrdered`, else `ul` |
| `listitem` (`listOrdinal`) | `li`; an ordered item's `listOrdinal` → `value=N` so AT numbers start-at/restart lists correctly |
| `table` | `table` |
| `row` | `tr` |
| `cell` | `td` |
| `columnheader` | `th[scope=col]` |
| `img` (`name`) | `span[role=img][aria-label=name]` (empty `aria-label` for a decorative/anonymous image) |
| `separator` | `hr` |
| `navigation` | `nav` |
| `banner` | `header` |
| `contentinfo` | `footer` |
| `doc-footnote` (`sourceBlockId`) | `section[role=doc-footnote]`, `id` = `sourceBlockId` when present |

## Text-run rendering

A node's `text` (an array of `AccessibilityTextRun`) becomes a sequence of
wrapper elements appended to the node's element. The outermost wrapper is chosen
by run kind:

| Run kind | Wrapper |
|---|---|
| `noteref` | `a[role=doc-noteref][href=#<noteref>]` (takes priority over `link`) |
| `link` | `a[href]`, with the URL sanitized through `isExportSafeLinkUrl` (`@taleweaver/core`'s `url-safety.ts`) — a dangerous scheme (`javascript:`/`data:`/…) drops the `href` but keeps the `<a>` for AT semantics |
| `insertion` suggestion | `ins` |
| `deletion` suggestion | `del` |
| plain | `span` |

Emphasis is nested **innermost-first** in a fixed order, so the outermost
emphasis element is `strong` when bold is active: `strong > em > u > s`.

Every run wrapper is stamped with `data-offset-start` / `data-offset-end` — the
LITERAL block offsets carried by the run. These are the forward hook a future
Selection-sync layer maps display positions back to literal `{blockId, offset}`
Positions through. A run inside a comment also carries `data-in-comment="true"`
for comment provenance; an `img` node carries its name as `aria-label`.

## Page-field run resolution

A page-valued field run (`fieldKind` set — `"page-number"` / `"page-count"` /
`"cross-ref-page"`, see
[`1-core/1.8-accessibility.md`](../1-core/1.8-accessibility.md)) carries a `""`
placeholder `text`, because the geometry-free core projection cannot know a value
that only exists after pagination. Two pure helpers resolve that text from a
layout-resolved values map (keyed by the run's `fieldKey` render key):

- `resolveFieldText(run, resolvedFields)` — returns the run's display text. A
  `cross-ref-page` / `page-count` run takes its value from the map by `fieldKey`,
  with a `""` map value (a broken cross-reference) resolving to the
  `BROKEN_CROSS_REFERENCE_TEXT` sentinel; a `page-number` run, a run with no map
  entry, and a non-field run keep their original `text`.
- `resolveTreeFields(node, resolvedFields)` — a structural walk that returns a
  copy of the `AccessibilityNode` tree with every field run's `text` rewritten
  through `resolveFieldText`. It is identity-preserving: a node with no field
  runs to rewrite (and whose children are likewise unchanged) is returned BY
  REFERENCE, so an empty / absent map leaves the whole tree untouched and the
  walk allocates nothing.

The host calls `resolveTreeFields` at the top of `syncTree`, upstream of
reconciliation, so the resolved text drives the fingerprint and the mirror
re-syncs on a page-count change (see [`2.11-dom-mirror-host.md`](./2.11-dom-mirror-host.md)).

## Visually-hidden technique

The `document`-role host is hidden with the **clip technique**
(`position:absolute; width:1px; height:1px; overflow:hidden;
clip:rect(0,0,0,0); white-space:nowrap`) — off-screen yet AT-visible. It is
deliberately NOT `display:none` / `visibility:hidden` / `aria-hidden`, all of
which would hide the subtree from assistive technology and defeat the mirror's
entire purpose.

## Exhaustiveness

The role switch is TypeScript-exhaustive over all `AccessibilityRole` members,
with no `default` arm: adding a new role to the core projection is a compile
error here until it is mapped. This pairs with the core projection's runtime
exhaustiveness guard — a newly-added document shape cannot silently fall out of
the accessibility surface on either side.

## The materialization layer: `dom-mirror-host`

`buildDomMirror` is the pure structural builder. The materialization layer that
consumes it — `createDomMirrorHost` (`dom-mirror-host.ts`) — is [implemented] and
wired into the editor controller behind the default-off `accessibilityMirror`
flag. It:

- mounts and reconciles (`reconcileMirror` in `dom-mirror-cache.ts`) the hidden
  mirror subtree into the editor container on each paint, resolving page-valued
  field runs upstream of the diff;
- owns the controlled-`contenteditable` input wiring (engine owns all edits);
- syncs the browser `Selection` to and from the engine's `Position`/`Span`
  through the runs' `data-offset-start` / `data-offset-end` + blocks'
  `data-block-id` hooks (`dom-mirror-selection.ts`).

See [`2.11-dom-mirror-host.md`](./2.11-dom-mirror-host.md) for the full
materialization API and reconciliation algorithm.
