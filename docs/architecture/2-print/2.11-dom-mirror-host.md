# 2.11 — `dom-mirror-host`

`createDomMirrorHost` is the materialization layer that consumes the pure
[`buildDomMirror`](./2.10-dom-mirror.md) transform. Where `buildDomMirror` returns
one detached subtree and nothing else, the host owns a *live* mirror element and
its lifecycle: it mounts a hidden, AT-visible, focusable element into the editor
container, incrementally reconciles that element's DOM against the
`AccessibilityNode` tree on every paint, owns the input + browser-`Selection`
wiring, and tears itself down. It is
the dom-side surface a screen reader actually focuses and traverses while the
canvas paints the visual document.

## Public surface

```ts
export interface DomMirrorHostOptions {
  readonly container: HTMLElement;
  readonly doc?: Document;
  readonly onSelectionChange?: (selection: Span) => void;
  readonly onKeyDown?: (e: KeyboardEvent) => void;
  readonly onInsertText?: (text: string) => void;
  readonly onCompositionStart?: () => void;
  readonly onCompositionEnd?: (text: string) => void;
  readonly onCopy?: (e: ClipboardEvent) => void;
  readonly onCut?: (e: ClipboardEvent) => void;
  readonly onPaste?: (e: ClipboardEvent) => void;
  readonly onFocus?: (e: FocusEvent) => void;
  readonly onBlur?: (e: FocusEvent) => void;
}

export interface DomMirrorHost {
  readonly element: HTMLElement;
  syncTree(tree: AccessibilityNode, resolvedFields?: ReadonlyMap<string, string>): void;
  syncSelection(selection: Selection): void;
  focus(): void;
  destroy(): void;
}

export function createDomMirrorHost(options: DomMirrorHostOptions): DomMirrorHost;
```

`doc` defaults to the ambient `document` and is injectable for testing /
non-default environments (jsdom supplies it under the dom test env). The host
element is created, hidden with the same clip technique as `buildDomMirror`'s
`document`-role host (off-screen yet AT-visible, NOT `display:none` /
`aria-hidden`), and appended to `container` on construction.

## The controlled-`contenteditable` contract — engine owns all edits

The mirror element is `contenteditable` with `role=textbox` and
`aria-multiline=true`, so assistive technology treats it as an editable text
field and the browser routes keystrokes, IME composition, and clipboard events to
it. The engine — not the browser's native editing — owns every mutation:

- `beforeinput` is always `preventDefault`ed. A plain `insertText` is lifted into
  an `onInsertText` callback (the engine dispatches its own `INSERT_TEXT`); every
  other input type is swallowed so the browser never edits the contenteditable
  DOM directly.
- `compositionstart` / `compositionend` bracket IME composition; during
  composition the host suppresses the `insertText` lift and surfaces the composed
  string through `onCompositionEnd`.
- The mirror DOM is authoritative-from-state: `syncTree` reconciles it to the
  `AccessibilityNode` tree on every paint, so any transient contenteditable
  mutation the browser does manage to apply (including an in-progress IME
  composition's tentative DOM) is overwritten on the next paint. The mirror never
  diverges from engine state. (Reconciliation no-ops mid-composition — see the
  IME guard below — so a live composition's DOM is left intact until it commits.)

This is the same "engine owns edits, the input host is controlled" contract the
hidden `<textarea>` path already follows — the mirror just additionally carries
the semantic document structure AT needs.

## Selection mapping

The mirror's run wrappers carry `data-offset-start` / `data-offset-end` (the
LITERAL block offsets, stamped by `buildDomMirror`), and block elements carry
`data-block-id` (stamped by [`dom-mirror`](./2.10-dom-mirror.md)). The pure functions
in `dom-mirror-selection.ts` map engine `Position` / `Span` ⇄ the browser
`Selection` through these attrs:

- `positionFromMirrorNode(node, nodeOffset)` / `readMirrorSelection(mirror, win)`
  — DOM endpoint(s) → engine `Position` / `Span`, walking up to the enclosing run
  and block. `readMirrorSelection` returns `null` unless BOTH endpoints live
  inside the mirror.
- `locateOffsetInMirror(mirror, pos)` / `placeMirrorSelection(mirror, selection,
  win)` — the inverse: an engine `Position` / `Selection` → the DOM text node +
  in-node offset, and from there a placed browser `Selection` (via
  `setBaseAndExtent`, preserving anchor/focus direction).

`syncSelection` places the browser selection from engine state each paint;
`onSelectionChange` fires on an in-mirror `selectionchange` and reports the read
`Span`. **Loop-prevention is a controller idempotency check, not a host flag:**
the controller dispatches `SET_SELECTION` only when the read span DIFFERS from the
current engine selection, so a place→read→dispatch cycle cannot feed back on
itself.

## Incremental keyed reconciliation

`syncTree` diffs the new `AccessibilityNode` tree (after the upstream page-field
resolution below) against the prior tree and
mutates the mirror DOM in place — O(changed) per paint — rather than rebuilding it
wholesale. The diff lives in `dom-mirror-cache.ts`'s `reconcileMirror`. Preserving
DOM element identity for unchanged blocks is the whole point: a typed character
must not tear down and rebuild the element the browser's `Selection` (and the
screen reader's review cursor) is anchored inside, or the caret / AT focus jumps
on every keystroke.

**Keying.** Each child is matched to a prior element by key:

- Block nodes are keyed by their stable `sourceBlockId` — the same id survives an
  edit, so the block's element is reused across paints.
- Synthetic container nodes (the `document` root, list groupings, landmarks) carry
  no Selection anchor and have no source block, so they are matched positionally
  by role among their siblings.

An element is reused **iff** its key AND its rendered tag both match the new node;
on reuse, only the run children that actually changed are rebuilt (text/emphasis/
link/suggestion runs via `buildDomMirror`'s per-run rendering), leaving the
container element — and any Selection inside it — intact. A tag change (a heading
changing level, a role change) cannot reuse the element: it is a fresh build of
that subtree.

The host retains the prior `AccessibilityNode` tree and a
`Map<AccessibilityNode, HTMLElement>` between paints to drive the next diff.
`buildDomMirror` remains the per-node fresh-build primitive the reconciler calls
for new and tag-changed subtrees, AND the byte-identity equivalence oracle the
reconciler's output is verified against (a reconcile must land on exactly the DOM
a fresh `buildDomMirror` would have produced).

**IME guard.** `syncTree` no-ops while an IME composition is in flight: recreating
a run's spans mid-composition would invalidate the browser's live composition
`Range`. Reconciliation is deferred to the post-`compositionend` paint, which
reconciles the mirror to the now-committed state.

## The `accessibilityMirror` flag in the controller

The host is wired into the editor controller behind an `accessibilityMirror`
option on `EditorControllerOptions`, **default-off**. When OFF, the controller
path is byte-identical to before: the hidden `<textarea>` is the focus / IME /
clipboard host and the canvas is the only structure.

When ON, the mirror SUBSUMES the textarea as the single focus / IME / clipboard
host:

- the `<textarea>` is taken out of the tab order (`tabIndex = -1`) so a Tab key
  can never land on it, and the mirror becomes the focusable surface
  (`focus()` routes to the mirror);
- the canvas is marked `aria-hidden` (AT reads the semantic mirror, not the
  unreadable pixels); the mirror is deliberately NOT `aria-hidden`;
- after each paint the controller calls `syncTree(buildAccessibilityTree(state),
  layoutTree.globalFieldValues)` (an empty map on the non-virtual `LayoutBox` /
  null path — page-field resolution applies only to the virtualized paginated
  tree) and `syncSelection(state.selection)`, and wires the host's `onInsertText`
  / `onKeyDown` / clipboard / `onSelectionChange` callbacks to the same dispatch
  the textarea path uses. The a11y tree's `suggestionView` must match the view the
  field values were resolved at (both `"suggesting"` today).

**What gates flipping the default ON:** the user's in-browser screen-reader / IME
smoke (the incremental reconciler that keeps per-paint cost O(changed) and
preserves AT focus across edits has landed). Until that smoke is done, the mirror
ships behind the off-by-default flag.

## Page-field / cross-reference-"page" resolved text

Page-number / page-count fields and cross-references rendered in "page" mode
display their resolved values only after layout assigns pages. The
`AccessibilityNode` tree is geometry-free — built from state without a layout
tree — so the core projection surfaces each page-valued field as a standalone
run carrying `fieldKind` + `fieldKey` and a `""` placeholder text (see
[`1-core/1.8-accessibility.md`](../1-core/1.8-accessibility.md)), NOT the
resolved number. The host resolves the number HERE, at the dom boundary, where
the layout-resolved values are available — keeping core geometry-free.

`syncTree(tree, resolvedFields?)` takes an optional `resolvedFields: ReadonlyMap<
string, string>` — the layout-resolved field values keyed by the same render key
the run carries in `fieldKey` (the layout tree's `globalFieldValues`; see
[`1-core/2.3-pagination.md`](./2.3-pagination.md)). At the TOP of
`syncTree`, UPSTREAM of `reconcileMirror`, the host runs `resolveTreeFields(tree,
resolvedFields)` (see [`2.10-dom-mirror.md`](./2.10-dom-mirror.md)) to rewrite each
field run's `text` from `resolveFieldText`:

- a `cross-ref-page` or `page-count` run takes its value from the map by
  `fieldKey`; a `""` map value (a broken cross-reference) resolves to the
  `BROKEN_CROSS_REFERENCE_TEXT` sentinel;
- a `page-number` run, and any run with no map entry (including the default-off /
  non-virtual path, which passes an empty map), keeps its `""` placeholder.

Resolving upstream of `reconcileMirror` is what makes a page-count change
re-sync correctly: the resolved text is folded into the node BEFORE the
reconciler computes its `selfFingerprint`, so a changed value re-fingerprints the
reused block element and rebuilds its run children, while an unchanged value
leaves the element (and any Selection inside it) intact — with no churn in the
`dom-mirror-cache.ts` signatures themselves. An empty / absent `resolvedFields`
map short-circuits `resolveTreeFields` to return the original tree by reference
(no field runs to rewrite), so the default-off and non-paginated paths are
byte-identical to before.
