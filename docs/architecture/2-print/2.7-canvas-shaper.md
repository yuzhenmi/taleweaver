# 2.7 — `canvas-shaper`

The canvas shaper is the default `TextShaper` implementation that ships
with `print`. It produces shaped runs for the engine's IFC by
delegating glyph rendering and metrics to the browser's canvas API,
supplemented with the engine's own Unicode-algorithm code for cluster
boundaries and break opportunities.

> ## Status: what the shipped shaper does
> The **shipped shaper** (`packages/print/src/canvas-shaper.ts` — the
> authoritative current behavior) is deliberately a per-run measurer. Two
> concerns that are paragraph- or language-level live OUTSIDE it, in the IFC:
> UAX #9 bidi resolution and hyphenation. What the shaper does today:
> - **Clusters:** UAX #29 extended grapheme clusters via `Intl.Segmenter`
>   (`segmentClusters` → `graphemeClusters`) — a base + combining marks, a
>   surrogate-pair emoji, a ZWJ sequence, a regional-indicator flag are each ONE
>   cluster. Advance is the canvas-measured width of the whole cluster string
>   (the browser shapes within a cluster); no ligature-glyph detection.
> - **Break opportunities:** **UAX #14** — `shape()` calls
>   `@taleweaver/core`'s `toBreakOpportunities` (the canonical adapter over the
>   `layout/uax14` classifier `lineBreakOpportunities`), mapping mandatory
>   breaks to `hard` and the rest to `soft`. A real,
>   committed line-break property table backs it (no runtime dependency). CJK
>   ideographs and NBSP/`GL` glue are handled correctly.
> - **Bidi:** a single **uniform per-run level** (0 for LTR, 1 for RTL from
>   `baseDirection`). UAX #9 is NOT a shaper concern: the IFC resolves it per
>   PARAGRAPH (`resolveParagraphBidi` in `layout/ifc-bidi.ts`, over core's
>   `layout/uax9` `resolveBidiLevels`) and reorders each line
>   (`ifc-bidi-reorder.ts`) — see [`2.2.2-ifc.md`](./2.2-layout/2.2.2-ifc.md).
> - **Hyphenation:** NOT a shaper concern either. `createCanvasShaper(canvas)`
>   takes **no options** and never emits a `"hyphen"` break opportunity (core's
>   `TextShaper` contract, `layout/text-shaper.ts`). The IFC applies the injected
>   `LayoutConfig.hyphenator` (built with `createLiangHyphenator` from per-language
>   pattern packages such as `@taleweaver/hyphenation-en-us`) when
>   `hyphens: auto` and the run has a `language`.
>
> Cross-cluster shaping (kerning, ligatures, cursive joining) comes from a
> HarfBuzz-WASM shaper supplied downstream through the same `TextShaper` interface.

## Construction

`createCanvasShaper(canvas) → TextShaper`. The host instantiates one
shaper per editor and passes it as the layout-driver's `LayoutConfig.measurer`
(see [`2.1-layout-driver.md`](./2.1-layout-driver.md)). The shaper
holds a reference to a canvas's 2D rendering context — used internally
to call `measureText` and to read font metrics.

A single shaper instance can serve many shape calls; it has no
per-string state.

## What it does

For each `shape(text, style, baseDirection)` call, the shaper:

1. **Resolves the font.** Builds the canvas font string from the
   computed-style font fields (`fontStyle fontWeight fontSize fontFamily`)
   and assigns it to the context.

2. **Measures cluster advances.** Calls `measureText` on the context
   once per grapheme cluster, adding letter- and word-spacing (a soft
   hyphen's advance is forced to 0). The browser shapes each cluster
   on its own, and the canvas renderer paints cluster by cluster at the
   same summed advances, so no kerning, ligature or cursive joining
   forms across clusters, in measurement or in paint.

3. **Computes cluster boundaries (UAX #29).** Segments the input string
   into extended grapheme clusters via `Intl.Segmenter`
   (`granularity: "grapheme"`, through `graphemeClusters`) — base codepoints
   with combining marks, surrogate-pair emoji, emoji ZWJ sequences, regional
   indicator pairs. Each cluster maps to one cursor stop and is treated as
   atomic for line-break decisions; its `start`/`end` are UTF-16 code-unit
   offsets that span the grapheme. The cluster advance is the canvas-measured
   width of the whole cluster string (the browser shapes within a cluster);
   cross-cluster complex-script metrics (HarfBuzz-quality mark/ligature
   positioning) are out of scope for the canvas backend.

4. **Reports the run's base bidi level.** One uniform level from
   `baseDirection` (0 LTR, 1 RTL). Per-character UAX #9 levels are resolved
   by the IFC over the whole paragraph (a run's level depends on its
   surrounding text, which a per-run shaper cannot see) — see
   [`2.2.2-ifc.md`](./2.2-layout/2.2.2-ifc.md).

5. **Computes break opportunities (UAX #14). [IMPLEMENTED]**
   `shape()` calls `@taleweaver/core`'s `toBreakOpportunities` (the canonical
   adapter over the `layout/uax14` classifier `lineBreakOpportunities`), which
   identifies exactly where line wrap may occur per the UAX #14 rules — after spaces,
   after hyphens, between CJK ideographs, never across `GL` glue (NBSP) —
   and maps mandatory breaks to `hard`, the rest to `soft`. Within-word
   hyphenation opportunities are not produced here: the IFC derives them from
   the injected `LayoutConfig.hyphenator` (see **Hyphenation** below).

6. **Reads font metrics.** Ascent, descent, x-height and cap-height come
   from the `TextMetrics` object the canvas returns (font-size fallbacks
   when absent); line height comes from the computed style, and `lineGap`
   is derived from it. Used by the IFC for baseline alignment.

The output is a `ShapedRun` containing per-cluster advances (each
glyph is the cluster's first code unit), cluster boundaries, the run's base bidi level, break opportunities, and
font metrics. The IFC and caret math consume it. The painter does not read
`ShapedRun.clusters`: it repeats the same segmentation (`segmentClusters`) and
the same advance rule (`clusterAdvance`, which zero-advances U+00AD and adds
letter-/word-spacing) and skips painting U+00AD (`isSoftHyphen`). The shaper
and the canvas paint loops sum that one shared helper, which is the no-drift
guarantee between painted glyphs and the caret. The PDF emitter does not
measure: it places clusters at the shaper's widths (`clusterWidths`) and applies
the same `isSoftHyphen` skip.

## What it doesn't do

The canvas shaper does not shape across grapheme clusters: each cluster
is measured, and painted, on its own. This means:

- **Latin and most European scripts** render legibly, without
  cross-cluster kerning or ligatures.
- **Hebrew** renders correctly (no joining); the IFC's per-paragraph
  UAX #9 pass orders it in multi-script lines.
- **Arabic and other cursive scripts** are drawn one cluster at a time,
  so letters do not join.
- **Indic scripts** lose conjunct and reph forms that span
  clusters.

A HarfBuzz-WASM shaper supplied downstream covers these cases; the
engine consumes either backend through the same `TextShaper` interface
without modification.

## Hyphenation

Hyphenation is language-dependent and dictionary-driven, so it is not part of
the shaper. The host builds a `Hyphenator` with `createLiangHyphenator(...)`
(`@taleweaver/print`, Knuth-Liang) from per-language `PatternSet` packages
(`@taleweaver/hyphenation-en-us`) and injects it as `LayoutConfig.hyphenator`.
The IFC asks it for in-word break points when a run has `hyphens: auto` and a
non-empty `language`, and shapes the visible `"-"` glyph at the chosen break.
With no hyphenator or no language, `auto` contributes no breaks. See
[`2.2.2-ifc.md`](./2.2-layout/2.2.2-ifc.md) and
[`1.4-text.md`](../1-core/1.4-text.md).

## Font fallback

When a glyph isn't available in the requested font, the browser's
canvas falls back to a configured font chain. The shaper sees the
final advance widths post-fallback and exposes them; the engine
doesn't need to know about the fallback chain itself.

## Why this is the default

A canvas shaper is the cheapest path to a working engine in a browser:
no WASM bundle, no font fetching, no integration work. It's good enough
for Latin, CJK and Hebrew documents (cursive and Indic scripts need a
cross-cluster shaper; see above) and gives the engine
correct cluster and break behavior even when the underlying
glyph shaper is opaque.

When richer shaping is needed, the same engine accepts a different
implementation — the contract is the `TextShaper` interface, not the
canvas-specific implementation.

## Reference

### Public API

```ts
function createCanvasShaper(canvas: HTMLCanvasElement | OffscreenCanvas): TextShaper;
```

The shaper takes no options; hyphenation is injected into layout, not the shaper.

The returned shaper holds a reference to the canvas's 2D context. It implements the `TextShaper` interface from `core` (see [`1.4-text.md`](../1-core/1.4-text.md)).

### `shape()` algorithm

`segmentClusters` segments UAX #29 grapheme clusters via `Intl.Segmenter`
(`graphemeClusters`), as pseudocode step 1 shows, and `shape()` calls
`toBreakOpportunities` (the canonical `core` adapter over the `layout/uax14`
classifier) for UAX #14 breaks (pseudocode step 2; this is step 5 of the
numbered responsibilities list above). The step numbers in the pseudocode below
are local to it. The run's `bidiLevel` is the uniform base level; UAX #9 is
resolved per paragraph by the IFC.

```
function shape(text, cs, baseDirection):
  setFont(ctx, cs)
  letterPx = resolveSpacingPx(cs.letterSpacing)   // 0 for `normal`
  wordPx   = resolveSpacingPx(cs.wordSpacing)

  // 1. Cluster boundaries (shared helper, so the renderer paints at the same advances)
  clusters = []
  start = 0
  for c in segmentClusters(text):                 // UAX #29 grapheme clusters
    // clusterAdvance gives U+00AD SOFT HYPHEN zero advance; the IFC shapes a
    // "-" separately when it is the chosen line-end break.
    w = clusterAdvance(ctx, c, letterPx, wordPx)
    clusters.push({
      start, end: start + c.length,
      inlineAdvance: w,
      isLigature: false,                          // canvas doesn't expose ligature info
      glyphs: [c.charCodeAt(0)],                  // first UTF-16 code unit, not a glyph ID
    })
    start += c.length

  // 2. Break opportunities (UAX #14)
  //    toBreakOpportunities is the canonical core adapter (wraps lineBreakOpportunities),
  //    single-sourced so every shaper maps kinds identically.
  breakOpportunities = toBreakOpportunities(text)

  // (no hyphen opportunities: hyphenation is applied by the IFC via `LayoutConfig.hyphenator`)

  // 3. Font metrics (measureFontMetricsImpl)
  m = ctx.measureText("Hg")
  ascent  = m.actualBoundingBoxAscent  ?? cs.fontSize * 0.8
  descent = m.actualBoundingBoxDescent ?? cs.fontSize * 0.2
  lineHeight = cs.lineHeight is number
      ? (cs.lineHeight < 4 ? cs.lineHeight * cs.fontSize : cs.lineHeight)  // <4: unitless multiplier, else px
      : cs.fontSize * 1.2
  lineGap   = max(0, lineHeight - ascent - descent)
  xHeight   = ctx.measureText("x").actualBoundingBoxAscent ?? cs.fontSize * 0.5
  capHeight = ctx.measureText("H").actualBoundingBoxAscent ?? cs.fontSize * 0.7

  // 4. Aggregates
  unbreakableRunInlineSize = sum(clusters.map(c => c.inlineAdvance))
  minClusterInlineSize = text is empty ? 0 : max(0, ...clusters.map(c => c.inlineAdvance))

  return {
    text, computedStyle: cs,
    clusters,
    ascent, descent, lineGap,
    minClusterInlineSize, unbreakableRunInlineSize,
    breakOpportunities,
    bidiLevel: baseDirection == "rtl" ? 1 : 0,
  }
```

### Performance contracts

- `shape(text, style, baseDirection)` cold: O(L) where L = `text.length`.
- `measureFontMetrics(cs)`: O(1) (a few `measureText` calls — `"Hg"`, `"x"`, `"H"`).
- The canvas's underlying `measureText` is fast (microseconds for typical run lengths). The shipped UAX #14 break classification (`lineBreakOpportunities`) is a linear pass over the run.
